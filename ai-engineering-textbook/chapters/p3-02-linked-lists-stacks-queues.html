Linked Lists, Stacks, Queues & Monotonic Structures

Linked lists teach pointer manipulation under invariants; stacks and queues encode order of processing — last-in-first-out and first-in-first-out — which is the hidden skeleton of recursion, BFS, schedulers and parsers. Monotonic stacks and queues turn a whole family of "next greater / window maximum" problems from quadratic to linear. Along the way we open up LinkedList, ArrayDeque, LinkedHashMap and Python's deque, and build an LRU cache the way interviewers expect.

  • Prerequisites: Chapter 3.1 (complexity, amortized analysis, arrays).
  • You will be able to: manipulate lists with sentinels and fast/slow pointers without bugs, prove Floyd's cycle detection, implement an O(1) LRU cache two ways, explain ArrayDeque and work-stealing deques, recognise monotonic-stack problems, and evaluate arithmetic expressions with operator precedence.

1. Introduction: Order of Processing as a Design Tool

The previous chapter was about where data lives. This chapter is about in what order you process it. Four structures cover most needs:

  • Linked lists — sequences of nodes connected by references. They give O(1) insertion and deletion at a known node, which is exactly what you need to keep recency order in an LRU cache or to splice lists without copying. In interviews they test whether you can maintain invariants while rewiring pointers.
  • Stacks (LIFO) — the most recent unfinished thing is handled first: function calls, undo, matching brackets, depth-first search, parsing.
  • Queues (FIFO) — fairness and arrival order: breadth-first search, request buffers, job queues, rate-limited pipelines.
  • Deques — both ends; they generalise both and power sliding-window maxima, 0-1 BFS and work-stealing schedulers.

The monotonic variants maintain elements in sorted order by discarding those that can never be an answer again. That single idea — "pop what is dominated" — gives Θ(n) solutions to next-greater-element, stock span, largest rectangle in a histogram and sliding-window maximum.

Bridging from Java & Spring Boot

What you already know
LinkedList, ArrayDeque, Queue.offer/poll, BlockingQueue in executors, the call stack in stack traces, maybe LinkedHashMap for ordered JSON. Spring's ThreadPoolTaskExecutor is a queue in front of workers; @Cacheable with Caffeine is an eviction-ordered structure.
Why that is not enough
Interviews ask you to build these from nodes and arrays: reverse a list in k-groups, detect a cycle in O(1) space, design an LRU cache with O(1) operations, compute window maxima in Θ(n). You also need to know why LinkedList is almost never the right production choice and why Stack is legacy.
The modern approach
Prefer array-backed structures (ArrayDeque, ring buffers) for cache locality; use linked structures only when you need O(1) splicing at arbitrary known positions (LRU recency lists, intrusive lists). Use sentinel nodes to remove edge cases. Think in invariants ("everything before prev is already reversed").
Where Python and Go fit
Python: list is a fine stack; collections.deque is the queue/deque (never list.pop(0)); OrderedDict.move_to_end and functools.lru_cache give LRU. Go: slices as stacks, container/list for doubly linked lists, buffered channels as bounded FIFO queues.
In production
Bounded queues for backpressure in executors and Kafka consumers, ring buffers in logging (Log4j 2 async loggers use the LMAX Disruptor), work-stealing deques in ForkJoinPool and virtual-thread schedulers, LRU-like caches everywhere.
Use it when / avoid it when
Use linked lists when you hold node references and need O(1) unlink/move; avoid them for indexed access, iteration-heavy workloads or memory-sensitive data. Use unbounded queues only when producers are naturally bounded; otherwise bound them and decide what happens when full.

2. History

  • 1946 — Stacks for subroutines. Alan Turing's ACE report described "burying" and "unburying" return addresses — a stack for subroutine calls.
  • 1955–1956 — Linked lists. Allen Newell, Cliff Shaw and Herbert Simon created linked lists for the Information Processing Language (IPL) used in their Logic Theorist program at RAND.
  • 1957–1960 — Stack-based evaluation. Friedrich Bauer and Klaus Samelson patented the "stack principle" for evaluating expressions (1957); the Burroughs B5000 (1961) was a stack machine; Dijkstra's shunting-yard algorithm (1961) converted infix expressions to postfix for ALGOL 60 compilers.
  • 1958–1960 — LISP (John McCarthy) made the cons-cell singly linked list a language primitive.
  • 1967 — Floyd's cycle-finding ("tortoise and hare") is attributed to Robert Floyd; Knuth credits him in TAOCP vol. 2 (1969). Richard Brent published an improved variant in 1980.
  • 1996 — Lock-free queue. Maged Michael and Michael Scott's non-blocking concurrent queue (PODC '96) later became java.util.concurrent.ConcurrentLinkedQueue (Java 5, 2004).
  • 2000 — Work stealing in Java. Doug Lea's "A Java Fork/Join Framework" described per-worker deques with stealing; it shipped as ForkJoinPool in Java 7 (2011).
  • 2006 — ArrayDeque arrived in Java 6, and its Javadoc recommends it over both Stack and LinkedList.
  • 2011 — LMAX Disruptor was open-sourced, popularising pre-allocated ring buffers with sequence counters for low-latency messaging.

3. Fundamentals

3.1 Singly linked lists

A node holds a value and a next reference; the list is a reference to the head (and often a tail). Operations: insert at head Θ(1); insert after a known node Θ(1); delete the node after a known node Θ(1); find by value or index Θ(n); delete a given node Θ(n) because you need its predecessor (unless you use the "copy the next node's value" trick, which fails for the tail). Memory: one object per element, each with an object header — on HotSpot a node with a value reference and a next reference is about 16–24 bytes plus the value.

Sentinel (dummy) nodes remove special cases. With a dummy head, "insert before the first node" and "delete the first node" are the same code path as for any other position. Most interview list bugs disappear with var dummy = new Node(0, head) and returning dummy.next.

3.2 Doubly linked lists

Nodes also hold prev, so deleting a node you hold a reference to is Θ(1): node.prev.next = node.next; node.next.prev = node.prev. With two sentinels (head and tail) there are no null checks at all. This is the recency list in an LRU cache and the structure behind LinkedHashMap, java.util.LinkedList, Go's container/list (a circular list with one sentinel) and the Linux kernel's intrusive list_head.

Intrusive vs external lists. In an external list (LinkedList<Order>), nodes wrap your objects. In an intrusive list, the object itself carries prev/next fields, so one object can be unlinked in O(1) given only the object, without a map from object to node. Caches and kernels prefer intrusive designs; Java collections are external, which is why an LRU needs a map from key to node.

3.3 Fast and slow pointers

Two references moving at different speeds over a sequence. Uses: middle of a list (slow moves 1, fast moves 2; when fast reaches the end, slow is at the middle), cycle detection (if there is a cycle, fast eventually laps slow), cycle entry (after they meet, restart one pointer from the head and move both one step; they meet at the entry), k-th from the end (advance one pointer k steps first, then move both). The technique works on any sequence defined by a function x → f(x), which is why "Find the Duplicate Number" (array values as next pointers) and "Happy Number" are cycle-detection problems in disguise.

3.4 Reversal

Iterative reversal keeps three references: prev (head of the already-reversed part), cur (the node to process), next (saved before we overwrite cur.next). Invariant: the nodes before cur form a reversed list headed by prev. Θ(n) time, Θ(1) space. The recursive version is elegant but uses Θ(n) stack — on a 10⁵-node list it can overflow a default thread stack. Sub-list reversal (between positions l and r, or in groups of k) is the same loop with careful reconnection of the boundaries.

3.5 Stacks

A stack supports push, pop and peek at one end. Array-backed: push/pop amortized O(1), excellent locality. Linked: O(1) worst case, a node per element. The call stack is the canonical example: each call pushes a frame (locals, return address); recursion depth is stack depth. Any recursive algorithm can be made iterative with an explicit stack — essential when depth can reach 10⁵+. Stacks also match things: brackets, tags, the most recent unmatched open item.

3.6 Queues and circular buffers

A queue supports enqueue at the tail and dequeue at the head. An array with a moving head wastes the front; the fix is a circular buffer: indices wrap modulo capacity, tail = (tail + 1) % cap. If capacity is a power of two, wrap with a mask: (i + 1) & (cap − 1). Distinguish full from empty by keeping a size counter (or by leaving one slot empty). A queue can also be built from two stacks: push onto in; to pop, if out is empty, move everything from in to out (reversing order), then pop out. Each element is moved at most once, so dequeue is amortized O(1) — a favourite amortized-analysis question, and the basis of purely functional queues.

3.7 Deques

A deque (double-ended queue) supports add/remove at both ends in O(1). A circular buffer with head and tail indices that can both move in either direction implements it. Deques are the most general of the three: use push/pop on one end for a stack and offerLast/pollFirst for a queue.

3.8 Priority queues (preview)

A priority queue dequeues the minimum (or maximum) rather than the oldest. It is a heap, not a list, and is covered in Chapter 4. Mentioned here because Queue in Java includes PriorityQueue, and confusing the two orders is a classic bug.

3.9 Monotonic stacks

A stack whose contents are kept increasing (or decreasing) from bottom to top. When a new element x arrives, pop every element that x "dominates" (e.g. smaller than x, for a decreasing stack). Each popped element has just found its next greater element: x. Each element is pushed once and popped at most once, so the total is Θ(n) even though there is a while loop inside the for loop. Variants answer: previous/next greater/smaller element, span ("how many consecutive days before today were ≤ today?"), the largest rectangle under a histogram (each bar's maximal extent is bounded by the previous and next smaller bars), trapping rain water, and contributions of each element as the minimum of subarrays.

3.10 Monotonic queues (deques)

For the maximum of every window of size k, keep a deque of indices whose values are decreasing from front to back. On each new index i: pop from the back while the back's value ≤ a[i] (they can never be a maximum again while i is in the window); push i; pop from the front if it has left the window (index ≤ i − k); the front is the window maximum. Θ(n) total. The same deque optimises some dynamic programs ("max of dp over the last k positions") — a technique you will meet again in Chapter 7.

3.11 Expression evaluation

Postfix (Reverse Polish) notation needs no parentheses or precedence: scan tokens; push numbers; on an operator pop two operands, apply, push the result. Infix needs precedence and associativity. Dijkstra's shunting-yard uses an operator stack: output numbers immediately; for an operator, pop to the output any operators of higher precedence (or equal precedence if left-associative), then push; "(" is pushed; ")" pops until "(". The output is postfix, which you evaluate with the first algorithm (or evaluate on the fly with two stacks). Recursive descent mirrors the grammar — expr := term (('+'|'-') term)*, term := factor (('*'|'/') factor)*, factor := number | '(' expr ')' | '-' factor — using the call stack as the operator stack. Both are Θ(n). Real-world descendants: Spring Expression Language (SpEL) parser, query planners, and every config/templating language.

4.3 java.util.LinkedList

A doubly linked list with first and last fields (no sentinel) and inner Node<E>{item, next, prev}. It implements both List and Deque. get(i) walks from whichever end is closer (i < size >> 1), so it is Θ(min(i, n−i)) — and a for (int i…) list.get(i) loop is Θ(n²). Its only real advantage is O(1) removal through a ListIterator you already hold; Joshua Bloch, who wrote it, has remarked publicly that he does not use it. Opinion In practice ArrayList or ArrayDeque wins almost every benchmark because of locality and lower per-element memory (~24 bytes of node overhead per element in LinkedList).

4.4 ArrayDeque

ArrayDeque is a circular buffer over Object[] elements with head (index of the first element) and tail (index where the next addLast goes). addFirst decrements head modulo the length; addLast writes at tail and increments it. When the buffer becomes full it grows: in JDK 9+ the growth is roughly doubling for small arrays (under 64) and +50% for larger ones, and the capacity is no longer required to be a power of two (JDK 6–8 used power-of-two capacities and masks). The elements wrapped past the end are moved so that the contents stay contiguous modulo the new length. Nulls are prohibited (null is used to mark empty slots, and poll returns null for "empty"). 4.5 LinkedHashMap as an LRU

LinkedHashMap extends HashMap; its entries add before/after links forming a doubly linked list through all entries. With the constructor flag accessOrder = true, every get or put of an existing key moves the entry to the tail (afterNodeAccess). After each insertion it calls removeEldestEntry(eldest); override it to return size() > capacity and you have an LRU cache in a few lines. It is not thread-safe — and note that in access-order mode even get is a structural modification, so concurrent readers corrupt it. Java 21's SequencedMap adds putFirst/putLast/pollFirstEntry.

4.6 Python deque and OrderedDict

CPython's collections.deque is a doubly linked list of fixed-size blocks (64 slots each). Appends and pops at either end are O(1) and touch one block; indexing the middle is O(n/64) — fine near the ends, linear in the middle. A maxlen deque discards from the opposite end, giving a ready-made bounded ring buffer. OrderedDict keeps a doubly linked list of keys alongside the dict, so move_to_end(key) and popitem(last=False) are O(1) — an LRU in a few lines. functools.lru_cache is implemented in C with a circular doubly linked list plus a dict.

5. Architecture: The Structures in Pictures

Reading the diagram: a get(3) finds node 3 through the map, unlinks it (two pointer writes) and relinks it before the tail sentinel, making it most recently used. A put that overflows capacity removes head.next (key 7) from both the list and the map — which is why each node stores its key. Neither structure alone suffices: the map has no order, the list has no O(1) lookup.

Reading the diagram: the owner treats its deque as a stack, which keeps recently split subtasks (and their data) hot in cache. Idle workers steal from the opposite end, taking the oldest task — in divide-and-conquer workloads that is the biggest remaining chunk, so one steal transfers a lot of work. Only when the deque has one element do owner and thief race, resolved with a CAS. This is the scheduler behind parallel streams, CompletableFuture's default async pool, and the carrier threads of virtual threads.

Reading the diagram: what happens in Full is a design decision, not an implementation detail: put blocks the producer (backpressure), offer with a timeout fails after waiting, and a ThreadPoolExecutor invokes its RejectedExecutionHandler (abort, caller-runs, discard, discard-oldest). Unbounded queues have no Full state — they convert overload into memory growth and latency instead.

6.2 Proof of Floyd's algorithm

Intuition: once both pointers are inside the cycle, the gap between them shrinks by one each step (fast gains one node per step), so they must meet within λ steps. Formally, let μ be the number of nodes before the cycle entry and λ the cycle length. After t steps, slow is at position t and fast at 2t (positions counted along the sequence). They coincide inside the cycle when t ≥ μ and 2t − t = t ≡ 0 (mod λ), i.e. at the first multiple of λ that is ≥ μ — so t ≤ μ + λ.

For the entry: at the meeting time t, t is a multiple of λ. Pointer p starts at the head and q at the meeting point (position t). After μ more steps p is at position μ (the entry) and q is at position t + μ ≡ μ (mod λ) inside the cycle — also the entry, because t ≡ 0. So they meet exactly at the entry. Cycle length: from the meeting point, walk until you return, λ steps. Total Θ(μ + λ) time, Θ(1) space — versus Θ(n) space for a HashSet of visited nodes.

6.3 Two-stack queue: potential argument

Let Φ = 2 × |in|. Enqueue: actual 1, ΔΦ = 2, amortized 3. Dequeue with out non-empty: actual 1, ΔΦ = 0. Dequeue with out empty and |in| = k: actual 2k + 1 (k pops, k pushes, 1 pop), ΔΦ = −2k, amortized 1. So every operation is amortized O(1), and the worst single dequeue is Θ(n). (Real-time queues from Okasaki's work remove the spike by transferring incrementally.)

6.4 Monotonic stack: aggregate argument

Each index is pushed exactly once and popped at most once. The work of the inner while loop summed over the whole run is at most n pops, so total time is Θ(n) + Θ(n) = Θ(n). The same argument bounds the monotonic deque (each index enters and leaves at most once from either end).

6.5 Largest rectangle in a histogram: why the stack finds every candidate

The optimal rectangle has height equal to some bar h[i] (otherwise raise it to the shortest bar it covers). For that bar, the rectangle extends left to just after the previous strictly smaller bar L(i) and right to just before the next smaller bar R(i): area = h[i] × (R(i) − L(i) − 1). An increasing stack computes R(i) at the moment i is popped (the popping index) and L(i) as the new top below it. All n candidates are evaluated in Θ(n).

6.6 Little's law for queues

Back-of-envelope for production queues: L = λ × W — the average number of items in a stable system equals arrival rate times average time in system. Illustrative A queue receiving 2,000 jobs/s where each job spends 50 ms waiting plus being processed holds about 100 jobs on average. If the queue suddenly holds 20,000 jobs, either λ rose or W did (slow downstream) — and every new job now waits ≈ 10 s. A bound of a few hundred items and a rejection policy keeps W predictable.

6.7 Ring buffer index arithmetic

For capacity C = 2ᵏ, i mod C = i & (C − 1) for non-negative i. The Disruptor uses ever-increasing 64-bit sequence numbers and masks them to slot indices, so "full" is simply producerSeq − consumerSeq == C — no wrap-around ambiguity. At 10⁹ events/s a 64-bit counter overflows after about 292 years.

7.1 Linked list toolkit

import java.util.ArrayList;
import java.util.List;

public final class ListToolkit {
    static final class Node {
        int val; Node next;
        Node(int val, Node next) { this.val = val; this.next = next; }
    }

    static Node of(int... vals) {
        Node dummy = new Node(0, null), t = dummy;
        for (int v : vals) t = t.next = new Node(v, null);
        return dummy.next;
    }

    static List<Integer> toList(Node h) {
        List<Integer> out = new ArrayList<>();
        for (; h != null; h = h.next) out.add(h.val);
        return out;
    }

    /** Iterative reversal: Theta(n) time, Theta(1) space. */
    static Node reverse(Node head) {
        Node prev = null, cur = head;
        while (cur != null) {
            Node next = cur.next;   // 1. save
            cur.next = prev;        // 2. rewire
            prev = cur;             // 3. advance prev
            cur = next;             // 4. advance cur
        }
        return prev;
    }

    /** Recursive reversal: elegant, but Theta(n) stack. */
    static Node reverseRec(Node head) {
        if (head == null || head.next == null) return head;
        Node newHead = reverseRec(head.next);
        head.next.next = head;      // the node after head now points back
        head.next = null;
        return newHead;
    }

    /** Second middle for even lengths (1,2,3,4 -> 3). */
    static Node middle(Node head) {
        Node slow = head, fast = head;
        while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
        return slow;
    }

    /** Floyd: returns the cycle entry, or null if acyclic. */
    static Node cycleEntry(Node head) {
        Node slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next; fast = fast.next.next;
            if (slow == fast) {                     // phase 2
                Node p = head;
                while (p != slow) { p = p.next; slow = slow.next; }
                return p;
            }
        }
        return null;
    }

    /** Merge two sorted lists with a dummy head: Theta(n + m), stable. */
    static Node merge(Node a, Node b) {
        Node dummy = new Node(0, null), t = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) { t.next = a; a = a.next; } else { t.next = b; b = b.next; }
            t = t.next;
        }
        t.next = (a != null) ? a : b;
        return dummy.next;
    }

    /** Remove the n-th node from the end in one pass (gap of n between pointers). */
    static Node removeNthFromEnd(Node head, int n) {
        Node dummy = new Node(0, head), lead = dummy, lag = dummy;
        for (int i = 0; i <= n; i++) lead = lead.next;
        while (lead != null) { lead = lead.next; lag = lag.next; }
        lag.next = lag.next.next;
        return dummy.next;
    }

    /** Merge sort on a linked list: Theta(n log n), O(log n) stack, no random access needed. */
    static Node sort(Node head) {
        if (head == null || head.next == null) return head;
        Node slow = head, fast = head.next;            // first middle so halves shrink
        while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
        Node second = slow.next;
        slow.next = null;
        return merge(sort(head), sort(second));
    }

    public static void main(String[] args) {
        check(toList(reverse(of(1, 2, 3, 4))), List.of(4, 3, 2, 1));
        check(toList(reverseRec(of(1, 2, 3))), List.of(3, 2, 1));
        if (middle(of(1, 2, 3, 4)).val != 3 || middle(of(1, 2, 3)).val != 2) throw new AssertionError();
        Node c = of(1, 2, 3, 4, 5, 6), entry = c.next.next, tail = c;
        while (tail.next != null) tail = tail.next;
        tail.next = entry;
        if (cycleEntry(c) != entry || cycleEntry(of(1, 2)) != null) throw new AssertionError();
        check(toList(merge(of(1, 3, 5), of(2, 3, 6))), List.of(1, 2, 3, 3, 5, 6));
        check(toList(removeNthFromEnd(of(1, 2, 3, 4, 5), 2)), List.of(1, 2, 3, 5));
        check(toList(removeNthFromEnd(of(1), 1)), List.of());
        check(toList(sort(of(4, 2, 1, 3, 2))), List.of(1, 2, 2, 3, 4));
        System.out.println("list toolkit ok");
    }
    static void check(Object got, Object want) { if (!got.equals(want)) throw new AssertionError(got + " != " + want); }
}

    dummy = tail = Node(0)

def to_list(h):
    out = []
    while h:
        out.append(h.val)
        h = h.next
    return out

def reverse(head):
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next   # RHS evaluated first: safe
    return prev

def cycle_entry(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            p = head
            while p is not slow:
                p, slow = p.next, slow.next
            return p
    return None

def merge(a, b):
    dummy = t = Node(0)
    while a and b:
        if a.val <= b.val:
            t.next, a = a, a.next
        else:
            t.next, b = b, b.next
        t = t.next
    t.next = a or b
    return dummy.next

7.2 LRU cache: from scratch and with LinkedHashMap

import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.Map;

/** O(1) get/put LRU cache: HashMap for lookup, doubly linked list with two sentinels for recency. */
public final class LruCache<K, V> {
    private final class Node {
        K key; V val; Node prev, next;
        Node(K k, V v) { key = k; val = v; }
    }

    private final int capacity;
    private final Map<K, Node> index = new HashMap<>();
    private final Node head = new Node(null, null);   // head.next = least recently used
    private final Node tail = new Node(null, null);   // tail.prev = most recently used

    public LruCache(int capacity) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity");
        this.capacity = capacity;
        head.next = tail; tail.prev = head;
    }

    public V get(K key) {
        Node n = index.get(key);
        if (n == null) return null;
        unlink(n); linkLast(n);                       // mark as most recently used
        return n.val;
    }

    public void put(K key, V val) {
        Node n = index.get(key);
        if (n != null) { n.val = val; unlink(n); linkLast(n); return; }
        if (index.size() == capacity) {               // evict LRU
            Node lru = head.next;
            unlink(lru);
            index.remove(lru.key);                    // why each node stores its key
        }
        n = new Node(key, val);
        index.put(key, n);
        linkLast(n);
    }

    private void unlink(Node n) { n.prev.next = n.next; n.next.prev = n.prev; }
    private void linkLast(Node n) { n.prev = tail.prev; n.next = tail; tail.prev.next = n; tail.prev = n; }

    /** The library version: access-ordered LinkedHashMap + removeEldestEntry. */
    static <K, V> Map<K, V> linkedHashMapLru(int capacity) {
        return new LinkedHashMap<>(16, 0.75f, true) {
            @Override protected boolean removeEldestEntry(Map.Entry<K, V> eldest) { return size() > capacity; }
        };
    }

    public static void main(String[] args) {
        var c = new LruCache<Integer, String>(2);
        c.put(1, "a"); c.put(2, "b");
        c.get(1);                 // 1 becomes MRU
        c.put(3, "c");            // evicts 2
        if (c.get(2) != null || !"a".equals(c.get(1)) || !"c".equals(c.get(3))) throw new AssertionError();
        var m = LruCache.<Integer, String>linkedHashMapLru(2);
        m.put(1, "a"); m.put(2, "b"); m.get(1); m.put(3, "c");
        if (m.containsKey(2) || !m.containsKey(1)) throw new AssertionError(m);
        System.out.println("lru ok " + m.keySet());
    }
}

7.3 Ring buffer queue, two-stack queue and min-stack

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.NoSuchElementException;

public final class Queues {

    /** Bounded FIFO ring buffer; power-of-two capacity so wrap is a mask. Not thread-safe. */
    static final class RingBuffer<E> {
        private final Object[] buf;
        private final int mask;
        private long head, tail;              // monotonically increasing sequence numbers

        RingBuffer(int capacityPow2) {
            if (Integer.bitCount(capacityPow2) != 1) throw new IllegalArgumentException("power of two");
            buf = new Object[capacityPow2];
            mask = capacityPow2 - 1;
        }
        boolean offer(E e) {
            if (tail - head == buf.length) return false;       // full: caller decides policy
            buf[(int) (tail++ & mask)] = e;
            return true;
        }
        @SuppressWarnings("unchecked")
        E poll() {
            if (head == tail) return null;
            int i = (int) (head++ & mask);
            E e = (E) buf[i];
            buf[i] = null;
            return e;
        }
        int size() { return (int) (tail - head); }
    }

    /** Queue from two stacks: amortized O(1) per operation. */
    static final class TwoStackQueue<E> {
        private final Deque<E> in = new ArrayDeque<>(), out = new ArrayDeque<>();
        void enqueue(E e) { in.push(e); }
        E dequeue() {
            if (out.isEmpty()) while (!in.isEmpty()) out.push(in.pop());   // each element moves once
            if (out.isEmpty()) throw new NoSuchElementException();
            return out.pop();
        }
    }

    /** Stack with O(1) getMin: store (value, min-so-far) pairs. */
    static final class MinStack {
        private record Entry(int val, int min) {}
        private final Deque<Entry> st = new ArrayDeque<>();
        void push(int x) { st.push(new Entry(x, st.isEmpty() ? x : Math.min(x, st.peek().min()))); }
        int pop() { return st.pop().val(); }
        int top() { return st.peek().val(); }
        int getMin() { return st.peek().min(); }
    }

    public static void main(String[] args) {
        var rb = new RingBuffer<Integer>(4);
        for (int i = 0; i < 4; i++) if (!rb.offer(i)) throw new AssertionError();
        if (rb.offer(99)) throw new AssertionError("should be full");
        if (rb.poll() != 0 || !rb.offer(4) || rb.size() != 4) throw new AssertionError();
        var q = new TwoStackQueue<String>();
        q.enqueue("a"); q.enqueue("b"); String x = q.dequeue(); q.enqueue("c");
        if (!x.equals("a") || !q.dequeue().equals("b") || !q.dequeue().equals("c")) throw new AssertionError();
        var ms = new MinStack();
        ms.push(5); ms.push(2); ms.push(7); ms.push(1);
        if (ms.getMin() != 1) throw new AssertionError();
        ms.pop();
        if (ms.getMin() != 2 || ms.top() != 7) throw new AssertionError();
        System.out.println("queues ok");
    }
}

7.4 Monotonic stack and monotonic deque

import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Deque;

public final class Monotonic {

    /** nge[i] = first value to the right greater than a[i], or -1. Theta(n). */
    static int[] nextGreater(int[] a) {
        int[] nge = new int[a.length];
        Arrays.fill(nge, -1);
        Deque<Integer> st = new ArrayDeque<>();                 // indices, values decreasing
        for (int i = 0; i < a.length; i++) {
            while (!st.isEmpty() && a[st.peek()] < a[i]) nge[st.pop()] = a[i];
            st.push(i);
        }
        return nge;
    }

    /** Max of each window of size k. Deque of indices with decreasing values. Theta(n). */
    static int[] windowMax(int[] a, int k) {
        int[] out = new int[a.length - k + 1];
        Deque<Integer> dq = new ArrayDeque<>();
        for (int i = 0; i < a.length; i++) {
            while (!dq.isEmpty() && a[dq.peekLast()] <= a[i]) dq.pollLast(); // dominated
            dq.offerLast(i);
            if (dq.peekFirst() <= i - k) dq.pollFirst();                     // expired
            if (i >= k - 1) out[i - k + 1] = a[dq.peekFirst()];
        }
        return out;
    }

    /** Largest rectangle in a histogram: increasing stack, sentinel bar of height 0 at the end. */
    static long largestRectangle(int[] h) {
        Deque<Integer> st = new ArrayDeque<>();
        long best = 0;
        for (int i = 0; i <= h.length; i++) {
            int cur = (i == h.length) ? 0 : h[i];
            while (!st.isEmpty() && h[st.peek()] >= cur) {
                int height = h[st.pop()];
                int left = st.isEmpty() ? -1 : st.peek();      // previous smaller bar
                best = Math.max(best, (long) height * (i - left - 1));  // i is the next smaller bar
            }
            st.push(i);
        }
        return best;
    }

    public static void main(String[] args) {
        if (!Arrays.equals(nextGreater(new int[]{2, 1, 2, 4, 3}), new int[]{4, 2, 4, -1, -1})) throw new AssertionError();
        if (!Arrays.equals(windowMax(new int[]{1, 3, -1, -3, 5, 3, 6, 7}, 3), new int[]{3, 3, 5, 5, 6, 7})) throw new AssertionError();
        if (largestRectangle(new int[]{2, 1, 5, 6, 2, 3}) != 10) throw new AssertionError();
        System.out.println("monotonic ok");
    }
}

7.5 Expression evaluation: shunting-yard and recursive descent

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Map;

/** Integer calculator supporting + - * / parentheses and unary minus. */
public final class Calculator {
    private static final Map<Character, Integer> PREC = Map.of('+', 1, '-', 1, '*', 2, '/', 2, '~', 3);

    /** Shunting-yard with two stacks, evaluating as operators are popped. '~' = unary minus. */
    static long evalShunting(String s) {
        Deque<Long> nums = new ArrayDeque<>();
        Deque<Character> ops = new ArrayDeque<>();
        boolean expectOperand = true;
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (c == ' ') continue;
            if (Character.isDigit(c)) {
                long v = 0;
                while (i < s.length() && Character.isDigit(s.charAt(i))) v = v * 10 + (s.charAt(i++) - '0');
                i--;
                nums.push(v);
                expectOperand = false;
            } else if (c == '(') { ops.push(c); expectOperand = true; }
            else if (c == ')') {
                while (ops.peek() != '(') apply(nums, ops.pop());
                ops.pop();
                expectOperand = false;
            } else {
                char op = (c == '-' && expectOperand) ? '~' : c;
                // left-associative binary ops pop equal precedence; unary (right-assoc) does not
                while (!ops.isEmpty() && ops.peek() != '(' && op != '~'
                        && PREC.get(ops.peek()) >= PREC.get(op)) apply(nums, ops.pop());
                ops.push(op);
                expectOperand = true;
            }
        }
        while (!ops.isEmpty()) apply(nums, ops.pop());
        return nums.pop();
    }

    private static void apply(Deque<Long> nums, char op) {
        if (op == '~') { nums.push(-nums.pop()); return; }
        long b = nums.pop(), a = nums.pop();
        nums.push(switch (op) {
            case '+' -> a + b;
            case '-' -> a - b;
            case '*' -> a * b;
            case '/' -> a / b;                 // truncates toward zero like Java
            default -> throw new IllegalStateException("op " + op);
        });
    }

    /** Recursive descent: the grammar is the code. */
    static final class Parser {
        private final String s; private int pos;
        Parser(String s) { this.s = s.replace(" ", ""); }
        long parse() { long v = expr(); if (pos != s.length()) throw new IllegalArgumentException("junk at " + pos); return v; }
        private long expr() {                     // expr := term (('+'|'-') term)*
            long v = term();
            while (pos < s.length() && (s.charAt(pos) == '+' || s.charAt(pos) == '-'))
                v = s.charAt(pos++) == '+' ? v + term() : v - term();
            return v;
        }
        private long term() {                     // term := factor (('*'|'/') factor)*
            long v = factor();
            while (pos < s.length() && (s.charAt(pos) == '*' || s.charAt(pos) == '/'))
                v = s.charAt(pos++) == '*' ? v * factor() : v / factor();
            return v;
        }
        private long factor() {                   // factor := '-' factor | '(' expr ')' | number
            char c = s.charAt(pos);
            if (c == '-') { pos++; return -factor(); }
            if (c == '(') { pos++; long v = expr(); pos++; return v; }
            long v = 0;
            while (pos < s.length() && Character.isDigit(s.charAt(pos))) v = v * 10 + (s.charAt(pos++) - '0');
            return v;
        }
    }

    public static void main(String[] args) {
        String[] cases = {"1 + 2 * 3", "(1+(4+5+2)-3)+(6+8)", "2*(3+4)-10/3", "-(2+3)*4", "14-3-2", "-2*-3"};
        long[] want = {7, 23, 11, -20, 9, 6};
        for (int i = 0; i < cases.length; i++) {
            long a = evalShunting(cases[i]), b = new Parser(cases[i]).parse();
            if (a != want[i] || b != want[i]) throw new AssertionError(cases[i] + " -> " + a + ", " + b);
        }
        System.out.println("calculator ok");
    }
}

8. Applications in Backend Engineering

  • Caches. LRU/LFU and their hybrids order entries by recency or frequency with linked lists (or approximations). Every API gateway, ORM second-level cache and HTTP client connection pool has one.
  • Executors and backpressure. ThreadPoolExecutor = a BlockingQueue + workers. Choosing ArrayBlockingQueue(500) with CallerRunsPolicy instead of the default unbounded LinkedBlockingQueue is the difference between graceful degradation and an OOM. Spring's ThreadPoolTaskExecutor exposes queueCapacity for this reason.
  • Work stealing. ForkJoinPool (parallel streams, CompletableFuture.supplyAsync default pool, virtual thread carriers) and Go's runtime scheduler (per-P local run queues with stealing) both use per-worker deques/queues.
  • Async logging and messaging. Log4j 2's async loggers use the LMAX Disruptor ring buffer; Aeron and Chronicle Queue use ring buffers and append-only memory-mapped logs. Kafka partitions are append-only logs — a queue whose consumers keep their own read offsets.
  • Graph traversal. BFS uses a FIFO queue (shortest paths in unweighted graphs, e.g. degrees of separation, dependency layers); DFS uses a stack, explicit or the call stack (Chapter 5). 0-1 BFS uses a deque.
  • Parsing and validation. Bracket matching in config validators, HTML/XML tag balancing, expression languages (SpEL, JSONPath, feature-flag rule engines), and SQL parsers are stack machines.
  • Undo/redo and navigation. Two stacks: edits push onto undo; undo pops to redo; a new edit clears redo. Browser back/forward is the same.
  • Rate limiting. A sliding-window-log limiter keeps a deque of request timestamps per client, popping expired ones from the front.
  • Streaming analytics. Rolling max/min over the last N samples (e.g. peak latency over the last minute) uses a monotonic deque instead of rescanning the window.
  • Operating systems. Run queues, wait queues and the free page lists of kernels are intrusive linked lists; Redis lists are "quicklists" — a doubly linked list of compact listpack arrays, a hybrid that balances locality and O(1) end operations.

9. Case Studies

9.1 Redis: approximated LRU instead of a linked list Verified

A textbook LRU needs two pointers per key and list manipulation on every read. Redis instead stores a 24-bit LRU clock in each object and, when it must evict, samples a few keys (maxmemory-samples, default 5) and evicts the best candidate from a small pool. The Redis documentation shows that with 10 samples the approximation is very close to true LRU, while saving memory on every key. It also offers LFU modes using a probabilistic logarithmic counter. Lesson for interviews: the HashMap + DLL design is the exact answer; production systems often trade exactness for memory and concurrency.

9.2 Caffeine and W-TinyLFU Verified

Caffeine (the default cache provider in Spring Boot when on the classpath) uses W-TinyLFU: a small LRU "window" admits new entries, a frequency sketch (count-min, 4-bit counters, periodically halved) decides whether a candidate deserves to displace the main region's victim, and the main region is segmented LRU (probation + protected lists). Reads are recorded into striped lossy ring buffers and drained under a try-lock, so the linked-list reorderings do not serialise readers. Ben Manes's wiki reports hit rates close to optimal across database, search and web traces.

9.3 LMAX Disruptor Verified

LMAX built a retail exchange processing millions of orders per second on a single business-logic thread. Their technical paper explains why queues were the bottleneck: linked queues allocate nodes (GC pressure) and contend on head/tail; array queues contend on a shared size. The Disruptor pre-allocates a ring of event objects, uses sequence counters padded to separate cache lines (avoiding false sharing), and lets consumers form a dependency graph. It is the ring buffer of §7.3, engineered for mechanical sympathy.

9.4 Michael–Scott queue in the JDK Verified

The Javadoc of ConcurrentLinkedQueue states that it is based on the algorithm in Michael and Scott's 1996 paper "Simple, Fast, and Practical Non-Blocking and Blocking Concurrent Queue Algorithms". The algorithm keeps a dummy node and uses CAS on tail.next then on tail, allowing other threads to "help" swing a lagging tail — the sentinel idea from §3.1 doing real concurrent work.

9.5 Fork/Join work stealing Verified

Doug Lea's 2000 paper describes per-worker double-ended queues where owners push/pop LIFO and thieves steal FIFO, following Cilk's work-stealing design. The JDK's ForkJoinPool implements this and is the default scheduler for virtual threads (JDK 21, JEP 444).

12. Common Mistakes

  • Losing the rest of the list: overwriting cur.next before saving it.
  • Null-pointer on fast pointers: the loop guard must be fast != null && fast.next != null, in that order.
  • Skipping the dummy node and writing special cases for the head — which then contain the bug.
  • Forgetting to remove evicted keys from the map in an LRU (map grows forever while the list is bounded) — or storing nodes without their key, making that removal impossible.
  • Using java.util.Stack or LinkedList as a queue in hot code; use ArrayDeque.
  • Mixing Deque method families: push adds to the front, offer/add to the back. Using push and poll together gives LIFO; offer and poll give FIFO. Read the Javadoc table.
  • Comparing Integer stack tops with == (st.peek() == a[i]) — identity, not value, beyond the cache range.
  • Storing values instead of indices in a monotonic deque — you then cannot tell when the front has left the window.
  • Strict vs non-strict comparisons in monotonic stacks: with duplicates, counting problems (e.g. sum of subarray minimums) need one side strict and the other non-strict to avoid double counting.
  • Python list.pop(0) as a queue — Θ(n) per pop, Θ(n²) BFS.
  • Unbounded executor queues (Executors.newFixedThreadPool) that accumulate millions of tasks during an outage.
  • Iterating a LinkedList with get(i) — Θ(n²).
  • Integer division semantics: Java and C truncate toward zero; Python's // floors. RPN problems specify truncation.
  • Recursive list algorithms on long lists — StackOverflowError in production for inputs that never appeared in tests.

13. Production Concerns

  • Bound every queue that crosses a trust or rate boundary. Expose queue depth and wait time as metrics (Micrometer's ExecutorServiceMetrics binds executor queue sizes); alert on sustained growth, which by Little's law is latency growth.
  • Choose a rejection policy deliberately. CallerRunsPolicy slows producers (natural backpressure for HTTP threads) but can block event loops; AbortPolicy fails fast and should map to HTTP 429/503 with retry hints.
  • Avoid false sharing in hand-rolled concurrent ring buffers: pad producer and consumer counters onto different cache lines (the JDK has @jdk.internal.vm.annotation.Contended internally; libraries pad manually).
  • Memory: a LinkedList<Long> of 10⁷ elements costs roughly 10⁷ × (24 node + 16 Long) ≈ 400 MB; a long[] costs 80 MB. Caches holding millions of entries should account for per-entry overhead in sizing (Caffeine can bound by weight).
  • Thread safety of LRU structures: access-ordered LinkedHashMap mutates on get; never share it unsynchronised. Prefer Caffeine.
  • Security: expression evaluators must not expose reflection or bean access to untrusted input (SpEL injection has produced real CVEs); deep nesting in input (JSON, expressions) can exhaust recursive parsers' stacks — enforce depth limits.
  • Testing: property-based tests (jqwik in Java, Hypothesis in Python) comparing your structure against ArrayDeque or LinkedHashMap as a reference model catch pointer bugs quickly.

How to recognise linked-list patterns

  • Extra pointers (random, child) → interleave copies or a map from old to new node.

A1 · Easy — "Remove Duplicates from Sorted List"

Given a sorted singly linked list, delete nodes so that each value appears once.

Solution

Approach: because duplicates are adjacent, skip cur.next while it equals cur. Θ(n) time, Θ(1) space. Do not advance cur after a deletion — there may be several duplicates in a row.

class LA1DedupSorted {
    static final class Node { int val; Node next; Node(int v, Node n) { val = v; next = n; } }
    static Node dedup(Node head) {
        for (Node cur = head; cur != null && cur.next != null; ) {
            if (cur.next.val == cur.val) cur.next = cur.next.next;   // stay on cur
            else cur = cur.next;
        }
        return head;
    }
    public static void main(String[] args) {
        Node h = dedup(new Node(1, new Node(1, new Node(1, new Node(2, new Node(3, new Node(3, null)))))));
        StringBuilder sb = new StringBuilder();
        for (; h != null; h = h.next) sb.append(h.val);
        if (!sb.toString().equals("123")) throw new AssertionError(sb);
        System.out.println("ok");
    }
}

A2 · Easy — "Intersection of Two Linked Lists"

Two singly linked lists may merge at some node (sharing all later nodes). Return the first shared node or null, in O(1) extra space.

Solution

Approach: walk pointer p over A then B, and q over B then A. Both travel a + c + b steps (a, b = private lengths, c = shared tail), so they arrive at the intersection simultaneously, or both reach null together. Θ(a + b) time, Θ(1) space. Compare references, not values.

class LA2Intersection {
    static final class Node { int val; Node next; Node(int v, Node n) { val = v; next = n; } }
    static Node intersect(Node a, Node b) {
        Node p = a, q = b;
        while (p != q) {
            p = (p == null) ? b : p.next;
            q = (q == null) ? a : q.next;
        }
        return p;
    }
    public static void main(String[] args) {
        Node shared = new Node(8, new Node(4, null));
        Node a = new Node(4, new Node(1, shared)), b = new Node(5, new Node(6, new Node(1, shared)));
        if (intersect(a, b) != shared || intersect(new Node(1, null), new Node(2, null)) != null) throw new AssertionError();
        System.out.println("ok");
    }
}

A3 · Easy/Medium — "Palindrome Linked List" in O(1) space

Decide whether a singly linked list reads the same forwards and backwards without copying it to an array.

Solution

Approach: find the middle with fast/slow, reverse the second half, compare, then (good manners in production) reverse it back. Θ(n) time, Θ(1) space. Mention that this temporarily mutates shared data — not acceptable if other threads read the list.

class LA3PalindromeList {
    static final class Node { int val; Node next; Node(int v, Node n) { val = v; next = n; } }
    static Node reverse(Node h) { Node p = null; while (h != null) { Node n = h.next; h.next = p; p = h; h = n; } return p; }
    static boolean isPalindrome(Node head) {
        Node slow = head, fast = head;
        while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
        Node second = reverse(slow), p = head, q = second;
        boolean ok = true;
        while (q != null) { if (p.val != q.val) { ok = false; break; } p = p.next; q = q.next; }
        reverse(second);                                   // restore the input
        return ok;
    }
    static Node of(int... v) { Node h = null; for (int i = v.length - 1; i >= 0; i--) h = new Node(v[i], h); return h; }
    public static void main(String[] args) {
        if (!isPalindrome(of(1, 2, 2, 1)) || !isPalindrome(of(1, 2, 3, 2, 1)) || isPalindrome(of(1, 2))) throw new AssertionError();
        System.out.println("ok");
    }
}

A4 · Medium — "Reorder List"

Rearrange L0 → L1 → … → Ln into L0 → Ln → L1 → Ln−1 → … in place.

Solution

Approach: three classic moves composed: split at the middle (fast/slow), reverse the second half, interleave the halves. Θ(n), Θ(1). Interviewers use this to see whether you can decompose a problem into known primitives.

class LA4ReorderList {
    static final class Node { int val; Node next; Node(int v, Node n) { val = v; next = n; } }
    static void reorder(Node head) {
        if (head == null) return;
        Node slow = head, fast = head;
        while (fast.next != null && fast.next.next != null) { slow = slow.next; fast = fast.next.next; }
        Node second = null, cur = slow.next;
        slow.next = null;                                    // split
        while (cur != null) { Node n = cur.next; cur.next = second; second = cur; cur = n; }  // reverse
        for (Node first = head; second != null; ) {          // interleave
            Node n1 = first.next, n2 = second.next;
            first.next = second; second.next = n1;
            first = n1; second = n2;
        }
    }
    public static void main(String[] args) {
        Node h = null; for (int i = 5; i >= 1; i--) h = new Node(i, h);
        reorder(h);
        StringBuilder sb = new StringBuilder(); for (Node p = h; p != null; p = p.next) sb.append(p.val);
        if (!sb.toString().equals("15243")) throw new AssertionError(sb);
        System.out.println("ok");
    }
}

A5 · Medium — "Add Two Numbers"

Two non-negative integers are stored as lists of digits, least significant first. Return their sum as a list.

Solution

Approach: schoolbook addition with a carry and a dummy head; continue while either list or the carry remains. Θ(max(m, n)). Follow-up (most significant digit first): push digits onto two stacks, or reverse both lists.

class LA5AddTwoNumbers {
    static final class Node { int val; Node next; Node(int v, Node n) { val = v; next = n; } }
    static Node add(Node a, Node b) {
        Node dummy = new Node(0, null), t = dummy;
        int carry = 0;
        while (a != null || b != null || carry != 0) {
            int s = carry + (a != null ? a.val : 0) + (b != null ? b.val : 0);
            t = t.next = new Node(s % 10, null);
            carry = s / 10;
            if (a != null) a = a.next;
            if (b != null) b = b.next;
        }
        return dummy.next;
    }
    public static void main(String[] args) {
        Node a = new Node(2, new Node(4, new Node(3, null))), b = new Node(5, new Node(6, new Node(4, null)));
        StringBuilder sb = new StringBuilder(); for (Node p = add(a, b); p != null; p = p.next) sb.append(p.val);
        if (!sb.toString().equals("708")) throw new AssertionError(sb);        // 342 + 465 = 807
        System.out.println("ok");
    }
}

A6 · Medium — "Copy List with Random Pointer"

Each node has next and an arbitrary random reference (possibly null). Produce a deep copy.

Solution

Approach 1: a Map<Node, Node> old → copy, two passes; Θ(n) space. Approach 2 (O(1) extra): interleave copies (A → A' → B → B'…), set copy.random = orig.random.next, then unweave. The interleaving makes the "map" implicit in the structure itself.

class LA6CopyRandomList {
    static final class Node { int val; Node next, random; Node(int v) { val = v; } }
    static Node copy(Node head) {
        for (Node p = head; p != null; p = p.next.next) {          // 1. interleave
            Node c = new Node(p.val); c.next = p.next; p.next = c;
        }
        for (Node p = head; p != null; p = p.next.next)             // 2. random links
            p.next.random = (p.random == null) ? null : p.random.next;
        Node dummy = new Node(0), t = dummy;
        for (Node p = head; p != null; p = p.next) {                 // 3. unweave
            t = t.next = p.next;
            p.next = p.next.next;
        }
        return dummy.next;
    }
    public static void main(String[] args) {
        Node a = new Node(7), b = new Node(13), c = new Node(11);
        a.next = b; b.next = c; b.random = a; c.random = c;
        Node x = copy(a);
        if (x == a || x.next.random != x || x.next.next.random != x.next.next || x.random != null) throw new AssertionError();
        if (a.next != b || b.next != c) throw new AssertionError("original not restored");
        System.out.println("ok");
    }
}

A7 · Hard — "Reverse Nodes in k-Group"

Reverse the list in consecutive groups of k; a final group shorter than k stays as is. O(1) extra space.

Solution

Approach: keep groupPrev (node before the group). Check that k nodes exist; reverse them with the standard loop, using the node after the group as the initial prev so the reversed group is already attached to the rest; then link groupPrev.next to the new group head and move groupPrev to the old group head (now the group's tail). Θ(n) time, Θ(1) space.

class LA7ReverseKGroup {
    static final class Node { int val; Node next; Node(int v, Node n) { val = v; next = n; } }
    static Node reverseKGroup(Node head, int k) {
        Node dummy = new Node(0, head), groupPrev = dummy;
        while (true) {
            Node kth = groupPrev;
            for (int i = 0; i < k && kth != null; i++) kth = kth.next;
            if (kth == null) break;                             // fewer than k left
            Node groupNext = kth.next, prev = groupNext, cur = groupPrev.next;
            while (cur != groupNext) { Node n = cur.next; cur.next = prev; prev = cur; cur = n; }
            Node oldHead = groupPrev.next;
            groupPrev.next = kth;                               // kth is the new group head
            groupPrev = oldHead;                                // old head is now the tail
        }
        return dummy.next;
    }
    public static void main(String[] args) {
        Node h = null; for (int i = 5; i >= 1; i--) h = new Node(i, h);
        StringBuilder sb = new StringBuilder(); for (Node p = reverseKGroup(h, 2); p != null; p = p.next) sb.append(p.val);
        if (!sb.toString().equals("21435")) throw new AssertionError(sb);
        System.out.println("ok");
    }
}

14.2 Ladder B — Stacks and queues

How to recognise a stack problem

  • Nested structure: brackets, tags, encoded strings like 3[ab], directories with ...
  • "The most recent unmatched / unresolved item" decides what happens next.
  • Collisions or cancellations between neighbours (asteroids, adjacent duplicates removal).
  • Recursion you must make iterative, or depth that could overflow.
  • Expressions with precedence.

B1 · Easy — "Valid Parentheses"

Decide whether a string of ()[]{} is properly nested.

Solution

Approach: push the expected closer for each opener; on a closer, the stack top must match. Valid iff the stack ends empty. Θ(n). Early exit if the length is odd.

import java.util.*;

class SB1ValidParens {
    static boolean valid(String s) {
        if (s.length() % 2 == 1) return false;
        Deque<Character> st = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            switch (c) {
                case '(' -> st.push(')');
                case '[' -> st.push(']');
                case '{' -> st.push('}');
                default -> { if (st.isEmpty() || st.pop() != c) return false; }
            }
        }
        return st.isEmpty();
    }
    public static void main(String[] args) {
        if (!valid("([]{})") || valid("(]") || valid("((") || !valid("")) throw new AssertionError();
        System.out.println("ok");
    }
}

B2 · Medium — "Simplify Path"

Canonicalise a Unix absolute path: collapse repeated slashes, resolve . and ...

Solution

Approach: split on "/", push names, pop on "..", ignore "" and ".". Use a deque so you can join from the bottom. Θ(n). Security tie-in: this is path normalisation, the defence against path traversal (../../etc/passwd) — in Java use Path.normalize() and then verify the result startsWith the allowed base directory.

import java.util.*;

class SB2SimplifyPath {
    static String simplify(String path) {
        Deque<String> st = new ArrayDeque<>();
        for (String part : path.split("/")) {
            if (part.isEmpty() || part.equals(".")) continue;
            if (part.equals("..")) { if (!st.isEmpty()) st.pollLast(); }
            else st.offerLast(part);
        }
        return "/" + String.join("/", st);
    }
    public static void main(String[] args) {
        if (!simplify("/a/./b/../../c/").equals("/c") || !simplify("/../").equals("/") || !simplify("/home//foo/").equals("/home/foo")) throw new AssertionError();
        System.out.println("ok");
    }
}

B3 · Medium — "Asteroid Collision"

Integers represent asteroids moving right (positive) or left (negative) with size |x|. When two meet, the smaller explodes; equal sizes both explode. Return the survivors.

Solution

Approach: a stack of survivors. A left-mover collides only with right-movers on top of the stack; resolve collisions in a loop. Each asteroid is pushed and popped at most once: Θ(n).

import java.util.*;

class SB3Asteroids {
    static int[] collide(int[] a) {
        Deque<Integer> st = new ArrayDeque<>();
        for (int x : a) {
            boolean alive = true;
            while (alive && x < 0 && !st.isEmpty() && st.peek() > 0) {
                int top = st.peek();
                if (top < -x) st.pop();                 // top explodes, keep checking
                else { alive = false; if (top == -x) st.pop(); }
            }
            if (alive) st.push(x);
        }
        int[] out = new int[st.size()];
        for (int i = out.length - 1; i >= 0; i--) out[i] = st.pop();
        return out;
    }
    public static void main(String[] args) {
        if (!Arrays.equals(collide(new int[]{5, 10, -5}), new int[]{5, 10})) throw new AssertionError();
        if (!Arrays.equals(collide(new int[]{8, -8}), new int[]{})) throw new AssertionError();
        if (!Arrays.equals(collide(new int[]{10, 2, -5}), new int[]{10})) throw new AssertionError();
        System.out.println("ok");
    }
}

B4 · Medium — "Decode String"

Expand encodings of the form k[...], which may nest, e.g. 3[a2[c]] → accaccacc.

Solution

Approach: two stacks — counts and partially built strings. On "[", push the current count and builder and start fresh; on "]", pop and append the current builder k times to the outer one. Θ(output length).

import java.util.*;

class SB4DecodeString {
    static String decode(String s) {
        Deque<Integer> counts = new ArrayDeque<>();
        Deque<StringBuilder> outer = new ArrayDeque<>();
        StringBuilder cur = new StringBuilder();
        int k = 0;
        for (char c : s.toCharArray()) {
            if (Character.isDigit(c)) k = k * 10 + (c - '0');
            else if (c == '[') { counts.push(k); outer.push(cur); cur = new StringBuilder(); k = 0; }
            else if (c == ']') { StringBuilder up = outer.pop(); up.append(cur.toString().repeat(counts.pop())); cur = up; }
            else cur.append(c);
        }
        return cur.toString();
    }
    public static void main(String[] args) {
        if (!decode("3[a2[c]]").equals("accaccacc") || !decode("2[abc]3[cd]ef").equals("abcabccdcdcdef")) throw new AssertionError();
        System.out.println("ok");
    }
}

B5 · Medium — "Basic Calculator II" (no parentheses)

Evaluate an expression with non-negative integers and + - * / (integer division truncating), without parentheses, in Θ(n) and without a full parser.

Solution

Approach: keep the last operator. For + and −, push ±num; for * and /, pop, combine and push. The answer is the stack sum. Can be reduced to Θ(1) space by keeping only the "last term" instead of a stack. For parentheses and unary minus, see §7.5.

class SB5CalculatorII {
    static int calc(String s) {
        int result = 0, last = 0, num = 0;
        char op = '+';
        for (int i = 0; i <= s.length(); i++) {
            char c = i < s.length() ? s.charAt(i) : '+';      // sentinel flushes the last number
            if (c == ' ') continue;
            if (Character.isDigit(c)) { num = num * 10 + (c - '0'); continue; }
            switch (op) {
                case '+' -> { result += last; last = num; }
                case '-' -> { result += last; last = -num; }
                case '*' -> last *= num;
                case '/' -> last /= num;
                default -> throw new IllegalStateException();
            }
            op = c; num = 0;
        }
        return result + last;
    }
    public static void main(String[] args) {
        if (calc("3+2*2") != 7 || calc(" 3/2 ") != 1 || calc(" 3+5 / 2 ") != 5 || calc("14-3*2") != 8) throw new AssertionError();
        System.out.println("ok");
    }
}

B6 · Hard — "Longest Valid Parentheses"

Given a string of '(' and ')', return the length of the longest well-formed substring.

Solution

Approach: stack of indices seeded with −1 as the "base" before the current valid run. Push '(' indices. On ')', pop; if the stack becomes empty, push the current index as the new base; else the valid length is i − peek(). Θ(n). (A two-pass counter solution achieves Θ(1) space.)

import java.util.*;

class SB6LongestValidParens {
    static int longest(String s) {
        Deque<Integer> st = new ArrayDeque<>();
        st.push(-1);
        int best = 0;
        for (int i = 0; i < s.length(); i++) {
            if (s.charAt(i) == '(') st.push(i);
            else {
                st.pop();
                if (st.isEmpty()) st.push(i);               // unmatched ')' becomes the new base
                else best = Math.max(best, i - st.peek());
            }
        }
        return best;
    }
    public static void main(String[] args) {
        if (longest("(()") != 2 || longest(")()())") != 4 || longest("()(())") != 6 || longest("") != 0) throw new AssertionError();
        System.out.println("ok");
    }
}
