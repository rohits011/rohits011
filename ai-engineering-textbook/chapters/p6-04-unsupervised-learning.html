Part 6 · Chapter 4

Unsupervised Learning: Clustering & Dimensionality Reduction

Most data has no labels. Unsupervised learning finds structure anyway: groups of similar customers, a handful of directions that explain most of the variation in hundreds of metrics, the rare request that looks like nothing seen before. This chapter derives the main algorithms (k-means, hierarchical clustering, DBSCAN, Gaussian mixtures, PCA, t-SNE, UMAP, isolation forests), shows exactly what each one optimises, and is candid about the central difficulty: without labels, "good" is defined by you, so evaluation needs as much care as the algorithm.

  • Prerequisites: Chapter 6.1 (distances, eigenvectors, SVD, Gaussian distribution, MLE) and Chapter 6.2 (scaling).
  • You will be able to: implement k-means and PCA from scratch; choose k with elbow and silhouette analysis; pick between k-means, hierarchical, DBSCAN and GMMs based on cluster shape and noise; explain EM; compute and interpret explained variance; use t-SNE and UMAP responsibly for visualisation; and build anomaly detectors with isolation forests for logs and metrics.

1. Introduction: Structure Without Labels

In supervised learning, the labels define the goal. In unsupervised learning you only have inputs x, and you ask the data to describe itself. Three questions cover most practical uses:

  • Clustering: which examples belong together? Customer segments, groups of similar log lines, families of malware samples, near-duplicate documents.
  • Dimensionality reduction: can these many correlated measurements be summarised by a few coordinates? Compressing 500 service metrics into 10 components, plotting 768-dimensional embeddings in 2-D, denoising inputs before a downstream model.
  • Anomaly detection: which examples do not fit? A login from an impossible location, a latency pattern unlike any previous deploy, a transaction that is isolated from everything else.

The difficulty is that there is no single right answer. Customers can be segmented by spend, by behaviour, or by product mix; all three are valid clusterings of the same table. The algorithm's objective (a distance, a density, a likelihood) encodes an assumption about what "similar" means, and the features you feed it encode the rest. So the engineering skill is less about running KMeans.fit and more about choosing representation, objective and evaluation so that the structure found is useful for a decision.

Bridging from Java & Spring Boot

What you already know
You have grouped things by key (Collectors.groupingBy), deduplicated with hashes, set static alert thresholds in Prometheus, and grepped logs for unfamiliar error messages. Clustering is "group by" when there is no key; anomaly detection is a learned alert threshold in many dimensions; PCA is compression with a known, bounded loss.
Why that is not enough
Static thresholds fail on multi-dimensional, seasonal, evolving behaviour: a CPU of 70% is normal at peak and alarming at 4 a.m. Exact-match grouping misses near-duplicates and new variants. With hundreds of metrics, humans cannot see the correlations.
The modern approach
Represent entities as scaled feature vectors or learned embeddings, then cluster (k-means/GMM for compact groups, HDBSCAN/DBSCAN for arbitrary shapes and noise), reduce (PCA for compression and preprocessing, UMAP/t-SNE for visualisation only), and score anomalies (isolation forest, reconstruction error, density). Validate with domain experts and downstream metrics.
Where Python and Go fit
Exploration and model fitting in Python (scikit-learn, umap-learn, hdbscan support in scikit-learn). Serving is cheap and portable: k-means assignment is "nearest centroid", a dot-product loop over k centroids you can ship as a JSON array to a Java or Go service; PCA projection is one matrix multiply; isolation forests export to ONNX.
In production
Segments are recomputed in batch (nightly Spark or Python jobs) and written to a customer attribute table that Spring services read; anomaly scores are computed in streaming jobs and turned into alerts; embedding projections feed internal dashboards for model debugging.
Use it when / avoid it when
Use it for exploration, compression, segmentation and novelty detection when labels are unavailable or expensive. Avoid it when you actually have labels for the decision (use supervised learning), or when stakeholders will treat discovered clusters as ground truth without validation.

3. Fundamentals

3.1 Similarity is a design decision

Every clustering algorithm needs a notion of closeness. For scaled tabular features, Euclidean distance is the default; for embeddings, cosine distance (1 − cosine similarity); for binary feature sets (which products did the customer buy?), Jaccard distance (1 − |A ∩ B| / |A ∪ B|). Scaling matters enormously (Chapter 6.2): cluster customers on (annual spend in dollars, number of orders) without scaling and you are clustering on spend alone. Feature choice matters even more: clustering on behaviour features finds behavioural segments; clustering on demographics finds demographic ones.

3.2 K-means

Intuition. Choose k "centres". Assign each point to its nearest centre. Move each centre to the average of the points assigned to it. Repeat until nothing changes. The result is k groups, each summarised by its centre (centroid), and the space is carved into regions (Voronoi cells) closest to each centroid.

Objective. K-means minimises the total squared distance from points to their assigned centroid, the within-cluster sum of squares (WCSS, called inertia_ in scikit-learn):

\[ J = \sum_{i=1}^{m}\big\|\mathbf{x}_i - \boldsymbol\mu_{c(i)}\big\|_2^2. \]

Worked example (1-D). Points 1, 2, 3, 10, 11, 12 and k = 2, starting centroids at 1 and 2. Assign: 1 → c₁; 2, 3, 10, 11, 12 → c₂ (closer to 2). Update: μ₁ = 1, μ₂ = (2 + 3 + 10 + 11 + 12)/5 = 7.6. Reassign: 1, 2, 3 are closer to 1 than 7.6 (3 is 2 from 1, 4.6 from 7.6), 10, 11, 12 to 7.6. Update: μ₁ = 2, μ₂ = 11. Reassign: no change. Converged with J = (1 + 0 + 1) + (1 + 0 + 1) = 4.

Why it converges. Each step can only lower J: the assignment step picks the closest centroid for each point (cannot increase distance), and the update step sets each centroid to the mean, which is the point minimising the sum of squared distances to a set (proved in §6). J is bounded below and there are finitely many assignments, so it stops. But it converges to a local minimum, which depends on initialisation.

Assumptions baked in. Squared Euclidean distance and mean centroids favour convex, roughly spherical clusters of similar size. K-means will split one elongated cluster in two and merge two nearby round ones; it cannot find rings or crescents; every point is forced into some cluster, including outliers, which drag centroids. And you must choose k.

3.3 K-means++ initialisation

Random initial centroids often start two centroids in the same true cluster, leaving another cluster without one, and Lloyd's iterations cannot escape. K-means++ spreads the seeds out: pick the first centroid uniformly at random from the data; then pick each next centroid from the data with probability proportional to D(x)², the squared distance from x to the nearest centroid chosen so far. Points far from existing centroids are much more likely to be chosen.

Example: centroid 1 is at 1 among points {1, 2, 3, 10, 11, 12}. D² values: 0, 1, 4, 81, 100, 121, total 307. The probability that the second seed lands in the right-hand group is (81 + 100 + 121)/307 ≈ 98%. Arthur and Vassilvitskii proved the expected cost after seeding alone is within O(log k) of optimal. scikit-learn uses k-means++ by default and also runs several initialisations (n_init) keeping the best.

3.4 Choosing k: elbow and silhouette

Elbow method. Plot WCSS against k. WCSS always decreases as k grows (with k = m it is zero), but the decrease slows sharply once k passes the "natural" number of groups. The k at the bend is a candidate. It is often ambiguous, a smooth curve with no clear elbow.

Silhouette. For each point i, let a(i) be its average distance to other points in its own cluster (cohesion), and b(i) the average distance to points in the nearest other cluster (separation). The silhouette is

\[ s(i) = \frac{b(i) - a(i)}{\max\{a(i), b(i)\}} \in [-1, 1]. \]

Near 1: well inside its cluster and far from others. Near 0: on a boundary. Negative: probably assigned to the wrong cluster. Example: a(i) = 2, b(i) = 8 gives s = 6/8 = 0.75; a(i) = 5, b(i) = 4 gives s = −1/5 = −0.2. The mean silhouette over all points summarises a clustering; plotting per-cluster silhouette distributions reveals weak clusters. Its cost is O(m²) distances, so use a sample for large data. Other internal indices: Davies-Bouldin (lower is better), Calinski-Harabasz (higher is better). All of them, like k-means itself, prefer compact convex clusters.

The real criterion is usefulness. A segmentation with k = 5 that marketing can act on beats k = 7 with a higher silhouette that nobody can name. Check stability (do clusters persist across bootstrap samples and random seeds?) and interpretability (can you describe each centroid?).

3.5 Hierarchical (agglomerative) clustering

Intuition. Start with every point as its own cluster. Repeatedly merge the two closest clusters until one remains. The full merge history is a tree, the dendrogram; cutting it at a height yields a flat clustering, and you can choose the cut after seeing the tree.

"Closest clusters" needs a linkage rule:

  • Single: distance between the closest pair of points. Finds elongated, chained shapes but suffers "chaining" (a thin bridge of points merges two clusters).
  • Complete: distance between the farthest pair. Compact clusters; sensitive to outliers.
  • Average: mean pairwise distance. A compromise.
  • Ward: merge the pair that increases total within-cluster variance the least. Produces k-means-like compact clusters; scikit-learn's default.

Example with points A = 0, B = 1, C = 5, D = 6, E = 20 under single linkage: merge A-B (distance 1) and C-D (1), then {A, B}-{C, D} (distance 4, between B and C), then E (distance 14). Cutting between heights 4 and 14 gives {A, B, C, D} and {E}; cutting between 1 and 4 gives {A, B}, {C, D}, {E}.

Cost: standard algorithms need O(m²) memory for the distance matrix and O(m²) to O(m³) time, so hierarchical clustering suits thousands to tens of thousands of points, not millions. It shines when the hierarchy itself is meaningful (taxonomies of products, families of log templates) and when connectivity constraints matter (only merge geographically adjacent regions).

3.6 DBSCAN and HDBSCAN: density-based clustering

Intuition. A cluster is a region where points are packed densely, separated from other clusters by sparse regions. Points in sparse regions are noise, not forced into any cluster. Two parameters: a radius ε and a minimum count min_samples.

  • A core point has at least min_samples points (including itself) within ε.
  • A border point is within ε of a core point but is not core itself.
  • A noise point is neither.

Clusters are formed by connecting core points within ε of each other (transitively) and attaching their border points. Consequences: DBSCAN finds arbitrarily shaped clusters (rings, crescents, river-shaped GPS traces), determines the number of clusters itself, and labels outliers as noise (label −1). Its weaknesses: one global ε cannot handle clusters of very different densities, and ε is hard to choose in high dimensions. The k-distance plot helps: sort every point's distance to its k-th nearest neighbour (k = min_samples) and choose ε near the knee.

HDBSCAN removes the single-ε limitation: conceptually it runs DBSCAN over all ε values, builds a hierarchy of density-connected clusters, and extracts the most persistent (stable) ones. Its main parameter, min_cluster_size, is far more intuitive than ε. For embeddings and geospatial data, HDBSCAN is usually a better default than DBSCAN Opinion.

3.7 Gaussian mixture models and EM

Intuition. Assume the data were generated by K Gaussian "blobs": to create a point, pick blob k with probability πk, then sample from that blob's Gaussian with mean μk and covariance Σk. Fitting the model means recovering the blobs. Unlike k-means, each point gets a soft assignment, a probability of belonging to each blob (its responsibility), and blobs can be elongated ellipses of different sizes thanks to full covariance matrices.

\[ p(\mathbf{x}) = \sum_{k=1}^{K}\pi_k\,\mathcal{N}(\mathbf{x}\mid\boldsymbol\mu_k,\Sigma_k). \]

EM (expectation-maximisation) fits it by alternating two steps, structurally the same as k-means:

  • E-step: given current parameters, compute each point's responsibilities rik = πk𝒩(xi|μk, Σk) / Σj πj𝒩(xi|μj, Σj). That is Bayes' theorem: prior πk times likelihood, normalised.
  • M-step: given responsibilities, re-estimate each blob as a weighted MLE: πk = average responsibility; μk = responsibility-weighted mean; Σk = responsibility-weighted covariance.

Numeric E-step example (1-D): two components with equal weights, μ₁ = 0, μ₂ = 4, both σ = 1. For x = 1: the densities are proportional to e−0.5 = 0.607 and e−4.5 = 0.011, so r₁ = 0.607/0.618 ≈ 0.982, r₂ ≈ 0.018. For x = 2 (equidistant), r₁ = r₂ = 0.5.

Each EM iteration provably does not decrease the data log-likelihood. K-means is the limit of EM for a GMM with equal, spherical covariances shrinking to zero, where soft responsibilities become hard assignments. GMMs give you a density p(x), useful for anomaly scoring (low p(x) is unusual), and a principled way to choose K via the BIC (Bayesian information criterion), which trades log-likelihood against parameter count: BIC = −2 log L + (number of parameters) × log m, lower is better.

3.8 Principal component analysis

Intuition. Rotate the coordinate system so that the first axis points along the direction in which the data vary the most, the second along the direction of most remaining variation (perpendicular to the first), and so on. Keep only the first few axes. Because many real features are correlated (CPU and request rate; height and weight; pixels near each other), a few directions often carry most of the variation, and dropping the rest loses little.

Picture 2-D points scattered along the line y ≈ x: say (1, 1.2), (2, 1.9), (3, 3.1), (4, 3.8). The first principal direction is close to (0.707, 0.707), along the diagonal; projecting onto it gives each point a single coordinate, and the second direction (−0.707, 0.707) carries only small wiggles. One number per point instead of two, with little error.

How it is computed. Centre the data (subtract each feature's mean, essential). Then either eigen-decompose the covariance matrix C = XᵀX/(m − 1), whose eigenvectors are the principal directions and eigenvalues the variances along them, or (as libraries do) take the SVD of the centred X = UΣVᵀ: the rows of Vᵀ are the principal directions, the projected coordinates (scores) are UΣ = XV, and the variances are σj²/(m − 1). §6 derives why the top eigenvector maximises variance.

Explained variance. The fraction of total variance captured by component j is λj/Σλ. If eigenvalues are [4.0, 1.0, 0.5, 0.3, 0.2] (total 6.0), the first component explains 66.7%, the first two 83.3%, the first three 91.7%. A scree plot of these values, or a rule like "keep enough components for 95% cumulative variance" (PCA(n_components=0.95)), sets the dimension.

Standardise or not? PCA on raw features is dominated by the features with the largest variance (units!). Standardise when features have different units (equivalent to PCA on the correlation matrix); do not when features share a unit and their raw variance is meaningful (pixel intensities).

Uses. Compression and denoising (reconstruct from the top k components: X̂ = X VkVkᵀ, adding back the mean); decorrelating features before linear models; speeding up downstream models and k-NN; visualising (first two components); anomaly detection via reconstruction error (a point poorly reconstructed by the top components does not follow the usual correlations, e.g. CPU high while request rate is low). PCA is linear: it cannot unroll curved structures (a "Swiss roll"), which is where t-SNE and UMAP come in.

3.9 t-SNE

Intuition. t-SNE (t-distributed stochastic neighbour embedding) places points in 2-D so that each point's neighbours in high dimensions remain its neighbours on the plot. It converts high-dimensional distances into neighbour probabilities (each point "picks" a neighbour with probability decreasing in distance, using a Gaussian whose width is set per point so that its effective number of neighbours equals the perplexity, typically 5–50). It then finds 2-D positions whose neighbour probabilities, computed with a heavy-tailed Student-t kernel, match the originals, by minimising the KL divergence between the two distributions with gradient descent.

The heavy tail is the clever part: in 2-D there is not enough room to keep all moderate distances, so the t-kernel lets moderately distant points be placed far apart, producing well-separated visual clusters (alleviating the "crowding problem").

Read t-SNE plots carefully. Local neighbourhoods are meaningful; global geometry largely is not. Cluster sizes in the plot do not reflect real spread; distances between clusters do not reflect real distances; different perplexities and seeds give different pictures; and random data can show apparent clusters at low perplexity. t-SNE is for visualisation and hypothesis generation only, never as features for a model or as proof of cluster structure. It is also O(m log m) at best (Barnes-Hut approximation) and has no straightforward transform for new points.

3.10 UMAP

Intuition. UMAP (uniform manifold approximation and projection) builds a weighted k-nearest-neighbour graph in high dimensions (with each point's distances rescaled by its local density) and then lays that graph out in low dimensions, pulling connected points together and pushing random non-neighbours apart, optimising a cross-entropy between the high- and low-dimensional edge weights. Parameters: n_neighbors (local versus global emphasis, like perplexity) and min_dist (how tightly points may pack).

Compared with t-SNE, UMAP is typically faster on large datasets, tends to preserve somewhat more global structure, supports transforming new points, and can embed into more than 2 dimensions as a preprocessing step for clustering (UMAP to ~10 dimensions, then HDBSCAN, is a popular pipeline for clustering text embeddings, used for example by the BERTopic library). The same caveats about interpreting distances and cluster sizes apply.

3.11 Anomaly detection and isolation forests

Anomaly detection asks "how unusual is this point?" Approaches: statistical (z-scores, robust thresholds, seasonal baselines for time series); distance/density (distance to k-th neighbour, Local Outlier Factor, low GMM density); reconstruction (large PCA or autoencoder reconstruction error); and isolation.

Isolation forest intuition. Anomalies are few and different, so they are easy to isolate. Build random trees by repeatedly picking a random feature and a random split value between its min and max until each point sits alone. A normal point deep inside a dense region needs many random cuts to be isolated; an anomaly far from the rest is often isolated in a few cuts. Average the path length over many random trees: short average path means anomalous. Example: on a 1-D dataset of 99 values in [0, 1] and one value at 50, a random threshold between 0 and 50 lands above 1 with probability 98%, isolating the outlier in a single cut.

The anomaly score normalises the average path length E[h(x)] by c(n), the average path length of an unsuccessful search in a binary search tree of n points:

\[ s(x, n) = 2^{-\frac{\mathbb{E}[h(x)]}{c(n)}},\qquad c(n) = 2H(n-1) - \frac{2(n-1)}{n},\quad H(i)\approx\ln i + 0.5772. \]

Scores near 1 are anomalies, well below 0.5 normal, around 0.5 everywhere means no distinct anomalies. Isolation forests use small subsamples per tree (256 by default), which makes them fast (linear in m), memory-light, and resistant to "masking" by clusters of anomalies. Limitations: axis-parallel cuts struggle with anomalies defined by correlations between features (Extended Isolation Forest addresses this), and the contamination parameter only sets the threshold; it does not make the model smarter.

Without labels, anomaly detectors are judged by the alerts they produce. Treat them as ranking systems: the top of the ranking must be dense with real issues, which you measure with precision at k on investigated alerts.

4. Internal Working

4.1 Lloyd's algorithm, step by step

  1. Seed k centroids with k-means++.
  2. Assign: compute the m × k matrix of squared distances. Using ‖x − μ‖² = ‖x‖² − 2xᵀμ + ‖μ‖², the dominant cost is the matrix product XMᵀ, so this step runs at BLAS speed: O(mkn) per iteration.
  3. Update: each centroid becomes the mean of its assigned points, O(mn).
  4. Check: stop when assignments do not change or centroid movement falls below a tolerance; handle empty clusters by re-seeding them (for example at the point farthest from its centroid).
  5. Restart n_init times with different seeds and keep the lowest-inertia result.

Accelerations: Elkan's algorithm uses the triangle inequality to skip distance computations whose result cannot change the assignment; mini-batch k-means updates centroids from small random batches with a per-centroid learning rate (a stochastic-gradient version), scaling to data that does not fit in memory at a small cost in quality.

4.2 DBSCAN's region queries

DBSCAN's cost is dominated by ε-neighbourhood queries. With a spatial index (KD-tree or ball tree) in low dimensions, average cost approaches O(m log m); in high dimensions or with large ε, it degrades towards O(m²), and memory for neighbourhood lists can explode. The algorithm itself is a graph traversal: pick an unvisited core point, BFS through ε-neighbours that are core, attach border points, mark the rest as noise. Practitioners on large data often use HDBSCAN or approximate neighbour graphs instead.

4.3 How EM is kept numerically sane

Gaussian densities in many dimensions underflow, so implementations compute log-densities and normalise responsibilities with log-sum-exp (Chapter 6.1). Covariance matrices can become singular when a component collapses onto a few points (likelihood goes to infinity), so a small value is added to the diagonal (reg_covar). Covariance structure can be restricted (covariance_type: full, tied, diag, spherical) to trade flexibility for stability and parameter count.

4.4 PCA in scikit-learn

PCA centres X and dispatches to a solver: full LAPACK SVD for small matrices, randomised SVD (a few passes of X times random matrices, then a small exact SVD) when the requested number of components is much smaller than the dimensions, or ARPACK. IncrementalPCA processes mini-batches for out-of-core data; TruncatedSVD skips centring so it works on sparse matrices (on TF-IDF this is latent semantic analysis). Signs of components are arbitrary (v and −v are equally valid), which matters if you compare components across retrains: scikit-learn applies a deterministic sign convention, but different libraries may disagree.

4.5 Isolation forest construction

  1. For each of t trees (default 100): draw a subsample of ψ points (default 256) without replacement.
  2. Recursively split: pick a random feature and a uniform random threshold between the node's min and max on that feature; stop when a node has one point or reaches depth ⌈log₂ ψ⌉ (deep paths are not needed: only short ones signal anomalies).
  3. Scoring: for x, compute its path length in each tree (adding c(size) at a truncated leaf to estimate the remaining depth), average, and convert to s(x, ψ).

5. Architecture: Algorithms, Flows and a Live Demo

What to try: step through one iteration at a time and watch the two phases alternate: points recolour (assignment), then centroids jump to the mean of their colour (update). Re-run with different random initialisations and notice when two centroids start in the same blob: the result is a poor local minimum where one true cluster is split and two others are merged. Increase k beyond the visible number of blobs and observe that k-means happily splits natural groups (inertia always falls with k). If the widget lets you place points, draw a ring or two crescents: k-means cuts them with straight boundaries, which is the motivation for DBSCAN.

Reading the diagram: the loop alternates between optimising the assignments with centroids fixed and optimising centroids with assignments fixed, each step lowering the same objective, like coordinate descent. The outer "n_init" restart is how we hedge against bad local minima, the clustering equivalent of retrying with backoff from different starting states.

Reading the diagram: information flows from the current model to per-point beliefs (E-step) and from those beliefs back to the model (M-step). Compared with Figure 6.4.2, "assign" became "compute probabilities" and "mean" became "weighted mean and covariance". The output is richer: a density usable for anomaly scoring and a likelihood for model selection with BIC.

Reading the diagram: representation comes first (featurisation and optional reduction), then the algorithm is chosen by goal. The anomaly branch has a feedback arrow: analyst verdicts on alerts become labels, and once enough accumulate, a supervised model can replace or complement the unsupervised detector. That transition is the usual maturity path for fraud and security detection.

6. The Math

6.1 The mean minimises squared distance (why the k-means update is optimal)

In words: the single point closest, in total squared distance, to a set of points is their average.

For points x₁…xn, f(μ) = Σ‖xi − μ‖². Gradient: −2Σ(xi − μ) = 0 ⇒ μ = (1/n)Σxi. f is convex (Hessian 2nI), so this is the global minimum. Numeric: for {1, 2, 6}, f(3) = 4 + 1 + 9 = 14 at the mean, f(2) = 1 + 0 + 16 = 17 at the median. (For absolute distance the median would be optimal: that variant is k-medians, more robust to outliers.)

6.2 K-means is NP-hard, so local search is the norm

Finding the global optimum of the k-means objective is NP-hard in general (even for k = 2 in high dimensions). Lloyd's algorithm is a local search that converges in practice in tens of iterations; k-means++ seeding gives an expected O(log k) approximation of the optimum before any iterations. This justifies multiple restarts.

6.3 PCA maximises projected variance

In words: the variance of the data along a unit direction v is vᵀCv; the direction maximising it is C's top eigenvector, and the maximum variance is the top eigenvalue.

Maximise vᵀCv subject to vᵀv = 1. Lagrangian: vᵀCv − λ(vᵀv − 1). Gradient: 2Cv − 2λv = 0 ⇒ Cv = λv. So v must be an eigenvector, and the objective equals vᵀCv = λ; pick the largest. Subsequent components maximise variance subject to orthogonality with earlier ones, yielding the next eigenvectors. Equivalently, PCA minimises reconstruction error: the squared error of projecting onto the top k components equals the sum of the discarded eigenvalues (times m − 1).

\[ \mathbf{v}_1 = \arg\max_{\|\mathbf{v}\|=1}\mathbf{v}^\top C\mathbf{v},\qquad \frac{1}{m-1}\big\|X - XV_kV_k^\top\big\|_F^2 = \sum_{j>k}\lambda_j. \]

Worked 2-D example. Centred data (−1.5, −1.3), (−0.5, −0.6), (0.5, 0.6), (1.5, 1.3), from §3.8's points minus their means (2.5, 2.5). Covariance (dividing by 3): var(x) = (2.25 + 0.25 + 0.25 + 2.25)/3 = 1.667; var(y) = (1.69 + 0.36 + 0.36 + 1.69)/3 = 1.367; cov = (1.95 + 0.3 + 0.3 + 1.95)/3 = 1.5. C = [[1.667, 1.5], [1.5, 1.367]]. Eigenvalues: trace 3.033, determinant 1.667 × 1.367 − 2.25 = 0.028; λ = (3.033 ± √(9.20 − 0.111))/2 = (3.033 ± 3.015)/2 ⇒ 3.024 and 0.009. The first component explains 3.024/3.033 = 99.7% of the variance: the data are essentially one-dimensional.

6.4 GMM log-likelihood and the EM guarantee

\[ \log L(\theta) = \sum_{i=1}^{m}\log\sum_{k=1}^{K}\pi_k\,\mathcal{N}(\mathbf{x}_i\mid\boldsymbol\mu_k,\Sigma_k). \]

The log of a sum has no closed-form maximiser. EM introduces the responsibilities as a distribution q over the hidden component of each point and uses Jensen's inequality: log Σk qk(ak/qk) ≥ Σk qk log(ak/qk). The E-step sets q to the posterior, making the bound tight; the M-step maximises the bound, which has closed-form weighted-MLE solutions. Since the bound touches the likelihood at the current θ and is then increased, the likelihood cannot decrease. M-step formulas with Nk = Σi rik:

\[ \pi_k = \frac{N_k}{m},\quad \boldsymbol\mu_k = \frac{1}{N_k}\sum_i r_{ik}\mathbf{x}_i,\quad \Sigma_k = \frac{1}{N_k}\sum_i r_{ik}(\mathbf{x}_i-\boldsymbol\mu_k)(\mathbf{x}_i-\boldsymbol\mu_k)^\top. \]

6.5 t-SNE's objective

High-dimensional affinities: pj|i ∝ exp(−‖xi − xj‖²/2σi²), with σi found by binary search so that 2H(Pi) equals the perplexity; symmetrised pij = (pj|i + pi|j)/2m. Low-dimensional affinities use a Student-t with one degree of freedom: qij ∝ (1 + ‖yi − yj‖²)−1. Minimise

\[ C = D_{\mathrm{KL}}(P\,\|\,Q) = \sum_{i\neq j}p_{ij}\log\frac{p_{ij}}{q_{ij}}. \]

Because KL(P‖Q) heavily penalises small q where p is large (Chapter 6.1's asymmetry), t-SNE prioritises keeping true neighbours close, and cares little about placing non-neighbours accurately, which is exactly why global distances in the plot are unreliable.

6.6 Isolation forest path lengths

For n = 256, H(255) ≈ ln 255 + 0.5772 ≈ 6.119, so c(256) ≈ 2 × 6.119 − 2 × 255/256 ≈ 12.24 − 1.99 = 10.24. A point with average path length 3 scores 2−3/10.24 ≈ 0.816 (anomalous); one with average path 10.24 scores exactly 0.5; one with 14 scores ≈ 0.388.

7.1 K-means and k-means++ from scratch

import numpy as np
from sklearn.cluster import KMeans
from sklearn.datasets import make_blobs
from sklearn.metrics import adjusted_rand_score

def kmeans_pp_init(X, k, rng):
    centroids = [X[rng.integers(len(X))]]
    for _ in range(1, k):
        d2 = np.min(((X[:, None, :] - np.array(centroids)[None]) ** 2).sum(-1), axis=1)
        centroids.append(X[rng.choice(len(X), p=d2 / d2.sum())])   # P proportional to D(x)^2
    return np.array(centroids)

def kmeans(X, k, n_init=10, max_iter=300, tol=1e-6, seed=0):
    rng = np.random.default_rng(seed)
    best = (np.inf, None, None)
    for _ in range(n_init):
        C = kmeans_pp_init(X, k, rng)
        for _ in range(max_iter):
            # squared distances via the expansion |x|^2 - 2 x.c + |c|^2 (BLAS-friendly)
            d2 = (X ** 2).sum(1)[:, None] - 2 * X @ C.T + (C ** 2).sum(1)[None, :]
            labels = d2.argmin(axis=1)
            newC = np.array([X[labels == j].mean(0) if np.any(labels == j) else X[rng.integers(len(X))]
                             for j in range(k)])
            shift = np.abs(newC - C).max()
            C = newC
            if shift < tol:
                break
        inertia = d2[np.arange(len(X)), labels].sum()
        if inertia < best[0]:
            best = (inertia, C, labels)
    return best

X, y_true = make_blobs(n_samples=1500, centers=4, cluster_std=[1.0, 1.5, 0.5, 1.2], random_state=7)
inertia, C, labels = kmeans(X, 4)
sk = KMeans(n_clusters=4, n_init=10, random_state=0).fit(X)
print("scratch inertia %.1f  sklearn inertia %.1f" % (inertia, sk.inertia_))     # nearly equal
print("ARI vs truth: scratch %.3f  sklearn %.3f" % (adjusted_rand_score(y_true, labels),
                                                     adjusted_rand_score(y_true, sk.labels_)))

7.4 PCA from scratch via SVD, and explained variance on real data

import numpy as np
from sklearn.datasets import load_breast_cancer, load_digits
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

def pca_svd(X, k):
    mu = X.mean(axis=0)
    Xc = X - mu                                   # centring is mandatory
    U, S, Vt = np.linalg.svd(Xc, full_matrices=False)
    components = Vt[:k]                           # principal directions (rows)
    scores = Xc @ components.T                    # == U[:, :k] * S[:k]
    var = S ** 2 / (len(X) - 1)
    return components, scores, var[:k] / var.sum(), mu

X = StandardScaler().fit_transform(load_breast_cancer().data)   # 30 features with different units
comp, scores, ratio, mu = pca_svd(X, 5)
sk = PCA(n_components=5).fit(X)
print("explained ratio scratch:", ratio.round(3))
print("explained ratio sklearn:", sk.explained_variance_ratio_.round(3))   # same (Illustrative ~[0.44 0.19 0.09 0.07 0.05])
print("abs-equal components:", np.allclose(np.abs(comp), np.abs(sk.components_), atol=1e-6))  # signs may differ

# How many components for 95% of variance on the digits images?
digits = load_digits().data                       # 64 pixel features, same units: no scaling
p = PCA(n_components=0.95, svd_solver="full").fit(digits)
print("components for 95% variance:", p.n_components_)          # ~29 (Illustrative)
recon = p.inverse_transform(p.transform(digits))
print("relative reconstruction error:", np.linalg.norm(digits - recon) / np.linalg.norm(digits))

# Reconstruction error as an anomaly score
p5 = PCA(n_components=10).fit(digits)
err = ((digits - p5.inverse_transform(p5.transform(digits))) ** 2).sum(1)
print("most unusual digit indices:", np.argsort(-err)[:5])

7.6 Log anomaly detection with an isolation forest

A compact version of a real pattern: parse log lines into templates (here with a deliberately simple regex masker; production systems use a parser such as Drain), count templates per service per minute, and score each minute's count vector. The data are synthetic, generated with a fixed seed, so the example is self-contained.

import re
from collections import Counter
import numpy as np
import pandas as pd
from sklearn.ensemble import IsolationForest
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(42)
normal_templates = ["GET /api/orders/<ID> 200 in <NUM>ms",
                    "Cache hit for key <ID>",
                    "Published event OrderCreated <ID>",
                    "DB pool active=<NUM> idle=<NUM>"]
rare_templates = ["Timeout calling payment-service after <NUM>ms",
                  "Circuit breaker OPEN for payment-service"]

def mask(line: str) -> str:
    line = re.sub(r"\b[0-9a-f]{8}-[0-9a-f-]{27}\b", "<ID>", line)   # UUIDs
    line = re.sub(r"\b\d+\b", "<NUM>", line)                       # numbers
    return line

def synth_minute(anomalous: bool):
    lines = []
    for t, rate in zip(normal_templates, [120, 80, 40, 10]):
        lines += [t.replace("<ID>", "3f2a9c1e-1111-2222-3333-444455556666").replace("<NUM>", str(rng.integers(1, 500)))] * rng.poisson(rate)
    if anomalous:
        lines += [rare_templates[0].replace("<NUM>", "3000")] * rng.poisson(60)
        lines += [rare_templates[1]] * rng.poisson(5)
    return Counter(mask(l) for l in lines)

minutes = [synth_minute(anomalous=(i in {700, 701, 702, 1200})) for i in range(1440)]
df = pd.DataFrame(minutes).fillna(0)
features = np.log1p(df.to_numpy())                                # counts are skewed: log
features = StandardScaler().fit_transform(features)

iso = IsolationForest(n_estimators=200, max_samples=256, contamination="auto", random_state=0)
iso.fit(features)
score = -iso.score_samples(features)                              # higher = more anomalous
top = np.argsort(-score)[:6]
print("top anomalous minutes:", sorted(top.tolist()))             # includes 700-702 and 1200 (Illustrative)
print(df.columns.tolist())

import numpy as np
import pandas as pd
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(1)
n = 5000
# Synthetic RFM table (recency days, frequency orders/yr, monetary spend/yr) with 4 latent groups
groups = rng.choice(4, size=n, p=[0.45, 0.25, 0.2, 0.1])
rec = np.select([groups == 0, groups == 1, groups == 2, groups == 3],
                [rng.gamma(2, 60, n), rng.gamma(2, 10, n), rng.gamma(2, 150, n), rng.gamma(2, 5, n)])
freq = np.select([groups == 0, groups == 1, groups == 2, groups == 3],
                 [rng.poisson(3, n), rng.poisson(12, n), rng.poisson(1, n), rng.poisson(40, n)]) + 1
mon = freq * np.exp(rng.normal(np.log(np.array([40, 60, 30, 90])[groups]), 0.4))
rfm = pd.DataFrame({"recency": rec, "frequency": freq, "monetary": mon})

pipe = make_pipeline(FunctionTransformer(np.log1p), StandardScaler(),
                     KMeans(n_clusters=4, n_init=20, random_state=0))
labels = pipe.fit_predict(rfm)
Z = pipe[:-1].transform(rfm)
print("silhouette:", round(silhouette_score(Z, labels, sample_size=2000, random_state=0), 3))

profile = rfm.assign(segment=labels).groupby("segment").agg(
    customers=("recency", "size"), recency=("recency", "median"),
    frequency=("frequency", "median"), monetary=("monetary", "median")).round(1)
print(profile)
# Name segments from the profile (e.g. "champions", "at risk", "new/occasional", "dormant")
# and export centroids so a Java service can assign new customers:
centroids = pipe[-1].cluster_centers_          # in scaled log space
scaler = pipe[1]
pd.DataFrame(centroids, columns=rfm.columns).to_json("segment_centroids.json", orient="records")

7.8 Assigning segments in Java

package com.example.segments;

import org.springframework.stereotype.Component;

/** Nearest-centroid assignment using parameters exported from the Python pipeline. */
@Component
public class SegmentAssigner {
    // Loaded from a versioned config/artifact in real code; inlined here for clarity.
    private final double[] mean;      // StandardScaler.mean_ (of log1p features)
    private final double[] scale;     // StandardScaler.scale_
    private final double[][] centroids;

    public SegmentAssigner(double[] mean, double[] scale, double[][] centroids) {
        this.mean = mean; this.scale = scale; this.centroids = centroids;
    }

    public int assign(double recency, double frequency, double monetary) {
        double[] raw = {recency, frequency, monetary};
        double[] z = new double[raw.length];
        for (int i = 0; i < raw.length; i++) {
            z[i] = (Math.log1p(raw[i]) - mean[i]) / scale[i];   // identical transform to training
        }
        int best = -1;
        double bestD = Double.MAX_VALUE;
        for (int c = 0; c < centroids.length; c++) {
            double d = 0;
            for (int i = 0; i < z.length; i++) {
                double diff = z[i] - centroids[c][i];
                d += diff * diff;
            }
            if (d < bestD) { bestD = d; best = c; }
        }
        return best;
    }
}

This is one of the rare cases where reimplementing the transform in Java is reasonable: it is three lines of arithmetic. Still add a parity test against the Python pipeline's predict on a fixture.

8. Applications

8.1 Customer segmentation

Cluster customers on behavioural features (recency, frequency, monetary value, category mix, channel usage), name the segments from their centroids, and use them for targeting, pricing experiments or as features for supervised models. Recompute periodically and track migration between segments; sudden mass migration usually signals a data or definition change, not a behavioural revolution.

8.2 Log and metric anomaly detection

Log lines are parsed into templates (constant text with variable fields masked), turning unstructured text into counts per template per time window; new templates are themselves a strong signal. Metric vectors (latency, error rate, saturation across services) are scored with isolation forests, PCA reconstruction error, or seasonal baselines. The hard part is operational: suppressing duplicates, routing to owners, and learning from feedback.

8.3 Embedding visualisation and debugging

Projecting model embeddings (search queries, product vectors, support-ticket embeddings) to 2-D with UMAP lets you see whether semantically similar items cluster, find mislabelled examples (a point surrounded by another class), and discover topics. Clustering embeddings with HDBSCAN groups support tickets into emerging issues without predefined categories.

8.4 Compression and preprocessing

PCA reduces embedding dimensions (768 → 128) to cut vector-index memory and latency with measurable recall loss, decorrelates features before linear models, and compresses dashboards of hundreds of correlated metrics into a few health indicators.

8.5 Deduplication and catalogue cleanup

Cluster product listings or documents by embedding similarity (or MinHash on shingles) to find near-duplicates; within each cluster, choose a canonical record. This is "group by" for messy data.

12. Common Mistakes

  • Clustering unscaled features. The largest-unit feature defines the clusters.
  • Treating clusters as ground truth. Algorithms always return clusters, even on uniform noise. Check stability and compare against a null (shuffled features).
  • Choosing k by inertia alone. Inertia always decreases with k.
  • Forgetting to centre for PCA (when implementing manually), or standardising when raw variance is meaningful.
  • Using t-SNE coordinates as model features or interpreting inter-cluster distances on t-SNE plots.
  • Unstable segment IDs. Cluster 3 this week is not cluster 3 next week; downstream systems keyed on IDs break. Map new clusters to old by centroid similarity.
  • Running DBSCAN with default ε on data of a different scale; everything becomes noise or one cluster.
  • Setting contamination as if it were knowledge. It only sets a score threshold; the ranking is unchanged.
  • Fitting PCA on all data before a train/test split for a downstream supervised model: a (mild) leakage, same rule as any transformer.
  • Euclidean k-means on embeddings that should use cosine. Normalise vectors to unit length first; then squared Euclidean distance is 2 − 2 cos, and k-means behaves like spherical k-means.

13. Production Concerns

13.1 Serving

Export centroids, scaler parameters and PCA components as data (JSON, Parquet, or ONNX). Nearest-centroid assignment and PCA projection are a few lines in any language and run in microseconds. For DBSCAN/HDBSCAN, there is no native predict for new points in scikit-learn's DBSCAN; either re-cluster in batch or assign new points to the cluster of their nearest core sample (HDBSCAN libraries offer approximate prediction).

13.2 Drift and recomputation

Monitor the distribution of assignments (fraction per segment), mean distance to assigned centroid (rising means the world has moved away from the centroids), and anomaly score distributions. Recompute on schedule with alignment to previous IDs, and version segment definitions like any API.

13.3 Alerting quality

For anomaly detection, track alert volume, precision on reviewed alerts, time-to-acknowledge, and duplicates. Deduplicate and group correlated anomalies before paging; suppress during known events (deploys, sales). An anomaly detector that pages too often is worse than none: it trains people to ignore alerts.

13.4 Privacy and fairness

Segments can encode protected attributes through proxies, and segment-based treatment (pricing, credit offers) can become discriminatory. Review features and outcomes per segment. Embedding plots of user data are personal data: restrict access.

13.5 Scale

Mini-batch k-means, IncrementalPCA and subsampled isolation forests scale to large data on one node; Spark MLlib provides distributed k-means, bisecting k-means, GMM and PCA. For embedding clustering at scale, cluster on a sample and assign the rest by nearest centroid or approximate nearest neighbour.

14. Exercises

Exercise 1 · Foundational

Run k-means by hand on 1-D points {2, 4, 5, 10, 12, 13} with k = 2 and initial centroids 2 and 4. Show each iteration and the final inertia.

Solution

Iteration 1: assign 2 → c₁ (2); 4, 5, 10, 12, 13 → c₂ (4) (note 10 is 6 from 4, 8 from 2). Update: c₁ = 2, c₂ = (4 + 5 + 10 + 12 + 13)/5 = 8.8. Iteration 2: 2 → c₁; 4 (2 vs 4.8) → c₁; 5 (3 vs 3.8) → c₁; 10, 12, 13 → c₂. Update: c₁ = 11/3 ≈ 3.667, c₂ = 35/3 ≈ 11.667. Iteration 3: assignments unchanged. Inertia = (1.667² + 0.333² + 1.333²) + (1.667² + 0.333² + 1.333²) = 2 × (2.778 + 0.111 + 1.778) = 2 × 4.667 = 9.333.

Exercise 2 · Foundational

A point has average distance 3 to members of its own cluster, and average distances 7 and 4 to the members of two other clusters. Compute its silhouette. What if its own-cluster average were 5?

Solution

b = min(7, 4) = 4 (the nearest other cluster). s = (4 − 3)/max(3, 4) = 0.25: weakly placed. With a = 5: s = (4 − 5)/5 = −0.2: it would fit better in the third cluster.

Exercise 3 · Intermediate

Covariance eigenvalues of a 10-feature standardised dataset are [5.2, 2.1, 1.0, 0.8, 0.5, 0.2, 0.1, 0.1, 0.0, 0.0]. (a) Explained variance ratio of each of the first three. (b) Smallest k for ≥ 90% cumulative. (c) Reconstruction MSE per point (summed over features) when keeping k = 3, assuming m − 1 normalisation.

Solution

Total = 10.0, as expected for 10 standardised features (the trace of a correlation matrix equals the number of features). (a) 0.52, 0.21, 0.10. (b) Cumulative: 0.52, 0.73, 0.83, 0.91 → k = 4. (c) The sum of discarded eigenvalues: 0.8 + 0.5 + 0.2 + 0.1 + 0.1 + 0 + 0 = 1.7 per point on average (squared error summed over features, with the m − 1 convention).

Exercise 4 · Intermediate

A 1-D GMM has π = (0.7, 0.3), μ = (0, 3), σ = (1, 1). Compute the responsibilities for x = 1.5 and x = 2.5.

Solution

Unnormalised (dropping the shared 1/√(2π)): x = 1.5: 0.7 e−1.125 = 0.7 × 0.3247 = 0.2273; 0.3 e−1.125 = 0.0974. Responsibilities 0.7 and 0.3: at the midpoint, the likelihoods tie and the prior decides. x = 2.5: 0.7 e−3.125 = 0.7 × 0.0439 = 0.0308; 0.3 e−0.125 = 0.3 × 0.8825 = 0.2648. r₁ = 0.0308/0.2956 ≈ 0.104, r₂ ≈ 0.896.

Exercise 5 · Advanced

Prove that for unit-normalised vectors, k-means with squared Euclidean distance assigns points to the centroid with the highest cosine similarity when centroids are also normalised, and explain how to implement spherical k-means with scikit-learn.

Solution

For ‖x‖ = ‖c‖ = 1: ‖x − c‖² = ‖x‖² − 2xᵀc + ‖c‖² = 2 − 2cos(x, c). Minimising distance is maximising cosine. Standard k-means centroids (means) are not unit-norm, so assignments differ slightly; spherical k-means renormalises centroids after each update. With scikit-learn, normalise X with Normalizer() and run KMeans (approximately spherical); for exact spherical k-means, implement the loop with a centroid renormalisation step, or normalise the fitted centroids and reassign by maximum dot product at serving time.

Exercise 6 · Advanced (design)

Design an anomaly detector for checkout latency across 300 microservices that pages at most 5 times per day. Specify features, algorithm, thresholding, suppression and how you will evaluate it without labels.

Solution

Features per service per minute: p50/p99 latency, error rate, request rate, each as a ratio to the same minute-of-week seasonal baseline (log ratio), plus deploy-in-last-15-min flag. Algorithm: per-service robust z-scores for univariate spikes, plus an isolation forest on the cross-service vector to catch correlated incidents. Thresholding: rank minutes by combined score; set the threshold so the backtest over the past 60 days yields about 5 incidents per day after grouping; require persistence (3 of 5 minutes). Suppression: group anomalies within 10 minutes and sharing dependencies into one incident; suppress during planned maintenance. Evaluation: backtest against past incident tickets (recall of known incidents), have on-call rate each page (precision), track time-to-detect versus existing alerts, and review monthly.

15. Interview Questions

Conceptual What does k-means optimise and why is it guaranteed to converge?

It minimises within-cluster sum of squared distances. The assignment step chooses each point's nearest centroid (cannot increase the objective) and the update step sets centroids to means (the minimiser of squared distance for fixed assignments). The objective is non-increasing and bounded below with finitely many partitions, so it converges, but only to a local minimum, hence k-means++ and multiple restarts.

Conceptual When would you choose DBSCAN/HDBSCAN over k-means?

When clusters are non-convex or of varying shapes, when the number of clusters is unknown, and when there is noise that should not be forced into clusters (geospatial traces, embedding topics, fraud rings). Choose k-means for compact, comparably sized clusters, when every point must be assigned, or when you need a cheap, servable model.

Conceptual How is PCA related to SVD, and how do you choose the number of components?

For centred X = UΣVᵀ, principal directions are V's columns, scores are UΣ, and component variances σ²/(m − 1). Choose k from a scree plot or a cumulative explained-variance target, but best by downstream performance (model metric or retrieval recall) versus cost.

Conceptual Explain EM for Gaussian mixtures and its relation to k-means.

E-step computes posterior responsibilities of each component for each point by Bayes' rule; M-step re-estimates weights, means and covariances as responsibility-weighted MLEs. Each iteration does not decrease likelihood. K-means is the hard-assignment limit with equal spherical covariances shrinking to zero.

Scenario A stakeholder shows a t-SNE plot with two distant clusters and concludes the two customer groups are "very different". How do you respond?

Explain that t-SNE preserves local neighbourhoods but not global distances or cluster sizes; separation can be exaggerated and depends on perplexity and seed. Validate with quantitative comparisons in the original space (feature distributions, distances, a classifier's ability to separate the groups), check stability across perplexities, and compare with PCA.

Scenario Your isolation-forest alerts page on-call 40 times a day, mostly false positives. What do you change?

Lower the alert rate by thresholding on rank to match capacity; add persistence requirements; deseasonalise features (ratios to time-of-week baselines) so normal peaks are not anomalous; suppress during deploys and known events; group correlated anomalies into incidents; collect feedback and evaluate precision@k; consider per-service models; eventually train a supervised classifier on labelled alerts.

Coding Write vectorised NumPy for the k-means assignment step.
def assign(X, C):
    d2 = (X**2).sum(1)[:, None] - 2 * X @ C.T + (C**2).sum(1)[None, :]
    return d2.argmin(1)

Uses the norm expansion to turn the distance computation into one matrix multiplication; mention clipping tiny negative values due to floating point if distances are needed.

Architecture Design nightly customer segmentation consumed by several Spring services.

Batch job: extract behavioural features from the warehouse as of the run date, apply a versioned pipeline (log transform, scaling, k-means), align clusters to the previous run's IDs by centroid matching, validate (segment sizes, silhouette, stability, drift versus last run), and publish to a segment table keyed by customer with a definition version. Services read via a cache or feature store; new customers are assigned online by nearest centroid using exported parameters. Monitor assignment distributions and keep the previous version for rollback.

Conceptual Why do isolation forests use small subsamples per tree?

Anomalies are isolated near the root regardless of sample size, while small samples reduce swamping (normal points near anomalies looking anomalous) and masking (clusters of anomalies hiding each other), and make training linear and cheap. Depth is capped at about log₂ ψ because only short paths matter.

16. Knowledge Check

  • Unsupervised results depend on representation and objective; "similar" is a design choice.
  • K-means minimises within-cluster squared distance with alternating assign/update steps; k-means++ seeding and restarts mitigate local minima.
  • Choose k by silhouette, elbow, stability and business usefulness, not inertia alone.
  • Hierarchical clustering gives a dendrogram; DBSCAN/HDBSCAN find arbitrary shapes and noise; GMMs give soft assignments and densities via EM.
  • PCA = eigenvectors of the covariance = right singular vectors of centred data; explained variance guides dimension.
  • t-SNE and UMAP are for visualisation: trust neighbourhoods, not distances or sizes.
  • Isolation forests score anomalies by how quickly random cuts isolate a point; operational alert quality is the real metric.

Which algorithm can label points as noise rather than assigning them to a cluster?

  1. k-means
  2. Gaussian mixture
  3. DBSCAN
  4. Ward agglomerative clustering
DBSCAN (and HDBSCAN) label points outside dense regions as noise (−1); the others assign every point.

What does the k-means++ initialisation do?

  1. Chooses each new seed with probability proportional to squared distance from existing seeds
  2. Chooses k seeds uniformly at random
  3. Places seeds on a grid
  4. Runs PCA and uses the top k components
D(x)² sampling spreads seeds out, giving an O(log k) expected approximation before Lloyd iterations.

The first two principal components have eigenvalues 6 and 3 out of a total of 12. Cumulative explained variance?

  1. 50%
  2. 25%
  3. 90%
  4. 75%
(6 + 3)/12 = 0.75.

Which statement about t-SNE plots is correct?

  1. Distances between clusters reflect true distances.
  2. Local neighbourhoods are meaningful; global distances and cluster sizes generally are not.
  3. Results are independent of perplexity.
  4. t-SNE coordinates are good features for production models.
t-SNE's KL objective prioritises preserving neighbours; global geometry is distorted and parameter-dependent.

An isolation forest gives a point an anomaly score of about 0.85. What does that suggest?

  1. The point is very normal.
  2. The point is average.
  3. The point is isolated in few random splits: likely anomalous.
  4. The model has not converged.
Scores near 1 correspond to short average path lengths; around 0.5 is typical; well below 0.5 is normal.

Why must features usually be standardised before k-means?

  1. Euclidean distance would otherwise be dominated by large-scale features.
  2. k-means requires Gaussian inputs.
  3. Standardisation makes k-means convex.
  4. It removes the need to choose k.
Distances weight features by their numeric ranges; scaling equalises influence.
