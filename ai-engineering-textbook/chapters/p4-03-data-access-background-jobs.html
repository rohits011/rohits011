SQLAlchemy, Database Integration, Celery & Task Queues

Persistence and asynchronous work are where Python services earn or lose their reliability. This chapter maps everything you know about JPA, Hibernate, Spring Data, Flyway and Spring's @Async/Kafka listeners onto SQLAlchemy 2.x, Alembic, Celery and its alternatives, then starts building docflow, a production-grade document-ingestion service for RAG pipelines that a Spring Boot estate can call.

  • You will be able to: explain SQLAlchemy's unit of work and identity map; manage session lifecycles in sync, async and worker contexts; eliminate N+1 queries with the right loading strategy; write safe Alembic migrations; design Celery tasks that are idempotent, retry correctly and survive worker crashes; choose between Celery, RQ, Dramatiq, arq and Temporal; and lay out a real service's persistence and job layers.

1. Introduction: The Persistence Context and the Job Queue, Python Edition

In Spring, @Transactional on a service method silently opens an EntityManager, binds it to the thread, flushes dirty entities on commit and closes everything afterwards. Background work is @Async on a thread pool, a @KafkaListener, or Spring Batch. You probably rarely think about the mechanics.

In Python you must think about them, because nothing is bound to the thread for you. SQLAlchemy has the same core ideas as Hibernate (a Session is a persistence context with a unit of work and an identity map), but its lifecycle is explicit: you create a session, use it inside a transaction block, and close it. In async code, the session cannot lazily load, so every relationship you touch must be loaded deliberately. Background jobs run in separate worker processes (Celery), so anything you pass to them is serialised, executed later, possibly more than once, on a different machine. Those three facts (explicit session, no implicit lazy I/O in async, at-least-once remote jobs) drive the design of every production Python data service.

For AI systems the stakes are concrete. A RAG ingestion pipeline receives documents, stores metadata, extracts text, chunks it, calls an embedding model and writes vectors. Each step can fail, take minutes and be expensive (embedding API costs). Getting idempotency, retries and transactional boundaries right is what separates a pipeline that silently double-bills your embedding provider from one that you can safely re-run.

Why that is not enough

Where Python and Go fit
Go favours thin data access (database/sql, pgx, sqlc) and explicit transactions; there is no mainstream Hibernate-style ORM culture. Python sits closer to Java: a powerful ORM is the default, with a SQL-expression layer (Core) beneath it for when you need control.

Use it when / avoid it when
Use the ORM for transactional domain logic with object graphs; use Core or raw SQL for bulk loads, analytics and hot paths. Use Celery for fire-and-forget or retryable background jobs; avoid it for multi-day workflows with human steps or complex compensation (use Temporal) and for simple in-request follow-ups (use BackgroundTasks).

3. Fundamentals

3.1 Two layers: Core and ORM

SQLAlchemy Core is a SQL expression language plus connection/transaction management: you build select(users.c.id).where(users.c.email == x) and execute it on a Connection, getting rows back. It is comparable to jOOQ or Spring's JdbcClient with a type-aware query builder. The ORM maps classes to tables and adds the Session, unit of work, identity map, relationships and loading strategies: comparable to Hibernate. In 2.x both share one select() construct; the ORM simply accepts entity classes in it.

3.2 Engine, connection pool and dialect

An Engine owns a connection pool (QueuePool by default: pool_size=5, max_overflow=10) and a dialect/driver pair (postgresql+psycopg, postgresql+asyncpg). It is a process-wide singleton, like a DataSource backed by HikariCP. Pools are per process: with 8 Gunicorn workers and pool_size=10 you hold up to 80 connections per pod (plus overflow). Key settings: pool_pre_ping=True (validate on checkout, like Hikari's connection test), pool_recycle (close connections older than N seconds, to beat idle-killing firewalls), pool_timeout.

3.3 The Session as persistence context

A Session is the equivalent of a JPA EntityManager: it holds an identity map (one Python object per primary key within the session, so loading the same row twice returns the same object) and tracks object states: transient (new, not added), pending (added, not flushed), persistent (in the identity map with a row), detached (session closed), deleted. At flush, the unit of work computes the minimal ordered set of INSERT/UPDATE/DELETE statements from the changes, topologically sorted by foreign-key dependencies.

3.4 Transactions and autobegin

In 2.x a session autobegins a transaction at first use and keeps it open until commit(), rollback() or close(). The idiomatic pattern is a context manager: with Session(engine) as s, s.begin(): ... commits on success and rolls back on exception, like a programmatic TransactionTemplate. There is no propagation model (REQUIRES_NEW etc.); you pass sessions explicitly or use nested savepoints with session.begin_nested().

3.5 Flush vs commit, and expire_on_commit

Flush sends pending SQL to the database inside the open transaction (autoflush happens before queries, like Hibernate's FlushMode.AUTO). Commit flushes and commits. After commit, by default every object is expired: the next attribute access reloads it from the database. That is safe in sync code but fatal in async code (the reload would be implicit I/O), which is why async sessions are created with expire_on_commit=False.

3.7 Async SQLAlchemy

create_async_engine and AsyncSession wrap the sync machinery using greenlets: the ORM code is still synchronous internally, and when it needs I/O it switches (via greenlet) to the event loop to await the async driver. Implicit I/O (lazy loads, expired attribute refresh) cannot be awaited from attribute access, so it raises MissingGreenlet. Rules: eager-load what you need; set expire_on_commit=False; use AsyncAttrs and await obj.awaitable_attrs.children for explicit lazy loads; never share an AsyncSession between concurrent tasks (a session is not concurrency-safe, just as an EntityManager is not thread-safe).

3.8 Alembic migrations

Alembic keeps an ordered graph of revision scripts (each with upgrade()/downgrade()) and records the current revision in an alembic_version table, like Flyway's flyway_schema_history. alembic revision --autogenerate diffs model metadata against the database to draft a migration (always review it: it misses renames, some constraint changes and data migrations). Revisions form a DAG with branch merging, useful when two feature branches each add a migration.

3.9 Background processing vocabulary

  • Broker: transports task messages (RabbitMQ, Redis, SQS). Equivalent to the JMS/AMQP broker.
  • Worker: a process that consumes messages and executes tasks, with a pool (prefork processes, threads, gevent greenlets, or solo).
  • Result backend: optional store for task state and return values (Redis, database). Often unnecessary; prefer writing results to your own tables.
  • Acknowledgement: early ack (on receipt; Celery default: at-most-once) vs late ack (after execution; at-least-once). Spring AMQP's default AUTO ack mode acknowledges after the listener returns, i.e. late.
  • Visibility timeout: for Redis and SQS brokers, how long an unacknowledged message stays invisible before being redelivered. Tasks longer than it get executed twice.
  • Idempotency: executing the same task twice produces the same effect as once. Mandatory with at-least-once delivery.
  • Prefetch: how many messages a worker reserves in advance (worker_prefetch_multiplier, default 4 per process), like Spring AMQP's prefetchCount.

3.10 The spectrum of background work

  1. In-process after response: FastAPI BackgroundTasks; lost on crash; for best-effort follow-ups (send a notification, warm a cache).
  2. Task queue: Celery, RQ, Dramatiq, arq; durable messages, retries, separate workers.
  3. Log-based streaming: Kafka consumers; replayable, ordered per partition; for event-driven integration with the Spring estate.
  4. Durable workflows: Temporal; persisted execution history, timers, signals, compensation; for long multi-step processes.

4. Internal Working

4.1 What happens on session.get() and session.execute(select(...))

  1. session.get(Document, id) first checks the identity map keyed by (Document, (id,), None). Hit: return the object without SQL (Hibernate's first-level cache does the same for find()).
  2. Miss or a query: the session autobegins a transaction, checks a connection out of the engine's pool, and (autoflush) flushes pending changes so the query sees them.
  3. The statement is compiled for the dialect. Compiled forms are cached in the engine's LRU compiled cache keyed by the statement's structure, so repeated queries skip compilation (SQLAlchemy's equivalent of a prepared-statement cache at the Python level).
  4. Rows come back; the ORM's loading machinery looks up each primary key in the identity map. Existing objects are returned as-is (their unflushed in-memory changes are not overwritten, unless populate_existing is requested); new ones are instantiated without calling __init__ and registered.
  5. Eager loaders run: joinedload data was in the same rows; selectinload issues a follow-up IN query, chunked (500 keys per batch by default).

4.2 Dirty checking and flush

SQLAlchemy instruments mapped attributes with descriptors. Setting doc.status = "READY" records the change in the object's InstanceState (old value history) immediately, so dirty checking at flush only examines objects that were actually modified: cheaper than Hibernate's default snapshot comparison of every managed entity (Hibernate's bytecode enhancement gives similar tracking). On flush the unit of work:

  1. Collects new, dirty and deleted objects.
  2. Builds a dependency graph between mappers (a Chunk row needs its Document row first) and topologically sorts it.
  3. Batches INSERTs per table using executemany and, on PostgreSQL, the "insertmanyvalues" feature (multi-row INSERT ... VALUES (...), (...) RETURNING id), which fetches server-generated keys in bulk. This avoids Hibernate's classic problem where IDENTITY generation disables batch inserts.
  4. Emits UPDATEs with only changed columns, optionally with a version column check (version_id_col, like @Version) raising StaleDataError on conflicts.
  5. Emits DELETEs in reverse dependency order, handling cascades configured on relationships.

4.3 The async bridge: greenlets

The ORM was not rewritten for async. Instead, AsyncSession.execute() runs the sync Session.execute() inside a greenlet via greenlet_spawn. When the sync code reaches the driver's cursor.execute(), SQLAlchemy's adapter for asyncpg/psycopg-async calls await_only(coro), which switches from the greenlet back to the parent coroutine, which awaits the real driver coroutine on the event loop, then switches back with the result. From outside it is ordinary await; inside, the ORM logic is unchanged. Attribute access that triggers a lazy load happens outside any greenlet context, so await_only cannot switch and raises MissingGreenlet. That error is your "LazyInitializationException", raised earlier and more predictably.

4.4 Connection pool mechanics per process

QueuePool holds idle connections in a LIFO queue (recently used connections first, which lets idle ones expire). Checkout: pop or create (if below pool_size + max_overflow), else wait up to pool_timeout then raise TimeoutError. On checkin, a rollback is issued ("reset on return") to clear transaction state. For async engines the pool is the same class with an async adaptation. After fork(), a child must not reuse the parent's connections (they share the same socket); call engine.dispose(close=False) in the child, which Celery and Gunicorn hooks make easy.

4.5 Celery's message lifecycle

  1. ingest_document.delay(doc_id) serialises a message (JSON by default since Celery 4; never enable pickle with untrusted brokers) with headers: task name, id (UUID), retries, ETA, root/parent IDs. Kombu publishes it to the broker exchange/queue (with Redis: an LPUSH to a list).
  2. A worker's consumer (in the main process) fetches up to prefetch_multiplier x concurrency messages. With Redis transport, fetched-but-unacked messages are tracked in an "unacked" sorted set with a timestamp; if not acked within visibility_timeout (default 1 hour), they are restored to the queue for redelivery.
  3. The main process dispatches the task to a pool child (prefork) via pipes.
  4. With default acks_late=False, the message is acknowledged when execution starts: if the child or machine dies mid-task, the task is lost (at-most-once). With acks_late=True, ack happens after completion (at-least-once); combined with task_reject_on_worker_lost=True, a killed child causes requeue.
  5. On exception, self.retry(exc=e, countdown=...) publishes a new message with incremented retry count and an ETA, then raises Retry so the current one is acked. autoretry_for with retry_backoff and retry_jitter automates exponential backoff.
  6. If a result backend is configured, state transitions (STARTED if tracked, SUCCESS, FAILURE, RETRY) are written there.

ETA tasks and visibility timeout

With Redis or SQS, a task scheduled with countdown/eta further in the future than visibility_timeout is held by the worker unacked; when the timeout expires it is redelivered to another worker, which also holds it. Result: duplicated executions. Keep ETAs short, raise visibility_timeout above your longest ETA plus task runtime, or use RabbitMQ (which redelivers only on connection loss), or schedule long delays elsewhere (database plus beat, or Temporal timers).

4.6 Prefork pool and process recycling

The prefork pool forks N children from the main worker process (CoW memory sharing; see Chapter 4.1). worker_max_tasks_per_child and worker_max_memory_per_child recycle children, which is the standard defence against fragmentation and leaky native libraries. Per-process resources (DB engines, HTTP clients, model weights) must be initialised in worker_process_init, never at import time in the parent if they hold sockets or threads.

4.7 Alembic upgrade internals

alembic upgrade head loads env.py, which configures an engine and target_metadata; reads the current revision from alembic_version; walks the revision DAG to head; and runs each script's upgrade() inside a transaction (PostgreSQL supports transactional DDL, so a failed migration rolls back cleanly; MySQL does not). Operations such as CREATE INDEX CONCURRENTLY cannot run in a transaction and need with op.get_context().autocommit_block():.

6. The Math: Pools, Queues and Retries

6.1 Connection budget

Total connections \( C = P \times W \times (s + o) \) for \( P \) pods, \( W \) worker processes per pod, pool size \( s \) and overflow \( o \). Ten pods, four workers, \( s=5, o=5 \): \( C = 400 \). Add Celery: 6 worker hosts with prefork concurrency 8 and a pool of 2 each: 96 more. PostgreSQL's per-connection memory (a backend process each) makes hundreds of mostly-idle connections expensive; PgBouncer in transaction mode multiplexes them onto a few dozen server connections (but disables session-level features such as server-side prepared statements unless configured; asyncpg's statement cache needs statement_cache_size=0 or PgBouncer 1.21+ prepared-statement support).

6.2 Worker count from Little's Law

If documents arrive at \( \lambda = 20 \) per second and extraction takes \( W = 1.5 \) s on average, you need \( L = \lambda W = 30 \) concurrent extraction slots. Extraction is CPU-bound (PDF parsing), so that means 30 processes, e.g. 4 hosts with 8 prefork children. Embedding is I/O-bound (an API call taking 400 ms per batch) and rate-limited by the provider; concurrency is \( \lambda_{batches} \times 0.4 \) and is better served by a thread or async pool than by processes.

6.3 Retry storms and backoff

With exponential backoff, attempt \( k \) waits \( b \cdot 2^{k} \) seconds, capped at \( m \): \( d_k = \min(m, b \cdot 2^{k}) \). Add full jitter, \( d_k \sim U(0, \min(m, b \cdot 2^k)) \), to avoid synchronized retries after an outage. If an upstream fails for \( T \) seconds and \( R \) tasks are in flight, without jitter all \( R \) retry at nearly the same instants, producing load spikes of \( R \) requests; with full jitter the expected arrival rate during recovery is spread roughly uniformly. Bound the total: with \( b=2, m=300 \), and 8 retries, the worst-case time to give up is \( \sum_k d_k \approx 2+4+\dots+256+300 \approx 810 \) s, which must stay below your visibility timeout plus task runtime if using Redis or SQS.

6.4 Probability of duplicate execution

With late acks, a duplicate occurs if the worker dies between finishing the side effect and acking. If that window is \( \delta \) and crashes occur at rate \( r \) per second per worker, the duplicate probability per task is roughly \( r\delta \): small but nonzero, and deploys (SIGKILL after a grace period) make \( r \) much larger than hardware failure rates. Design for duplicates rather than estimating them away.

joinedload on a collection multiplies parent rows (Cartesian growth with several collections, exactly as multiple JOIN FETCH bags do in Hibernate, which is why Hibernate throws MultipleBagFetchException). selectinload keeps row counts linear and is the default recommendation for collections. 7.3 Async session lifecycle patterns

import asyncio
from sqlalchemy import select, update
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from n_plus_one import Author, Base, Book   # reuse the models above

engine = create_async_engine("sqlite+aiosqlite://", echo=False)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)   # critical for async

async def main() -> None:
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)

    # Pattern 1: transaction block = TransactionTemplate.execute(...)
    async with SessionLocal() as s, s.begin():
        s.add(Author(name="Ada", books=[Book(title="Notes")]))

    # Pattern 2: read with eager loading, then use objects after the session closes
    async with SessionLocal() as s:
        from sqlalchemy.orm import selectinload
        authors = (await s.scalars(select(Author).options(selectinload(Author.books)))).all()
    print([(a.name, [b.title for b in a.books]) for a in authors])   # safe: already loaded

    # Pattern 3: forgetting eager loading -> explicit error instead of hidden query
    async with SessionLocal() as s:
        a = (await s.scalars(select(Author))).first()
        try:
            print(a.books)                       # implicit I/O is impossible in async
        except Exception as e:
            print(type(e).__name__)              # MissingGreenlet (may be wrapped in StatementError)

    # Pattern 4: bulk UPDATE without loading objects (Core-style, like @Modifying JPQL)
    async with SessionLocal() as s, s.begin():
        await s.execute(update(Book).where(Book.title.like("N%")).values(title="Notes v2"))

    # Pattern 5: concurrent work needs one session PER task (sessions are not task-safe)
    async def count_books() -> int:

"""add language column and index without locking the table

Revision ID: 0002
Revises: 0001
"""
import sqlalchemy as sa
from alembic import op

revision = "0002"
down_revision = "0001"

def upgrade() -> None:
    # 1. Nullable column first: no table rewrite, instant on PostgreSQL 11+
    op.add_column("documents", sa.Column("language", sa.String(8), nullable=True))
    # 2. Index concurrently: must run outside the migration transaction
    with op.get_context().autocommit_block():
        op.create_index("ix_documents_language", "documents", ["language"],
                        postgresql_concurrently=True, if_not_exists=True)
    # 3. Backfill and NOT NULL go in LATER releases (expand/contract), in batches,
    #    never in the same deploy that introduces the column.

def downgrade() -> None:
    with op.get_context().autocommit_block():
        op.drop_index("ix_documents_language", table_name="documents",
                      postgresql_concurrently=True, if_exists=True)
    op.drop_column("documents", "language")

This is exactly the expand/contract discipline you apply with Flyway: additive changes first, deploy code that tolerates both shapes, backfill, then tighten constraints. Run migrations as a Kubernetes Job or init step before rolling out the new version, never from every app replica at startup (concurrent migration attempts and slow startups).

        root.mkdir(parents=True, exist_ok=True)

        path = self.root / key
        await asyncio.to_thread(self._write, path, data)    # file I/O off the event loop

    @staticmethod
    def _write(path: Path, data: bytes) -> None:
        path.parent.mkdir(parents=True, exist_ok=True)
        tmp = path.with_suffix(".tmp")
        tmp.write_bytes(data)
        tmp.replace(path)                                    # atomic rename

    def get_sync(self, key: str) -> bytes:
        return (self.root / key).read_bytes()

import base64
import uuid
from datetime import datetime

from sqlalchemy import func, select, tuple_, update
from sqlalchemy.ext.asyncio import AsyncSession

from docflow.models import Chunk, DocStatus, Document, OutboxMessage

EXTRACT_TOPIC = "docflow.tasks.extract"

class DocumentRepository:
    """Async repository; the caller owns the transaction (like a Spring @Transactional service)."""

    def __init__(self, session: AsyncSession) -> None:
        self.s = session

    async def get(self, tenant_id: str, doc_id: uuid.UUID) -> Document | None:
        return await self.s.scalar(
            select(Document).where(Document.id == doc_id, Document.tenant_id == tenant_id))

    async def find_by_sha(self, tenant_id: str, sha: str) -> Document | None:
        return await self.s.scalar(
            select(Document).where(Document.tenant_id == tenant_id, Document.content_sha256 == sha))

    def add_with_extract_request(self, doc: Document) -> None:
        """Insert the document and its outbox message in the SAME transaction."""
        self.s.add(doc)
        self.s.add(OutboxMessage(topic=EXTRACT_TOPIC, key=str(doc.id),
                                 payload={"document_id": str(doc.id), "version": doc.version}))

    async def request_reprocess(self, doc: Document) -> None:
        await self.s.execute(
            update(Document).where(Document.id == doc.id)
            .values(version=Document.version + 1, status=DocStatus.RECEIVED, last_error=None))
        await self.s.refresh(doc)
        self.s.add(OutboxMessage(topic=EXTRACT_TOPIC, key=str(doc.id),
                                 payload={"document_id": str(doc.id), "version": doc.version}))

    async def page(self, tenant_id: str, limit: int, cursor: str | None) -> tuple[list[Document], str | None]:
        """Keyset pagination on (created_at, id): stable under concurrent inserts, O(log n)."""
        stmt = select(Document).where(Document.tenant_id == tenant_id)
        if cursor:
            ts_s, id_s = base64.urlsafe_b64decode(cursor.encode()).decode().split("|")
            ts, last_id = datetime.fromisoformat(ts_s), uuid.UUID(id_s)
            stmt = stmt.where(tuple_(Document.created_at, Document.id) < tuple_(ts, last_id))
        rows = list(await self.s.scalars(
            stmt.order_by(Document.created_at.desc(), Document.id.desc()).limit(limit + 1)))
        nxt = None
        if len(rows) > limit:
            last = rows[limit - 1]
            nxt = base64.urlsafe_b64encode(f"{last.created_at.isoformat()}|{last.id}".encode()).decode()
        return rows[:limit], nxt

    async def chunks(self, doc_id: uuid.UUID, limit: int, offset: int) -> list[Chunk]:
        return list(await self.s.scalars(
            select(Chunk).where(Chunk.document_id == doc_id)
            .order_by(Chunk.ordinal).limit(limit).offset(offset)))

    async def count_chunks(self, doc_id: uuid.UUID) -> int:
        return await self.s.scalar(select(func.count()).where(Chunk.document_id == doc_id)) or 0

Note tuple_(created_at, id) < tuple_(ts, last_id) (a plain Python tuple comparison would not work: Python would try to evaluate the column expressions as booleans): SQLAlchemy renders a SQL row-value comparison, which PostgreSQL can serve from a composite index. Keyset pagination is the scalable alternative to OFFSET, just as with Spring Data's ScrollPosition.keyset().

@router.post("", status_code=status.HTTP_202_ACCEPTED, response_model=DocumentOut,
             responses={200: {"model": DocumentOut, "description": "duplicate upload"}})
async def upload(file: UploadFile, tenant: TenantDep, session: SessionDep, repo: RepoDep,
                 blobs: BlobDep, settings: SettingsDep, response: Response) -> Document:
    ctype = (file.content_type or "").split(";")[0]
    if ctype not in ALLOWED_TYPES:
        raise HTTPException(status.HTTP_415_UNSUPPORTED_MEDIA_TYPE, f"unsupported type {ctype}")
    data = await file.read(settings.max_upload_bytes + 1)          # bounded read
    if len(data) > settings.max_upload_bytes:
        raise HTTPException(status.HTTP_413_CONTENT_TOO_LARGE, "file too large")
    sha = hashlib.sha256(data).hexdigest()

    async with session.begin():
        existing = await repo.find_by_sha(tenant, sha)
    if existing:                                                    # idempotent upload
        response.status_code = status.HTTP_200_OK
        return existing

    doc_id = uuid.uuid4()
    blob_key = f"{tenant}/{sha[:2]}/{sha}"
    await blobs.put(blob_key, data)                                 # content-addressed: safe to repeat
    # Column defaults (default=1) are applied at FLUSH time, so set values we read before flushing.
    doc = Document(id=doc_id, tenant_id=tenant, filename=file.filename or "upload",
                   content_type=ctype, size_bytes=len(data), blob_key=blob_key, content_sha256=sha,
                   version=1, status=DocStatus.RECEIVED, chunk_count=0)
    try:
        async with session.begin():
            repo.add_with_extract_request(doc)                      # row + outbox, one transaction
    except IntegrityError:                                          # concurrent identical upload won
        async with session.begin():
            winner = await repo.find_by_sha(tenant, sha)
        assert winner is not None
        response.status_code = status.HTTP_200_OK
        return winner
    response.headers["Location"] = f"/v1/documents/{doc.id}"
    return doc

import re
from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class TextChunk:
    ordinal: int
    content: str
    token_count: int

_WS = re.compile(r"\s+")

def chunk_text(text: str, max_tokens: int = 300, overlap: int = 50) -> list[TextChunk]:
    """Greedy word-window chunker with overlap.

    Words approximate tokens (roughly 0.75 words per token for English); swap in a real
    tokenizer (e.g. tiktoken or HF tokenizers) when chunk size must match a model limit exactly.
    """
    if overlap >= max_tokens:
        raise ValueError("overlap must be smaller than max_tokens")
    words = _WS.split(text.strip())
    if words == [""]:
        return []
    step = max_tokens - overlap
    chunks: list[TextChunk] = []
    for i, start in enumerate(range(0, len(words), step)):
        window = words[start : start + max_tokens]
        chunks.append(TextChunk(ordinal=i, content=" ".join(window), token_count=len(window)))
        if start + max_tokens >= len(words):
            break
    return chunks

class Embedder(Protocol):

class TransientEmbeddingError(Exception):
    """Retryable: 429/5xx/timeouts."""

class HttpEmbedder:
    """OpenAI-compatible /v1/embeddings client (works with many hosted and self-hosted servers)."""
    def __init__(self, url: str, api_key: str | None, model: str, dim: int, timeout: float = 30.0) -> None:
        headers = {"Authorization": f"Bearer {api_key}"} if api_key else {}
        self.client = httpx.Client(base_url=url, headers=headers, timeout=timeout)
        self.model, self.dim = model, dim

    def embed(self, texts: list[str]) -> list[list[float]]:
        try:
            r = self.client.post("/v1/embeddings",
                                 json={"model": self.model, "input": texts, "dimensions": self.dim})
        except httpx.TransportError as e:
            raise TransientEmbeddingError(str(e)) from e
        if r.status_code == 429 or r.status_code >= 500:
            raise TransientEmbeddingError(f"embedding API {r.status_code}")
        r.raise_for_status()                                  # 4xx: permanent, do not retry
        data = sorted(r.json()["data"], key=lambda d: d["index"])
        return [d["embedding"] for d in data]

class HashEmbedder:
    """Deterministic fake for dev/tests: same text -> same unit vector. Not semantic."""
    def __init__(self, dim: int) -> None:
        self.dim = dim
    def embed(self, texts: list[str]) -> list[list[float]]:
        out = []
        for t in texts:
            seed = hashlib.sha256(t.encode()).digest()
            raw = [((seed[i % 32] + i * 31) % 255) / 127.0 - 1.0 for i in range(self.dim)]
            norm = math.sqrt(sum(x * x for x in raw)) or 1.0
            out.append([x / norm for x in raw])
        return out

def _lock_doc(s: Session, doc_id: uuid.UUID) -> Document | None:
    # Row lock serialises duplicate deliveries of the same task (SKIP LOCKED is for queues;
    # here we WANT the duplicate to wait, then observe the finished state and no-op).
    return s.scalar(select(Document).where(Document.id == doc_id).with_for_update())

def _fail(doc_id: uuid.UUID, version: int, stage: str, err: str) -> None:
    with res.sessionmaker() as s, s.begin():
        s.execute(update(Document).where(Document.id == doc_id, Document.version == version)
                  .values(status=DocStatus.FAILED, last_error=err[:2000]))
        s.add(IngestJob(document_id=doc_id, document_version=version, stage=stage,
                        state="FAILED", last_error=err[:2000]))

@celery_app.task(bind=True, max_retries=5, autoretry_for=(OSError,),
                 retry_backoff=2, retry_backoff_max=120, retry_jitter=True)
def extract_document(self: Task, document_id: str, version: int) -> str:
    doc_id = uuid.UUID(document_id)
    with res.sessionmaker() as s, s.begin():
        doc = _lock_doc(s, doc_id)
        if doc is None or doc.version != version or doc.status != DocStatus.RECEIVED:
            return "skipped"                                  # idempotency: stale or already done
        blob_key, ctype = doc.blob_key, doc.content_type
    data = res.blob_store.get_sync(blob_key)                  # outside the transaction
    try:
        text = extract_text(data, ctype)
    except UnsupportedDocument as e:                          # permanent: no retry
        _fail(doc_id, version, "extract", f"unsupported: {e}")
        return "failed"
    pieces = chunk_text(text, settings.chunk_tokens, settings.chunk_overlap)
    with res.sessionmaker() as s, s.begin():
        doc = _lock_doc(s, doc_id)
        if doc is None or doc.version != version or doc.status != DocStatus.RECEIVED:
            return "skipped"                                  # lost a race with a duplicate
        s.execute(delete(Chunk).where(Chunk.document_id == doc_id))   # replace on reprocess
        s.add_all(Chunk(document_id=doc_id, ordinal=p.ordinal, content=p.content,
                        token_count=p.token_count) for p in pieces)
        doc.status, doc.chunk_count = DocStatus.EXTRACTED, len(pieces)
        s.add(IngestJob(document_id=doc_id, document_version=version, stage="extract",
                        state="DONE", attempts=self.request.retries + 1))
        s.add(OutboxMessage(topic=EMBED_TOPIC, key=document_id,
                            payload={"document_id": document_id, "version": version}))
    return "extracted"

@celery_app.task(bind=True, max_retries=8, autoretry_for=(TransientEmbeddingError, OSError),
                 retry_backoff=5, retry_backoff_max=600, retry_jitter=True, rate_limit="30/m")
def embed_document(self: Task, document_id: str, version: int) -> str:
    doc_id = uuid.UUID(document_id)
    with res.sessionmaker() as s, s.begin():
        doc = _lock_doc(s, doc_id)
        if doc is None or doc.version != version or doc.status != DocStatus.EXTRACTED:
            return "skipped"
        pending = s.execute(select(Chunk.id, Chunk.content)
                            .where(Chunk.document_id == doc_id, Chunk.embedding.is_(None))
                            .order_by(Chunk.ordinal)).all()
    # Embed in batches OUTSIDE any transaction; persist each batch so a retry resumes
    # where it stopped instead of paying for the same embeddings again.
    for i in range(0, len(pending), settings.embedding_batch):
        batch = pending[i : i + settings.embedding_batch]
        vectors = res.embedder.embed([c.content for c in batch])
        with res.sessionmaker() as s, s.begin():
            for (chunk_id, _), vec in zip(batch, vectors, strict=True):
                s.execute(update(Chunk).where(Chunk.id == chunk_id, Chunk.embedding.is_(None))
                          .values(embedding=vec))
    with res.sessionmaker() as s, s.begin():
        doc = _lock_doc(s, doc_id)
        if doc is None or doc.version != version or doc.status != DocStatus.EXTRACTED:
            return "skipped"
        doc.status = DocStatus.READY
        s.add(IngestJob(document_id=doc_id, document_version=version, stage="embed",
                        state="DONE", attempts=self.request.retries + 1))
        s.add(OutboxMessage(topic=INGESTED_TOPIC, key=document_id,
                            payload={"document_id": document_id, "tenant_id": doc.tenant_id,
                                     "version": version, "chunk_count": doc.chunk_count}))
    return "ready"

Three idempotency layers protect against at-least-once delivery: the (version, status) guard rejects stale or completed work; the row lock serialises concurrent duplicates; and per-batch persistence with embedding IS NULL guards makes the expensive step resumable, so a retry after a crash only pays for the embeddings that were not saved. This is the same reasoning you would apply to a Spring Kafka consumer that calls a paid API.

from datetime import UTC, datetime
from typing import Any

from sqlalchemy import select
from sqlalchemy.orm import Session, sessionmaker

from docflow.models import OutboxMessage

Publisher = Callable[[OutboxMessage], None]

def celery_publisher(msg: OutboxMessage) -> None:
    from docflow.worker.celery_app import celery_app
    task = {"docflow.tasks.extract": "docflow.worker.tasks.extract_document",
            "docflow.tasks.embed": "docflow.worker.tasks.embed_document"}[msg.topic]
    celery_app.send_task(task, kwargs=msg.payload)

def relay_once(sm: sessionmaker[Session], publishers: dict[str, Publisher], batch: int = 100) -> int:
    with sm() as s, s.begin():
        rows = s.scalars(select(OutboxMessage)
                         .where(OutboxMessage.published_at.is_(None))
                         .order_by(OutboxMessage.id).limit(batch)
                         .with_for_update(skip_locked=True)).all()   # several relays can run
        for msg in rows:
            publishers[msg.topic](msg)      # if this raises, the tx rolls back: retried next loop
            msg.published_at = datetime.now(UTC)
        return len(rows)
    # Crash after publish but before commit -> message republished: consumers must be idempotent.

def main() -> None:
    from docflow.db import make_sync_engine, make_sync_sessionmaker
    from docflow.settings import get_settings
    settings = get_settings()
    sm = make_sync_sessionmaker(make_sync_engine(settings.worker_database_url))
    publishers: dict[str, Publisher] = {"docflow.tasks.extract": celery_publisher,
                                        "docflow.tasks.embed": celery_publisher}
    if settings.kafka_bootstrap:
        from docflow.events.kafka import kafka_publisher           # Chapter 4.4
        publishers["document.ingested"] = kafka_publisher(settings.kafka_bootstrap)
    else:
        publishers["document.ingested"] = lambda m: log.info("event %s %s", m.topic, m.payload)
    stop = False
    def _stop(*_: Any) -> None:
        nonlocal stop
        stop = True
    signal.signal(signal.SIGTERM, _stop)
    while not stop:
        n = relay_once(sm, publishers)
        if n == 0:
            time.sleep(0.5)                 # PostgreSQL LISTEN/NOTIFY can replace polling

8. Applications

8.1 RAG ingestion and re-indexing

Exactly the docflow pattern: upload, extract, chunk, embed, index, with a version number so that changing the chunker or embedding model triggers a controlled re-embed of the corpus (bump versions in batches through the outbox, throttle the embed queue with rate_limit to respect provider quotas).

8.2 Model-serving side jobs

Batch inference, evaluation runs over datasets, nightly fine-tuning data exports: Celery or a workflow engine schedules them; results land in tables that dashboards and Spring services read.

8.3 Webhooks and third-party integrations

Inbound webhooks are acknowledged quickly by FastAPI (store raw payload plus outbox row) and processed by workers with retries; outbound webhooks are tasks with exponential backoff and a dead-letter state.

8.4 Analytics and reporting queries

SQLAlchemy Core or raw SQL (with text() and bound parameters) for aggregations, window functions and bulk COPY; the ORM is not used for reporting, the same way you would bypass JPA for reporting in Spring.

8.5 Long-running business processes

Customer onboarding with KYC checks, document review with human approval, multi-day agent workflows: these move from Celery chains to Temporal, which persists workflow state and handles timers of days or weeks without broker visibility hacks.

9. Case Studies

9.1 Instagram: queue the slow work from day one

Verified Instagram's 2011 engineering post "What Powers Instagram: Hundreds of Instances, Dozens of Technologies" described a Django web tier that pushed slow work, such as fanning out a newly shared photo to followers, onto a task queue (Gearman at the time) processed by separate worker machines. 9.2 Temporal's origin at Uber

Verified Temporal is a fork of Cadence, the workflow engine built at Uber; its founders Maxim Fateev and Samar Abbas previously worked on AWS Simple Workflow Service and Microsoft's Durable Task Framework respectively. Temporal publishes SDKs for Java, Go, Python and TypeScript, which makes it a natural cross-language choice for a Spring estate adding Python AI workers: a Java workflow can call Python activities on a dedicated task queue.

Verified Netflix's open-source Dispatch (FastAPI) uses SQLAlchemy with Alembic migrations and separates Pydantic API models from ORM models, a public, production-quality reference for the layering used in docflow.

9.4 The dual-write problem in the wild

Illustrative A typical failure: an API commits an order row, then publishes a Celery task; the broker is briefly unavailable; the request returns 500 even though the row exists, and the client retries, creating a duplicate. Or the publish succeeds but the commit fails, and a worker processes an order that does not exist. The outbox pattern (Debezium-style CDC or a polling relay as in docflow) removes this class of bug; it is the same pattern Spring teams implement with Spring Modulith's event publication registry or Debezium.

12. Common Mistakes and Production Failures

  1. N+1 queries from default lazy loading in sync code. Fix with lazy="raise" conventions and explicit loader options.
  2. MissingGreenlet in async code from touching unloaded or expired attributes, often after commit with expire_on_commit=True.
  3. Sharing a session across tasks or threads (a global session object). Sessions are not thread- or task-safe, like EntityManager.
  4. Holding transactions open across slow I/O (calling an LLM inside session.begin()), pinning pool connections and holding row locks.
  5. Python-side defaults read before flush: mapped_column(default=1) is applied at INSERT time, so the attribute is None until flush (docflow hit this while being written; see the comment in routes.py).
  6. JSON None vs SQL NULL: SQLAlchemy's JSON type stores Python None as JSON null unless none_as_null=True, so IS NULL filters silently miss rows (also caught while testing docflow on SQLite).
  7. Autogenerated migrations applied unreviewed, dropping and recreating renamed columns (data loss) or locking big tables.
  8. Celery defaults assumed to be at-least-once: they are at-most-once (early ack). Enable acks_late and design idempotent tasks.
  9. Passing ORM objects to tasks: they are serialised (or fail to), go stale, and bypass tenancy checks. Pass IDs plus a version.
  10. Long ETAs on Redis/SQS brokers exceeding the visibility timeout, causing duplicate execution.
  11. Retrying permanent errors (bad input, 4xx) with the same backoff as transient ones, wasting capacity and money. Classify exceptions.
  12. Engines created before fork, sharing sockets across worker processes: random protocol errors. Create in worker_process_init.
  13. Unbounded queues: no back-pressure, so an upstream burst creates a backlog that takes hours to drain. Monitor queue depth and age; shed or throttle at the API.

13. Production Concerns

13.1 Database

  • Size pools per process and add them up (§6.1); consider PgBouncer; set statement_timeout and idle_in_transaction_session_timeout in PostgreSQL as a safety net.
  • Use echo=False in production, but enable slow-query logging in PostgreSQL and SQLAlchemy event hooks for query counts per request in tests (assert query budgets, as you might with Hibernate statistics).
  • Migrations: expand/contract, CONCURRENTLY indexes, lock timeouts (SET lock_timeout = '5s' in migrations), run as a separate job.
  • Read replicas: a second engine and an explicit get_read_session dependency; do not hide replica routing behind magic.

13.2 Workers

  • Separate queues per workload class (CPU-bound extract vs I/O-bound embed) with separately scaled deployments; autoscale on queue depth (KEDA has Redis and RabbitMQ scalers).
  • Graceful shutdown: Celery's warm shutdown on SIGTERM finishes current tasks; set Kubernetes terminationGracePeriodSeconds above your soft time limit, or rely on acks_late plus idempotency for tasks that get killed.
  • Monitoring: queue length and oldest-message age, task runtime histograms, retry and failure counts by exception type, worker restarts. Flower for ad-hoc inspection; Prometheus exporters for alerting.
  • Dead letters: after max retries, mark the business entity FAILED (as docflow does) and alert; provide a reprocess endpoint rather than poking the broker.

13.3 Security

  • JSON serialisation only; disable pickle. Authenticate to the broker (Redis ACLs/TLS, RabbitMQ users/vhosts).
  • Tenant isolation in every query (where tenant_id = ...), or PostgreSQL row-level security with a per-transaction SET LOCAL app.tenant_id.
  • Bound upload sizes, validate content types, and treat extracted text as untrusted (it will later be inserted into LLM prompts: a prompt-injection vector covered in Part 8).

13.4 Cost control for AI pipelines

Embedding calls are the expensive part. Deduplicate by content hash (docflow's unique constraint), persist progress per batch, rate-limit per provider, and record token counts per tenant for chargeback.

Selecting columns instead of entities bypasses the identity map entirely: cheaper, and the result is plain rows.

Exercise 2 · Intermediate

Add optimistic locking to Document so that two concurrent reprocess requests cannot both succeed silently, and map the conflict to HTTP 409.

Solution

Add __mapper_args__ = {"version_id_col": version}; then ORM UPDATEs include WHERE version = :old and increment it, raising StaleDataError when no row matches. Change request_reprocess to modify the loaded object (doc.status = RECEIVED) instead of a bulk update() (bulk statements bypass version checking), and register an exception handler mapping StaleDataError to 409. Note that docflow's version doubles as the pipeline generation number, which is convenient: tasks for older versions become no-ops.

Exercise 3 · Advanced

The embed queue processes 30 documents per minute but uploads arrive at 50 per minute during business hours. Propose a capacity and back-pressure plan.

Solution

Measure where the limit is: provider rate limit (tokens per minute), worker concurrency, or DB writes. If provider-bound, request a quota increase, batch larger (fewer requests per token), or add a second provider/region behind the Embedder protocol. If worker-bound, scale embed workers on queue depth (KEDA) and use a thread pool (I/O-bound). Back-pressure: expose queue age as a metric; when age exceeds an SLO, return 429 with Retry-After for bulk-upload tenants, or accept but mark as "queued" with an ETA. Over a day, 20 surplus documents per minute for 8 hours is a 9,600-document backlog, which must drain overnight at the same throughput: check that \( 30 \times 60 \times 16 \gt 9600 \).

Exercise 5 · Expert

Prove (informally) that docflow never embeds a chunk twice for the same document version, even with duplicated task deliveries and crashes at any point. Identify any remaining gap.

Solution

Each batch update is guarded by embedding IS NULL and executed after the embed call; a crash before commit loses the vectors (the call is repeated: a paid duplicate, the gap), while a crash after commit leaves them saved and a retry skips those chunks. Duplicated concurrent deliveries both read the pending list and may both call the provider for the same batch before either commits: also a paid duplicate, though storage stays correct thanks to the guard. Closing the gap requires claiming batches before calling the provider (e.g. a claimed_by/claimed_at column set with SELECT ... FOR UPDATE SKIP LOCKED) or serialising per document with the row lock held only for the claim. So: correctness is guaranteed; at-most-once spending is not, and the fix is a claim step.

15. Interview Questions

Conceptual Explain SQLAlchemy's identity map and unit of work in JPA terms.

The identity map is the persistence context's first-level cache: one object per primary key per session. The unit of work tracks new, dirty and deleted objects and flushes them as ordered SQL at flush/commit, like Hibernate's action queue. Differences: SQLAlchemy tracks changes via attribute instrumentation rather than snapshots, and session/transaction boundaries are explicit code rather than proxies.

Conceptual Why does async SQLAlchemy forbid lazy loading?

Lazy loading happens on attribute access, which is synchronous and cannot be awaited; the async bridge only works inside greenlet-wrapped calls. Rather than block the loop, SQLAlchemy raises. You must eager-load or use awaitable_attrs.

Conceptual What delivery guarantee does Celery give by default, and how do you get at-least-once?

At-most-once: messages are acked when execution starts. Set task_acks_late=True (and task_reject_on_worker_lost=True) for at-least-once, and make tasks idempotent. Exactly-once is an end-to-end property you build with idempotency keys and transactional state, not a broker setting.

Architecture Design reliable "save then process asynchronously" for an upload API.

Transactional outbox: insert entity and outbox row in one transaction; a relay publishes with FOR UPDATE SKIP LOCKED polling or CDC (Debezium), marks rows published; consumers are idempotent keyed by entity ID and version. Alternatives: CDC directly from the entity table, or Temporal with workflow IDs as idempotency keys.

Architecture How would you integrate Python workers into a Spring Boot system that already uses Kafka?

Use Kafka as the integration contract (schemas in a registry, Avro or Protobuf), Python consumers via confluent-kafka with manual commits after processing and idempotent handlers; keep Celery (if at all) as an internal implementation detail of the Python service. Chapter 4.4 details this.

Scenario Tasks are executed twice roughly an hour after being scheduled. Why?

Redis or SQS visibility timeout (default one hour in Celery's Redis transport) expiring for tasks with long ETAs or long runtimes, so the message is redelivered while the first worker still holds it. Raise the timeout, shorten ETAs, switch to RabbitMQ, and make tasks idempotent.

Scenario After moving to async SQLAlchemy, the DB shows hundreds of idle-in-transaction connections. Diagnose.

Sessions opened per request but transactions not closed promptly: handlers awaiting slow external calls inside session.begin(), or sessions never closed (no context manager). Fix scoping, set idle_in_transaction_session_timeout, and audit with pg_stat_activity.

Behavioral Describe a data migration you planned to avoid downtime.

Expand/contract story: additive schema, dual writes or backfill in batches with progress tracking, feature-flagged read switch, verification queries, then contract. Mention lock timeouts, rollback plan and communication with dependent teams.
