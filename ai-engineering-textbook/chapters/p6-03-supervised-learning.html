Supervised Learning: Regression, Classification, Trees & Boosting

Most ML in production at ordinary companies is supervised learning on tables: predict a number (delivery time, price, demand) or a label (fraud, churn, click) from features. This chapter builds the core algorithms from their mathematics, from linear models through decision trees to gradient-boosted ensembles like XGBoost and LightGBM, which still win most tabular problems. Each algorithm is implemented once from scratch so you know what the library is doing, then used properly through scikit-learn, XGBoost and LightGBM.

  • Prerequisites: Chapter 6.1 (gradients, MLE, norms, cross-entropy) and Chapter 6.2 (pipelines, encoding, splits).
  • You will be able to: derive and implement linear regression (normal equation and gradient descent), ridge/lasso/elastic net, logistic and softmax regression; explain k-NN and SVM margins; grow a decision tree with Gini/entropy and prune it; explain why random forests and gradient boosting work; derive XGBoost's split gain from its second-order objective; and choose between XGBoost, LightGBM and CatBoost for a given problem.

1. Introduction: Learning a Function from Examples

Supervised learning starts with pairs (x, y): an input description x and the answer y someone or something recorded for it. A delivery with its distance, restaurant, hour and weather (x) and how long it actually took (y). A card transaction (x) and whether it was later charged back (y). The goal is a function f such that f(x) is close to y for new x we have not seen. When y is a number, the task is regression; when y is a category, it is classification.

Three choices define every supervised method, and once you see them you can place any algorithm in the space:

  1. Hypothesis class: what functions f can the model express? Lines and hyperplanes (linear models), piecewise-constant regions (trees), sums of trees (ensembles), compositions of matrix multiplications and non-linearities (neural networks).
  2. Loss: how is the gap between f(x) and y measured? Squared error, log-loss, hinge loss. As Chapter 6.1 showed, each corresponds to a probabilistic noise assumption.
  3. Optimiser: how are the parameters found? Closed form, gradient descent, greedy recursive partitioning, stage-wise boosting.

Add a fourth, regularisation (how complexity is penalised), and you have the whole design space. Linear regression is (hyperplanes, squared error, normal equation). Random forests are (averages of deep trees, impurity, greedy splitting plus bootstrap). XGBoost is (sums of shallow trees, any twice-differentiable loss, stage-wise second-order boosting, explicit penalties on tree size and leaf values).

Bridging from Java & Spring Boot

What you already know
You have written rules engines: chains of if (amount > 1000 && country != homeCountry) riskScore += 30, maybe in Drools or as a strategy pattern. You have tuned thresholds by hand from dashboards. A decision tree is exactly such a rule set, except that the conditions and thresholds are chosen automatically to minimise error on historical data, and a gradient-boosted model is hundreds of such small rule sets whose scores are added.
Why that is not enough
Hand-written rules do not scale beyond a few dozen conditions, interact in unpredictable ways, and drift silently as behaviour changes. Learned models search millions of candidate rules, weigh evidence consistently, and can be retrained on a schedule.
The modern approach
For tabular data, start with a regularised linear/logistic baseline and a gradient-boosted tree model (XGBoost, LightGBM, CatBoost, or scikit-learn's HistGradientBoosting). Neural networks win on images, text and audio, but on typical business tables, boosted trees are usually as good or better with far less tuning Opinion, a view supported by benchmark studies such as Grinsztajn et al. (NeurIPS 2022).
Where Python and Go fit
Training is Python. Serving is flexible: XGBoost and LightGBM models are plain tree dumps (JSON/text) and have native JVM bindings (XGBoost4J), Java predictors, and ONNX converters (onnxmltools); Tribuo (Oracle's Java ML library) can train and serve linear models and trees directly in Java. A linear model is just a weight vector you can store in a config file and evaluate with a dot product in any language.
In production
The trained model becomes a dependency of a Spring service: a versioned file loaded at startup (or hot-swapped from a registry), wrapped in a ScoringService bean, scored per request in microseconds for trees with a few hundred estimators, with features from a feature store and predictions logged for monitoring and retraining.
Use it when / avoid it when
Use supervised learning when you have historical labels that reflect the decision you want to automate, and the future resembles the past. Avoid it when labels are absent or biased by the old process (consider the feedback loop), when the cost of errors requires guarantees rules can give and models cannot, or when a simple deterministic rule already captures the logic.

3. Fundamentals

3.1 The supervised learning framing

Formally, we assume examples (x, y) are drawn independently from an unknown distribution D. We want f minimising the expected loss (the risk) on D, but we only have m samples, so we minimise the empirical risk, the average loss on the training set, plus a regularisation term:

\[ \hat f = \arg\min_{f\in\mathcal{F}} \;\frac{1}{m}\sum_{i=1}^{m}\ell\big(f(\mathbf{x}_i), y_i\big) + \lambda\,\Omega(f). \]

In words: pick the function from the allowed family that fits the training data well, while not being too complex. The gap between training performance and performance on D is the generalisation gap, which Chapter 6.5 measures with validation and cross-validation and analyses with the bias-variance decomposition.

3.2 Linear regression

Intuition. Predict y as a weighted sum of the features plus a constant. Each weight answers: "holding the other features fixed, how much does the prediction change per unit of this feature?" For houses, perhaps price ≈ 50 + 2.0 × (m²) + 10 × (bedrooms), in thousands. A 100 m² three-bedroom house is predicted at 50 + 200 + 30 = 280.

\[ \hat y = w_0 + w_1x_1 + \dots + w_nx_n = \mathbf{w}^\top\mathbf{x}\quad(\text{with } x_0 = 1). \]

Loss. Mean squared error, \( \text{MSE} = \frac{1}{m}\sum_i(\hat y_i - y_i)^2 \), justified in Chapter 6.1 as maximum likelihood under Gaussian noise. Squaring penalises large errors more than small ones and makes the loss a smooth convex bowl.

Two solvers. The normal equation \( \mathbf{w} = (X^\top X)^{-1}X^\top\mathbf{y} \) solves it exactly in one shot (implemented via QR or SVD); gradient descent iterates \( \mathbf{w}\leftarrow\mathbf{w} - \eta\cdot\frac{2}{m}X^\top(X\mathbf{w}-\mathbf{y}) \). Tiny example: points (1, 1), (2, 3), (3, 4). With an intercept, the least-squares line is ŷ = −0.333 + 1.5x (slope = Σ(x − x̄)(y − ȳ) / Σ(x − x̄)² = (−1·(−1.667) + 0 + 1·1.333)/2 = 3/2 = 1.5; intercept = ȳ − 1.5x̄ = 2.667 − 3 = −0.333). Predictions 1.167, 2.667, 4.167; residuals −0.167, 0.333, −0.167, which sum to zero, as they always do with an intercept.

Interpreting coefficients requires care: they are conditional on the other features, change when correlated features are added or removed, and are only comparable in magnitude if features are standardised. Linear regression can also model curves by adding transformed features (x², log x, splines); it is "linear in the parameters", not necessarily in the inputs.

3.3 Regularisation: L2 (ridge), L1 (lasso), elastic net

Intuition: a complexity budget. With many features, especially correlated or noisy ones, least squares will happily assign huge positive and negative weights that cancel on the training data and explode on new data. Regularisation charges the model for weight size, so it only "spends" weight where the data strongly justifies it.

Ridge (L2) adds λ‖w‖₂²: every weight is shrunk toward zero proportionally, correlated features share weight, and nothing becomes exactly zero. Closed form: \( \mathbf{w} = (X^\top X + \lambda I)^{-1}X^\top\mathbf{y} \). Example with one standardised feature where Σx² = 10 and Σxy = 20: OLS gives w = 2.0; ridge with λ = 10 gives 20/(10 + 10) = 1.0. The weight is halved.

\[ \min_{\mathbf{w}}\;\|X\mathbf{w}-\mathbf{y}\|_2^2 + \lambda\|\mathbf{w}\|_2^2. \]

Lasso (L1) adds λ‖w‖₁: small weights are pushed to exactly zero, performing feature selection. In the single-feature case the solution is soft-thresholding: compute the OLS weight, subtract a constant from its magnitude, and clip at zero. With the same numbers and the objective ‖Xw − y‖² + λ|w|, w = sign(2) × max(0, 2 − λ/(2 × 10)); with λ = 20, w = 1.0; with λ ≥ 40, w = 0.

\[ \min_{\mathbf{w}}\;\|X\mathbf{w}-\mathbf{y}\|_2^2 + \lambda\|\mathbf{w}\|_1. \]

Why L1 gives zeros and L2 does not has a clean geometric picture: the solution is where the elliptical contours of the squared error first touch the constraint region. The L1 region is a diamond with corners on the axes, and contours usually first touch at a corner, where some coordinates are zero. The L2 region is a circle with no corners. A gradient picture says the same thing: the L2 penalty's pull, 2λw, fades as w approaches zero; the L1 pull, λ·sign(w), stays constant all the way to zero.

Elastic net mixes both, \( \lambda[\alpha\|\mathbf{w}\|_1 + \tfrac{1-\alpha}{2}\|\mathbf{w}\|_2^2] \) (scikit-learn's l1_ratio = α). It keeps lasso's sparsity but, unlike lasso, selects groups of correlated features together instead of arbitrarily picking one. Remember: penalties assume standardised features, and the intercept is not penalised. In scikit-learn, Ridge(alpha) and Lasso(alpha) use α for λ, while LogisticRegression(C) uses C = 1/λ, so larger C means less regularisation.

3.4 Logistic regression

Intuition. For a yes/no outcome we want a probability. Compute the same linear score z = wᵀx (called the logit, which can be any real number), then squash it into (0, 1) with the sigmoid function σ(z) = 1/(1 + e−z). z = 0 maps to 0.5; z = 2 maps to 0.881; z = −2 to 0.119. The logit has a concrete meaning: it is the log-odds, log(p/(1 − p)). A weight of 0.7 on "has used a coupon before" means that feature multiplies the odds of conversion by e0.7 ≈ 2.0, holding the rest fixed.

\[ P(y=1\mid\mathbf{x}) = \sigma(\mathbf{w}^\top\mathbf{x}) = \frac{1}{1+e^{-\mathbf{w}^\top\mathbf{x}}},\qquad \log\frac{p}{1-p} = \mathbf{w}^\top\mathbf{x}. \]

Loss. Log-loss (binary cross-entropy), the Bernoulli negative log-likelihood from Chapter 6.1. Its gradient has the elegant form \( \nabla = \frac{1}{m}X^\top(\hat{\mathbf{p}} - \mathbf{y}) \): the same "error times input" shape as linear regression. There is no closed-form solution, but the loss is convex, so gradient descent, Newton's method or L-BFGS (scikit-learn's default lbfgs solver) reliably finds the global optimum. If the classes are perfectly separable, the unregularised optimum is at infinity (weights grow forever to push probabilities to exactly 0 and 1); regularisation is what keeps the solution finite.

Decision boundary. Predicting class 1 when p ≥ 0.5 is the same as wᵀx ≥ 0: a straight line in 2-D, a hyperplane in general. Logistic regression is a linear classifier; curved boundaries require engineered features (polynomials, interactions, splines) or a different model. The threshold need not be 0.5: Chapter 6.5 shows how to choose it from costs.

3.5 Softmax (multinomial) regression

For K classes, compute one score per class, zk = wkᵀx, and turn the score vector into probabilities with softmax: exponentiate each score (making them positive) and divide by the sum (making them add to 1). Scores [2.0, 1.0, 0.1] become e² : e¹ : e0.1 = 7.389 : 2.718 : 1.105, normalised to [0.659, 0.242, 0.099]. The largest score wins, but the others keep non-zero probability.

\[ P(y=k\mid\mathbf{x}) = \frac{e^{z_k}}{\sum_{j=1}^{K}e^{z_j}},\qquad \mathcal{L} = -\log P(y = y_{\text{true}}\mid\mathbf{x}). \]

With cross-entropy loss, the gradient with respect to the scores is simply (p − onehot(y)): for the example above with true class 0, it is [0.659 − 1, 0.242, 0.099] = [−0.341, 0.242, 0.099]. Gradient descent raises the true class's score and lowers the others in proportion to their probability. Logistic regression is the K = 2 special case. Softmax is also the output layer of almost every neural classifier, and, in Chapter 7.3, the core of attention.

3.6 k-nearest neighbours

Intuition. To classify a new point, find the k most similar training points and let them vote (or average their targets for regression). No training phase at all: the "model" is the stored dataset. With k = 3 and neighbours labelled {spam, spam, ham}, predict spam with confidence 2/3.

Everything depends on the distance metric, so features must be scaled (Chapter 6.2). Small k gives jagged, high-variance boundaries that chase noise; large k gives smooth, high-bias boundaries. Prediction cost is the catch: brute force compares the query with all m training points, O(md) per query; KD-trees and ball trees help in low dimensions, and approximate nearest-neighbour indexes (HNSW, IVF) are needed at scale. In high dimensions distances concentrate (the nearest and farthest neighbours become nearly equidistant), the "curse of dimensionality", which is why k-NN works best on learned low-dimensional embeddings rather than raw features. k-NN over embeddings is exactly what a vector database does.

3.7 Support vector machines, briefly

Intuition. Among all lines that separate two classes, choose the one with the widest "street" (margin) between them, because a wide margin is robust to small perturbations of new points. The points on the edge of the street are the support vectors; the solution depends only on them. The soft-margin SVM allows some points inside the street or on the wrong side, paying a penalty controlled by C.

\[ \min_{\mathbf{w},b}\;\tfrac12\|\mathbf{w}\|^2 + C\sum_i\max\big(0,\;1 - y_i(\mathbf{w}^\top\mathbf{x}_i + b)\big),\quad y_i\in\{-1,+1\}. \]

The second term is the hinge loss: zero for points correctly classified beyond the margin, growing linearly otherwise. The margin width is 2/‖w‖, so minimising ‖w‖ maximises it. Compare with logistic regression: same linear score, a different loss (hinge versus log-loss), and SVMs output no calibrated probabilities. The kernel trick lets SVMs learn non-linear boundaries by replacing dot products with a kernel K(x, x′) (for example the RBF kernel exp(−γ‖x − x′‖²)), equivalent to working in a very high-dimensional feature space without constructing it. Kernel SVMs train in roughly O(m²) to O(m³), so they fell out of favour for large datasets; linear SVMs remain useful for high-dimensional sparse text.

3.8 Decision trees

Intuition. A decision tree is a flowchart of yes/no questions on features ("amount > 450?", "country == home?") ending in leaves that hold a prediction (the majority class or the mean target of the training rows that reached it). It is learned top-down: at each node, try every feature and every threshold, pick the split that makes the two child groups as pure as possible, and recurse until a stopping rule.

Impurity measures for classification. For a node with class proportions pk:

\[ \text{Gini} = 1 - \sum_k p_k^2,\qquad \text{Entropy} = -\sum_k p_k\log_2 p_k. \]

Gini is the probability that two randomly drawn rows from the node have different labels; entropy is the average surprise from Chapter 6.1. A pure node scores 0 on both; a 50/50 binary node has Gini 0.5 and entropy 1 bit. They usually choose the same splits; Gini is slightly cheaper (no logarithm) and is scikit-learn's default.

Information gain is the parent impurity minus the size-weighted average child impurity. Worked example: a node with 10 rows, 5 fraud and 5 legitimate (Gini 0.5). Candidate split "amount > 450" sends 4 rows left (4 fraud, 0 legit; Gini 0) and 6 right (1 fraud, 5 legit; Gini = 1 − (1/6)² − (5/6)² = 1 − 0.0278 − 0.694 = 0.278). Weighted child Gini = 0.4 × 0 + 0.6 × 0.278 = 0.167. Gain = 0.5 − 0.167 = 0.333. A different split, "is_weekend", giving left (3 fraud, 3 legit) and right (2 fraud, 2 legit), has gain 0: it separates nothing. The algorithm picks the amount split.

For regression trees, impurity is variance (MSE around the node mean), and each leaf predicts its mean.

Overfitting and pruning. Grown without limit, a tree keeps splitting until every leaf is pure, memorising noise: training accuracy 100%, test accuracy mediocre. Controls: pre-pruning (stop early: max_depth, min_samples_leaf, min_impurity_decrease) and post-pruning, notably CART's cost-complexity pruning, which grows a full tree then removes subtrees whose accuracy contribution does not justify their size, minimising error + α × (number of leaves) for a validated α (ccp_alpha in scikit-learn).

Properties. Trees handle mixed feature types, need no scaling, capture interactions and non-linearities naturally, and are readable when small. But a single tree is unstable: change a few training rows and the top split can change, altering the whole tree. Its predictions are piecewise constant (step functions), and it cannot extrapolate beyond the target range seen in training. Ensembles keep the strengths and fix the instability.

3.9 Bagging and random forests

Intuition: wisdom of a diverse crowd. If you average many predictors whose errors are not perfectly correlated, the errors partially cancel. Bagging (bootstrap aggregating) creates diversity by training each tree on a bootstrap sample: m rows drawn with replacement from the m training rows. Each tree sees a slightly different dataset, so it overfits differently, and the average is far more stable than any single tree.

Trees grown on bootstrap samples of the same data are still quite correlated, mostly because the same strong features dominate the top splits. Random forests add feature randomness: at each split, only a random subset of features (often √n for classification) is considered. That decorrelates the trees further, and the averaging becomes more effective. The math of why (variance of an average of correlated variables) is in §6.

Out-of-bag (OOB) evaluation. A bootstrap sample of size m omits about 36.8% of rows (the probability a given row is never drawn is (1 − 1/m)m ≈ e−1). Each row can therefore be scored by the roughly one-third of trees that did not see it, giving a nearly free validation estimate (oob_score=True).

Random forests are robust defaults: few critical hyperparameters (number of trees, which only needs to be "enough"; max_features; min_samples_leaf), hard to badly overfit by adding trees, embarrassingly parallel. They are usually somewhat less accurate than well-tuned boosting, and their models are large (hundreds of deep trees), which matters for memory and latency.

3.10 Gradient boosting

Intuition: a team of specialists who fix each other's mistakes. Start with a constant prediction (the mean). Look at the errors, the residuals. Fit a small tree to predict those residuals. Add a fraction of that tree's predictions to the model. Recompute residuals, fit another small tree, add a fraction, and repeat hundreds of times. Each new tree focuses on what the ensemble still gets wrong.

Numeric example with squared error. Targets y = [10, 20, 30]; start at F₀ = mean = 20; residuals [−10, 0, 10]. Suppose tree 1 learns to predict [−10, 0, 10] exactly (in reality it approximates). With learning rate (shrinkage) ν = 0.1, F₁ = 20 + 0.1 × [−10, 0, 10] = [19, 20, 21]; new residuals [−9, 0, 9]. After t perfect steps, the residuals are 0.9t times the original: 100 steps reduce them to about 0.003%. Shrinkage makes each step deliberately timid, which counterintuitively improves generalisation because no single tree's noise dominates; the cost is needing more trees.

Why "gradient"? For squared error L = ½(y − F)², the negative gradient with respect to the prediction F is exactly the residual y − F. For any other differentiable loss, we fit each tree to the negative gradient, the pseudo-residuals. Boosting is therefore gradient descent, but in function space: instead of nudging a parameter vector, each step adds a small function (a tree) pointing downhill. For log-loss the pseudo-residual is y − p, the same "error" term as logistic regression.

\[ F_m(\mathbf{x}) = F_{m-1}(\mathbf{x}) + \nu\, h_m(\mathbf{x}),\qquad h_m \approx -\frac{\partial\,\ell(y, F)}{\partial F}\Big|_{F=F_{m-1}}. \]

Key hyperparameters: number of trees (choose by early stopping on a validation set), learning rate (0.01 to 0.3), tree depth or number of leaves (controls interaction order; shallow trees of depth 3 to 8 are typical), row and column subsampling (stochastic gradient boosting, which adds randomness like a forest), and minimum samples or hessian weight per leaf.

Bagging versus boosting. Bagging averages independent, low-bias, high-variance models to reduce variance. Boosting sums dependent, high-bias (shallow) models sequentially to reduce bias, with shrinkage and subsampling controlling variance. Forests are hard to overfit by adding trees; boosting does overfit with too many trees, hence early stopping.

3.11 XGBoost

XGBoost ("eXtreme Gradient Boosting", Chen and Guestrin 2016) made gradient boosting fast, scalable and well-regularised. Its contributions, each explained in §4 and §6:

  • Regularised objective. The loss includes an explicit complexity penalty on each tree: γ per leaf (a cost for adding a leaf) and ½λ‖w‖² on leaf values (L2 shrinkage of leaf predictions), plus optional α‖w‖₁.
  • Second-order approximation. Each boosting step approximates the loss with a second-order Taylor expansion using both the gradient g and the hessian h (curvature) of the loss per example. This yields a closed-form optimal leaf value, −G/(H + λ), and an exact formula for split gain, making split search a matter of summing g and h.
  • Split finding. Exact greedy enumeration for small data; for large data, an approximate algorithm that proposes candidate thresholds from weighted quantiles (the "weighted quantile sketch", weighted by hessians), and in modern versions the histogram method (tree_method="hist", the default since XGBoost 2.0).
  • Sparsity-aware splitting. Missing values and sparse zeros get a learned default direction per split, and the algorithm only iterates over non-missing entries, making it fast on sparse one-hot data.
  • Systems engineering. Column blocks stored sorted in memory, cache-aware access, out-of-core computation, distributed training, and GPU support.

3.12 LightGBM and CatBoost

LightGBM (Microsoft, 2017) focuses on speed for large datasets. It bins features into histograms (typically up to 255 bins) and computes split gains on bins; it grows trees leaf-wise (always splitting the leaf with the largest gain, rather than level by level), which reaches lower loss with the same number of leaves but can overfit small data unless num_leaves and min_data_in_leaf are constrained. It adds GOSS (keep examples with large gradients, sample those with small ones) and Exclusive Feature Bundling (merge sparse features that are rarely non-zero together). Native categorical handling finds good category partitions by sorting categories by gradient statistics.

CatBoost (Yandex, 2017) focuses on categorical data and robustness. Its ordered target statistics encode categories using only rows that precede the current row in a random permutation, avoiding target leakage; ordered boosting applies the same idea to residuals to reduce prediction shift; and it uses oblivious (symmetric) trees, where every node at the same depth uses the same split, making trees very regular, fast to evaluate and less prone to overfitting. Default parameters are strong, so it often needs less tuning.

4. Internal Working

4.1 How a CART tree is grown

  1. Start with all training rows at the root.
  2. For each feature, sort the rows' values (or bin them). Sweep through candidate thresholds between consecutive distinct values; for each, maintain running class counts (or sums and sums of squares for regression) on the left and right, so each candidate's impurity is computed in O(1) after the sort. Total per node: O(n · m log m) for n features and m rows, or O(n · bins) with histograms.
  3. Choose the (feature, threshold) with the largest impurity decrease. If no split improves impurity by at least min_impurity_decrease, or limits such as max_depth/min_samples_split are hit, make a leaf.
  4. Partition rows into left and right children and recurse on each.
  5. Optionally post-prune with cost-complexity pruning, choosing α by cross-validation.

Prediction walks from root to leaf: O(depth), a handful of comparisons. That is why tree ensembles serve in microseconds even on a JVM: 500 trees of depth 6 are 3,000 comparisons and 500 additions.

4.2 How a random forest trains and predicts

  1. For b = 1 … B (in parallel): draw a bootstrap sample; grow a deep tree where each split considers only max_features randomly chosen features; record which rows were out-of-bag.
  2. Predict by averaging the trees' outputs (regression) or averaging their class probability estimates (classification, in scikit-learn).
  3. OOB score: for each row, aggregate only trees for which it was out-of-bag.

4.3 How gradient boosting trains

  1. Initialise F₀ to the constant minimising the loss (mean for squared error; log-odds of the base rate for log-loss).
  2. For t = 1 … T: compute per-example gradients gi (and hessians hi for second-order methods) of the loss at the current predictions; optionally subsample rows and columns; fit a regression tree to these statistics; set leaf values (for XGBoost, −G/(H + λ)); add ν times the tree to the ensemble; evaluate on the validation set; stop if the validation metric has not improved for early_stopping_rounds.
  3. The model is the base score plus the sum of all trees' leaf values for the input, passed through a link function (sigmoid for binary log-loss, softmax for multiclass).

4.4 Inside XGBoost's histogram split search

Before training, each feature is quantised into at most max_bin bins (default 256) using quantiles. At a node, a single pass over its rows accumulates, per feature and per bin, the sums Gbin and Hbin. Scanning bins left to right with prefix sums gives GL, HL for every candidate threshold, and GR = G − GL. Missing values are accumulated separately and tried on both sides. A key trick, the histogram subtraction: after splitting, build the histogram only for the smaller child and obtain the larger child's histogram as parent minus smaller, halving the work. On GPU, histograms are built with parallel atomic adds across thousands of threads.

4.5 How prediction is serialised and served

An XGBoost model saved as JSON (model.save_model("m.json"); the old binary format was removed in 3.1) contains the base score and, per tree, arrays of split feature indices, thresholds, default directions for missing values, child indices and leaf values. Any language can evaluate it with a loop. XGBoost4J loads the same file on the JVM; ONNX converters turn it into a TreeEnsembleClassifier operator for ONNX Runtime. Feature order is positional: the serving code must assemble features in exactly the training column order, which is the most common integration bug.

5. Architecture: How the Algorithms Relate

Reading the diagram: linear models differ only in their loss (squared, log, hinge) and penalty; they share the same hypothesis class. Tree ensembles split into two strategies for fixing a single tree's weaknesses: bagging attacks variance by averaging, boosting attacks bias by sequential correction. The three boosting libraries share the gradient-boosting core and differ in engineering and regularisation choices.

Reading the diagram: information flows from the current ensemble's errors (gradients and hessians) into the structure and leaf values of the next tree, which is then added with shrinkage η. The validation check is the governor: it measures generalisation every round and stops the loop when additional trees start fitting noise. Like a deployment pipeline with automated rollback, you keep the best version seen, not the last.

Reading the diagram: a boosted tree does not output a class; each leaf holds a small additive contribution to the log-odds. A transaction of 600 on a known device gets +0.4 from this tree; the final score is base log-odds plus the sum over all trees, passed through the sigmoid. "Missing" edges show the sparsity-aware default direction. Compare with a hand-written rules engine: same shape, but every threshold and weight was optimised against data.

6. The Math

6.1 Logistic regression gradient and Hessian

In words: the gradient is "prediction error times input", and the curvature is largest where the model is most uncertain (p near 0.5).

With pi = σ(wᵀxi) and the average log-loss, using σ′ = σ(1 − σ) (derived in Chapter 6.1, Exercise 5):

\[ \nabla_{\mathbf{w}}\mathcal{L} = \frac1m X^\top(\mathbf{p}-\mathbf{y}),\qquad \nabla^2_{\mathbf{w}}\mathcal{L} = \frac1m X^\top S X,\quad S = \operatorname{diag}\big(p_i(1-p_i)\big). \]

Since S has non-negative entries, the Hessian is positive semi-definite: the loss is convex. Newton's method, w ← w − H⁻¹∇L, converges in a handful of iterations (this is "iteratively reweighted least squares"). Adding an L2 term λ‖w‖² adds 2λI to the Hessian, making it strictly positive definite and the optimum unique and finite even for separable data.

6.2 Softmax cross-entropy gradient

With pk = ezk/Σjezj and L = −log pc for true class c: L = −zc + log Σj ezj. Differentiating, ∂L/∂zk = −[k = c] + ezk/Σezj = pk − [k = c]. In vector form:

\[ \frac{\partial\mathcal{L}}{\partial\mathbf{z}} = \mathbf{p} - \mathbf{e}_c,\qquad \frac{\partial\mathcal{L}}{\partial W} = (\mathbf{p}-\mathbf{e}_c)\,\mathbf{x}^\top. \]

6.3 Ridge closed form and its shrinkage in the SVD basis

Setting the gradient of ‖Xw − y‖² + λ‖w‖² to zero: 2Xᵀ(Xw − y) + 2λw = 0, so (XᵀX + λI)w = Xᵀy. Using the SVD X = UΣVᵀ, the fitted values are

\[ X\mathbf{w}_{\text{ridge}} = \sum_j \mathbf{u}_j\,\frac{\sigma_j^2}{\sigma_j^2+\lambda}\,\mathbf{u}_j^\top\mathbf{y}. \]

In words: ridge projects y onto each principal direction of the data and shrinks that component by σj²/(σj² + λ). Directions with large singular values (well-supported by data) are barely shrunk; directions with tiny singular values (where OLS would be wildly unstable) are shrunk almost to zero. Numeric: σ² = 100, λ = 1 gives factor 0.99; σ² = 0.5 gives 0.33.

6.4 Impurity and information gain, formally

For a split of node S into SL, SR with impurity I:

\[ \Delta I = I(S) - \frac{|S_L|}{|S|}I(S_L) - \frac{|S_R|}{|S|}I(S_R). \]

Entropy-based gain equals the mutual information between the split indicator and the label within the node. Redoing §3.8's example with entropy: parent 1 bit; left (4/0) entropy 0; right (1/5) entropy −(1/6)log₂(1/6) − (5/6)log₂(5/6) = 0.431 + 0.219 = 0.650; gain = 1 − 0.6 × 0.650 = 0.610 bits.

6.5 Why averaging correlated trees helps (and its limit)

If B identically distributed predictors each have variance σ² and pairwise correlation ρ, the variance of their average is

\[ \operatorname{Var}\Big(\frac1B\sum_b T_b\Big) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2. \]

In words: adding trees drives the second term to zero, but the first term, ρσ², is a floor that more trees cannot remove. Only decorrelation (lower ρ) lowers the floor, which is exactly what random feature subsets do. Numeric: σ² = 1, ρ = 0.5, B = 100: variance 0.5 + 0.005 = 0.505. Halve ρ to 0.25 and it is 0.2575. Going from 100 to 1,000 trees at ρ = 0.5 only saves 0.0045.

6.6 The out-of-bag fraction

The probability that a specific row is not drawn in m draws with replacement is (1 − 1/m)m. Since ln(1 − 1/m) ≈ −1/m for large m, this tends to e−1 ≈ 0.368. For m = 10: 0.910 ≈ 0.349; for m = 1,000: about 0.3677.

6.7 Gradient boosting as functional gradient descent

Think of the predictions on the training set, F = (F(x₁), …, F(xm)), as a vector of m "parameters". The steepest-descent step on the total loss is −∇FL = (−∂ℓ/∂F(xi))i. We cannot add an arbitrary vector (it would not generalise to new x), so we add the tree h from our hypothesis class that best approximates this direction in the least-squares sense, then take a step of size ν. 6.8 XGBoost's objective, leaf weights and split gain

In words: approximate the loss around the current predictions by a parabola per example; within a leaf, all examples get the same added value w, so the leaf's loss is a sum of parabolas in w, whose minimum is at −(sum of slopes)/(sum of curvatures + λ). The quality of a tree structure is how far it can push down the total of those parabola minima, minus γ per leaf.

At round t, the objective for the new tree ft with T leaves and leaf values w is

\[ \mathcal{L}^{(t)} = \sum_i \ell\big(y_i,\hat y_i^{(t-1)} + f_t(\mathbf{x}_i)\big) + \gamma T + \tfrac12\lambda\sum_{j=1}^T w_j^2. \]

Second-order Taylor expansion with gi = ∂ℓ/∂ŷ and hi = ∂²ℓ/∂ŷ² at ŷ(t−1), dropping constants:

\[ \mathcal{L}^{(t)} \approx \sum_i\Big[g_i f_t(\mathbf{x}_i) + \tfrac12 h_i f_t(\mathbf{x}_i)^2\Big] + \gamma T + \tfrac12\lambda\sum_j w_j^2 = \sum_{j=1}^{T}\Big[G_j w_j + \tfrac12(H_j+\lambda)w_j^2\Big] + \gamma T, \]

where Gj, Hj sum g and h over the examples in leaf j. Each bracket is a parabola in wj, minimised at

\[ w_j^* = -\frac{G_j}{H_j+\lambda},\qquad \mathcal{L}^* = -\frac12\sum_{j=1}^{T}\frac{G_j^2}{H_j+\lambda} + \gamma T. \]

Splitting one leaf into left and right changes the objective by

\[ \text{Gain} = \frac12\left[\frac{G_L^2}{H_L+\lambda} + \frac{G_R^2}{H_R+\lambda} - \frac{(G_L+G_R)^2}{H_L+H_R+\lambda}\right] - \gamma. \]

A split is worth making only if Gain > 0, so γ acts as a minimum gain threshold (pre-pruning built into the objective). min_child_weight requires H in each child to exceed a threshold; for log-loss, H = Σp(1 − p), so this prevents leaves made of a few confidently predicted examples.

Numeric example (squared error, so g = ŷ − y and h = 1). Targets [1, 2, 8, 9], current prediction 5 for all, so g = [4, 3, −3, −4]. λ = 1, γ = 0. Split {1, 2} | {8, 9}: GL = 7, HL = 2, GR = −7, HR = 2. Gain = ½[49/3 + 49/3 − 0/5] ≈ 16.33. Leaf values: −7/3 ≈ −2.33 and +2.33. Plain residual-mean fitting would give ∓3.5; λ shrinks leaves with little hessian mass toward zero, which is how XGBoost regularises small leaves. Alternative split {1} | {2, 8, 9}: GL = 4, HL = 1, GR = −4, HR = 3; gain = ½[16/2 + 16/4 − 0] = 6.0. The first split wins.

import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import log_loss, roc_auc_score, accuracy_score
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)          # 569 rows, 30 features, y=1 benign
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)
sc = StandardScaler().fit(X_tr)
X_tr, X_te = sc.transform(X_tr), sc.transform(X_te)

def sigmoid(z):
    # numerically stable: avoid exp overflow for large |z|
    out = np.empty_like(z)
    pos = z >= 0
    out[pos] = 1.0 / (1.0 + np.exp(-z[pos]))
    ez = np.exp(z[~pos])
    out[~pos] = ez / (1.0 + ez)
    return out

def fit_logreg(X, y, lam=0.01, eta=0.5, epochs=3000):
    m, n = X.shape
    w, b = np.zeros(n), 0.0
    for epoch in range(epochs):
        p = sigmoid(X @ w + b)
        grad_w = X.T @ (p - y) / m + 2 * lam * w      # L2 on weights, not on bias
        grad_b = np.mean(p - y)
        w -= eta * grad_w
        b -= eta * grad_b
    return w, b

w, b = fit_logreg(X_tr, y_tr)
p_te = sigmoid(X_te @ w + b)
print("scratch : acc %.3f  auc %.4f  logloss %.4f" % (
    accuracy_score(y_te, p_te >= 0.5), roc_auc_score(y_te, p_te), log_loss(y_te, p_te)))

# Same objective in scikit-learn: C = 1 / (2 * lam * m) maps our averaged penalty to sklearn's
sk = LogisticRegression(C=1 / (2 * 0.01 * len(y_tr)), max_iter=5000).fit(X_tr, y_tr)
p_sk = sk.predict_proba(X_te)[:, 1]
print("sklearn : acc %.3f  auc %.4f  logloss %.4f" % (
    accuracy_score(y_te, p_sk >= 0.5), roc_auc_score(y_te, p_sk), log_loss(y_te, p_sk)))
print("max |w diff|:", np.abs(sk.coef_.ravel() - w).max())   # small: same optimum
# Illustrative: acc ~0.97, AUC ~0.99 for both

The mapping C = 1/(2λm) comes from scikit-learn minimising ½‖w‖² + C·Σℓi (a sum, not a mean). Matching your from-scratch objective to the library's exact parameterisation is a valuable exercise in reading docs carefully.

7.2 Softmax regression from scratch (digits)

import numpy as np
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
X, y = load_digits(return_X_y=True)                  # 1797 8x8 images, 10 classes
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)
sc = StandardScaler().fit(X_tr)

K, (m, n) = 10, X_tr.shape
Y = np.eye(K)[y_tr]                                  # one-hot targets

def softmax(Z):
    Z = Z - Z.max(axis=1, keepdims=True)
    E = np.exp(Z)
    return E / E.sum(axis=1, keepdims=True)

W, b = 0.01 * rng.normal(size=(n, K)), np.zeros(K)
for epoch in range(500):
    P = softmax(X_tr @ W + b)
    G = (P - Y) / m                                  # dL/dZ, the (p - onehot) result
    W -= 0.5 * (X_tr.T @ G + 1e-3 * W)
    b -= 0.5 * G.sum(axis=0)
    if epoch % 100 == 0:
        loss = -np.mean(np.log(P[np.arange(m), y_tr] + 1e-12))
        print(f"epoch {epoch} loss {loss:.4f}")
acc = (softmax(X_te @ W + b).argmax(axis=1) == y_te).mean()
print("test accuracy", round(acc, 3))                # ~0.96-0.97 (Illustrative)

7.4 A regression tree from scratch

import numpy as np
from dataclasses import dataclass
from typing import Optional

@dataclass
class Node:
    value: float
    feature: Optional[int] = None
    threshold: Optional[float] = None
    left: Optional["Node"] = None
    right: Optional["Node"] = None

def best_split(X, y, min_leaf):
    m, n = X.shape
    best = (None, None, 0.0)                    # feature, threshold, gain (SSE reduction)
    parent_sse = ((y - y.mean()) ** 2).sum()
    for j in range(n):
        order = np.argsort(X[:, j])
        xs, ys = X[order, j], y[order]
        csum, csq = np.cumsum(ys), np.cumsum(ys ** 2)
        tot, totsq = csum[-1], csq[-1]
        for i in range(min_leaf, m - min_leaf + 1):
            if xs[i - 1] == xs[i]:
                continue                        # cannot split between equal values
            nl, nr = i, m - i
            sl, sr = csum[i - 1], tot - csum[i - 1]
            sse_l = csq[i - 1] - sl ** 2 / nl   # SSE = sum(y^2) - (sum y)^2 / n, O(1) per candidate
            sse_r = (totsq - csq[i - 1]) - sr ** 2 / nr
            gain = parent_sse - sse_l - sse_r
            if gain > best[2]:
                best = (j, (xs[i - 1] + xs[i]) / 2, gain)
    return best

def grow(X, y, depth=0, max_depth=4, min_leaf=5):
    node = Node(value=float(y.mean()))
    if depth >= max_depth or len(y) < 2 * min_leaf:
        return node
    j, t, gain = best_split(X, y, min_leaf)
    if j is None:
        return node
    mask = X[:, j] <= t
    node.feature, node.threshold = j, t
    node.left = grow(X[mask], y[mask], depth + 1, max_depth, min_leaf)
    node.right = grow(X[~mask], y[~mask], depth + 1, max_depth, min_leaf)
    return node

def predict_one(node, x):
    while node.feature is not None:
        node = node.left if x[node.feature] <= node.threshold else node.right
    return node.value

if __name__ == "__main__":
    from sklearn.datasets import fetch_california_housing

7.5 Gradient boosting from scratch

import numpy as np
from sklearn.datasets import fetch_california_housing
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeRegressor

X, y = fetch_california_housing(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, random_state=0)
X_tr, X_val, y_tr, y_val = train_test_split(X_tr, y_tr, test_size=0.2, random_state=0)

class TinyGBM:
    """Squared-error gradient boosting with shrinkage, row subsampling and early stopping."""
    def __init__(self, n_estimators=2000, learning_rate=0.05, max_depth=4,
                 subsample=0.8, patience=50, seed=0):
        self.n, self.lr, self.depth = n_estimators, learning_rate, max_depth
        self.subsample, self.patience = subsample, patience
        self.rng = np.random.default_rng(seed)

    def fit(self, X, y, X_val, y_val):
        self.f0 = y.mean()
        self.trees = []
        F, F_val = np.full(len(y), self.f0), np.full(len(y_val), self.f0)
        best, best_iter = np.inf, 0
        for t in range(self.n):
            residual = y - F                               # negative gradient of 1/2 (y-F)^2
            idx = self.rng.random(len(y)) < self.subsample # stochastic gradient boosting
            tree = DecisionTreeRegressor(max_depth=self.depth, random_state=t)
            tree.fit(X[idx], residual[idx])
            F += self.lr * tree.predict(X)
            F_val += self.lr * tree.predict(X_val)
            self.trees.append(tree)
            val_mse = np.mean((y_val - F_val) ** 2)
            if val_mse < best:
                best, best_iter = val_mse, t
            elif t - best_iter >= self.patience:
                break
        self.trees = self.trees[: best_iter + 1]           # keep the best iteration
        return self

    def predict(self, X):
        return self.f0 + self.lr * sum(t.predict(X) for t in self.trees)

gbm = TinyGBM().fit(X_tr, y_tr, X_val, y_val)
print("trees kept:", len(gbm.trees), " test MSE:", np.mean((gbm.predict(X_te) - y_te) ** 2))
# Illustrative: several hundred trees, test MSE ~0.22-0.25 (vs ~0.55 for linear regression)

12. Common Mistakes

  • Interpreting raw coefficients of unscaled or correlated features as importance. A coefficient's size depends on units; correlated features split or flip weight.
  • Reading C as regularisation strength. In LogisticRegression and SVC, C is the inverse: higher C means weaker regularisation.
  • Forgetting regularisation is on by default. scikit-learn's LogisticRegression is L2-regularised by default; coefficients differ from statsmodels' unpenalised MLE.
  • Unlimited-depth single trees in production. Perfect training accuracy, unstable predictions.
  • Boosting without early stopping. Validation loss rises while training loss keeps falling.
  • Using the test set for early stopping. Then the test score is optimistically biased; use a separate validation split.
  • Assuming tree models extrapolate. A GBDT trained on prices up to $2M will never predict $3M; trees output values within the training target range. Combine with a linear component or model ratios if extrapolation matters.
  • Feature order mismatch at serving. XGBoost DMatrix columns are positional; a reordered feature list silently produces garbage scores.
  • Trusting gain-based feature importance. It is biased toward high-cardinality and continuous features; use permutation importance or SHAP.
  • Mismatched library versions between training and serving (XGBoost4J vs Python XGBoost), changing default behaviours or model format support.
  • Thresholding at 0.5 out of habit. The threshold is a business decision based on costs and base rates (Chapter 6.5).

13. Production Concerns

13.1 Latency and throughput

Inference cost for GBDTs is roughly trees × depth comparisons, cache behaviour dominating at scale. Batch requests; use compiled predictors where latency matters (ONNX Runtime, Treelite/TL2cgen-style compilation, or the library's native predictor); constrain tree count and depth with latency as an explicit objective. For linear models, the cost is feature retrieval, not math.

13.2 Calibration

Logistic regression is usually well calibrated; boosted models trained on log-loss are often reasonable; random forests and SVMs are not. If probabilities feed decisions, check reliability curves and apply Platt scaling or isotonic regression on held-out data (Chapter 6.5).

13.3 Monitoring and retraining

Monitor input drift, score distributions, and (when labels arrive) performance by segment. Retrain on a schedule or on drift triggers; compare challenger to champion offline, then online. Keep the previous model artifact for instant rollback, as you would keep the previous container image.

13.4 Reproducibility

Seed everything (random_state, seed), pin library versions, log the training data snapshot ID and feature list, and store the model with its metadata in a registry (MLflow or equivalent). Note that multithreaded histogram building can introduce tiny floating-point differences; use deterministic settings where offered if you need bit-exact reproduction.

13.5 Security and robustness

Validate inputs at the service boundary (ranges, types) before scoring; trees will happily score absurd inputs. Rate-limit and avoid exposing raw scores externally to reduce model extraction risk. Model files are code-adjacent: load only signed artifacts from your registry; avoid pickle where a data format (XGBoost JSON, ONNX) exists.

Fit y = a + bx by least squares to (0, 1), (1, 3), (2, 2), (3, 6) by hand. Report a, b, the residuals and the MSE.

Solution

Exercise 3 · Intermediate

For binary log-loss boosting, g = p − y and h = p(1 − p) with p the current predicted probability. Four examples all currently at p = 0.5 have labels [1, 1, 1, 0]. With λ = 1, compute the optimal single-leaf value, and the new probability for these examples if the learning rate is 0.3. Then compute the gain of splitting into {first three} and {last one}, γ = 0.

Solution

g = [−0.5, −0.5, −0.5, 0.5], h = 0.25 each. G = −1.0, H = 1.0. w* = −G/(H + λ) = 1/2 = 0.5. New log-odds = 0 + 0.3 × 0.5 = 0.15, p = σ(0.15) ≈ 0.537. Split: GL = −1.5, HL = 0.75; GR = 0.5, HR = 0.25. Gain = ½[2.25/1.75 + 0.25/1.25 − 1/2] = ½[1.286 + 0.2 − 0.5] = 0.493. Positive, so the split helps; leaf values 1.5/1.75 ≈ 0.857 and −0.5/1.25 = −0.4.

Exercise 4 · Intermediate

Derive the lasso solution for a single standardised feature, minimising ½Σ(yi − wxi)² + λ|w| with Σxi² = m. Show it is soft-thresholding of the OLS estimate.

Solution

For w ≠ 0 the derivative is −Σxi(yi − wxi) + λ sign(w) = −Σxiyi + mw + λ sign(w). Let ŵ = Σxiyi/m (OLS). Setting to zero: w = ŵ − (λ/m) sign(w). If ŵ > λ/m, w = ŵ − λ/m > 0, consistent. If ŵ < −λ/m, w = ŵ + λ/m. If |ŵ| ≤ λ/m, no non-zero w is consistent and the subgradient condition 0 ∈ −mŵ + λ[−1, 1] holds at w = 0. Hence w = sign(ŵ) max(|ŵ| − λ/m, 0): shrink by a constant, clip at zero.

Exercise 5 · Advanced

A random forest of trees with individual variance σ² = 4 and pairwise correlation ρ = 0.3. (a) Variance of the average of 50 trees? (b) Of infinitely many? (c) If reducing max_features lowers ρ to 0.15 but raises σ² to 4.5, is it worth it for 500 trees?

Solution

(a) 0.3 × 4 + 0.7 × 4/50 = 1.2 + 0.056 = 1.256. (b) 1.2. (c) Before: 1.2 + 2.8/500 = 1.2056. After: 0.15 × 4.5 + 0.85 × 4.5/500 = 0.675 + 0.00765 = 0.683. Exercise 6 · Advanced (coding)

Extend TinyGBM (§7.5) to binary classification with log-loss: initialise with the log-odds of the base rate, fit trees to y − p, and set each leaf's value with a Newton step Σ(y − p)/Σp(1 − p). Test it on breast cancer against HistGradientBoostingClassifier.

Solution
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeRegressor

def sigmoid(z): return 1 / (1 + np.exp(-z))

class TinyGBMClassifier:
    def __init__(self, n=300, lr=0.1, depth=3, lam=1.0):
        self.n, self.lr, self.depth, self.lam = n, lr, depth, lam

    def fit(self, X, y):
        p0 = y.mean()
        self.f0 = np.log(p0 / (1 - p0))
        F = np.full(len(y), self.f0)
        self.trees = []
        for t in range(self.n):
            p = sigmoid(F)
            g, h = y - p, p * (1 - p)
            tree = DecisionTreeRegressor(max_depth=self.depth, random_state=t).fit(X, g)
            leaf = tree.apply(X)
            values = {}
            for lf in np.unique(leaf):                       # Newton leaf values
                idx = leaf == lf
                values[lf] = g[idx].sum() / (h[idx].sum() + self.lam)
            F += self.lr * np.vectorize(values.get)(leaf)
            self.trees.append((tree, values))
        return self

    def decision_function(self, X):
        F = np.full(len(X), self.f0)
        for tree, values in self.trees:
            F += self.lr * np.vectorize(values.get)(tree.apply(X))
        return F

X, y = load_breast_cancer(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, stratify=y, random_state=0)
ours = TinyGBMClassifier().fit(X_tr, y_tr)
ref = HistGradientBoostingClassifier(random_state=0).fit(X_tr, y_tr)
print(roc_auc_score(y_te, ours.decision_function(X_te)), roc_auc_score(y_te, ref.predict_proba(X_te)[:, 1]))
# Both ~0.99 (Illustrative)

The tree's structure is chosen by fitting the gradient with squared error (as in Friedman's original algorithm); the leaf values are then replaced by Newton steps, which is the essence of XGBoost's leaf formula with λ.

15. Interview Questions

Conceptual Explain the difference between bagging and boosting.

Bagging trains models independently on bootstrap samples and averages them, reducing variance; base learners are typically deep, low-bias trees; it parallelises and rarely overfits as trees are added. Boosting trains models sequentially, each correcting the current ensemble's errors (fitting negative gradients), reducing bias; base learners are shallow; it uses shrinkage and subsampling to control variance and needs early stopping.

Conceptual Why does L1 regularisation produce sparse models while L2 does not?

Geometrically, the L1 constraint region has corners on the axes where loss contours tend to touch first. Analytically, the L1 subgradient applies a constant pull λ toward zero regardless of magnitude, so small coefficients are driven exactly to zero (soft-thresholding), whereas L2's pull 2λw vanishes as w approaches zero, only shrinking proportionally.

Conceptual What does XGBoost add on top of classic gradient boosting?

A regularised objective (γ per leaf, L2/L1 on leaf weights); a second-order Taylor approximation using gradients and hessians, giving closed-form leaf weights −G/(H + λ) and an analytic split gain; sparsity-aware default directions for missing values; weighted-quantile and histogram split finding; column/row subsampling; and systems work (cache-aware blocks, out-of-core, distributed and GPU training).

Conceptual Is logistic regression a linear model if it outputs a sigmoid?

Yes: its log-odds are linear in the features, and its decision boundary wᵀx = threshold-logit is a hyperplane. The sigmoid is a monotone link mapping the linear score to a probability; it does not bend the boundary.

Coding Implement one gradient-descent step of L2-regularised logistic regression in NumPy.
def step(w, b, X, y, eta=0.1, lam=1e-3):
    p = 1 / (1 + np.exp(-(X @ w + b)))
    grad_w = X.T @ (p - y) / len(y) + 2 * lam * w
    grad_b = (p - y).mean()
    return w - eta * grad_w, b - eta * grad_b

Mention numerical stability (clip logits or use a stable sigmoid), not regularising the bias, and feature scaling.

Scenario Your GBDT validation AUC is 0.92 but drops to 0.84 after a month in production. What do you check?

Data drift (feature distributions, unknown categories, null rates), concept drift (fraud patterns change), training/serving skew (feature computation differences, feature order), label delay effects (immature labels in evaluation), leakage in the original validation (random split on time-dependent data). Remedies: temporal validation, retraining cadence, drift monitors, parity tests.

Scenario A product manager wants the price model to never predict a lower price for a larger flat, all else equal. How?

Use monotonic constraints on the size feature in XGBoost/LightGBM/HistGradientBoosting (+1 for increasing). Verify with partial dependence or ICE plots and property-based tests that sweep size while holding other features fixed. Alternatively use a linear or GAM-style model with constrained coefficients.

Architecture How would you serve an XGBoost model at 20k requests per second with p99 under 10 ms from a Spring Boot fleet?

Load the model in-process (XGBoost4J or ONNX Runtime) to avoid network hops; batch micro-requests where possible; prefetch features in parallel from the online store with timeouts and defaults; cap trees/depth from a latency budget measured in load tests; warm up at startup; pool predictors if not thread-safe; expose metrics for feature fetch versus inference time; deploy new models via registry with canary and shadow scoring; keep a rule-based fallback on timeout.

Conceptual Why can't tree ensembles extrapolate and when does it matter?

Each tree's prediction is a leaf value computed from training targets, so the ensemble's output is bounded by combinations of training-range values; beyond the last split threshold the prediction is flat. It matters for trends (prices rising over time, growth forecasting) and for inputs outside the training range. Mitigate with detrending, modelling ratios or differences, linear components (LightGBM's linear_tree), or linear models.
