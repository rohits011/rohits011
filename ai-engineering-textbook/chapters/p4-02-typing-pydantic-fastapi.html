Type Hints, Pydantic, FastAPI & Dependency Injection

Spring Boot gives you a compiler, Bean Validation, Jackson, an IoC container and Spring Security out of the box. Modern Python assembles the same capabilities from separate, composable pieces: a gradual type system checked by mypy or pyright, Pydantic v2 for runtime validation and serialisation, FastAPI on top of the ASGI standard and Starlette, and a function-parameter-based dependency injection system. This chapter shows how each piece works internally and how to combine them into an API that a Spring team would trust in production.

  • Prerequisites: Chapter 4.1 (event loop, threads); Spring MVC, Jackson, Bean Validation, Spring IoC and Spring Security experience.
  • You will be able to: write strictly typed Python with generics, Protocols and ParamSpec; design Pydantic v2 models, validators, settings and serialisers with correct performance characteristics; trace a FastAPI request from socket to response; choose between async and sync endpoints; build scoped dependencies with clean test overrides; and implement JWT auth and cross-cutting middleware.

1. Introduction: Rebuilding the Spring Toolbox from Python Parts

When a Spring Boot developer writes @PostMapping with a @Valid @RequestBody OrderRequest, at least five frameworks cooperate: the Java compiler checks types, Jackson deserialises JSON, Hibernate Validator enforces constraints, Spring's DispatcherServlet routes and resolves arguments, and the IoC container injects the service. Springdoc then derives an OpenAPI spec from the same annotations.

FastAPI achieves the same developer experience with a different philosophy: the type hints are the single source of truth. A parameter annotated order: OrderIn (a Pydantic model) tells FastAPI to read and validate the JSON body; limit: int = 20 becomes a validated query parameter; svc: Annotated[OrderService, Depends(get_order_service)] is injection; the return annotation drives response serialisation; and all of it is emitted into the OpenAPI document. Static checkers read the same hints to catch bugs before runtime. Understanding where static checking ends and runtime validation begins is the key mental shift.

This matters for AI systems specifically. LLM-backed services live and die by schemas: tool/function-calling definitions are JSON Schema, structured outputs are validated against models, and agent frameworks (the OpenAI and Anthropic SDKs, LangChain, LlamaIndex, Pydantic AI, instructor) all use Pydantic models to describe what a model may return. Mastering Pydantic is mastering the contract layer of AI applications.

Bridging from Java & Spring Boot

What you already know
Static types enforced by javac; generics with erasure; record DTOs; Jackson annotations (@JsonProperty, @JsonIgnore); Bean Validation (@NotNull, @Size, custom ConstraintValidator); @ConfigurationProperties with relaxed binding; constructor injection with singleton/request/prototype scopes; @ControllerAdvice; servlet filters and HandlerInterceptors; Spring Security's filter chain; @MockBean/@MockitoBean in tests.
Why that is not enough
Python's types are not enforced at runtime at all: an annotation is metadata. A typo in a dict key or a None where a string was expected passes silently unless a checker or a validator catches it. There is no container scanning the classpath; there are no annotations on classes driving injection; scopes are expressed by function lifetimes and generators.
The modern approach
Treat mypy/pyright in strict mode as your compiler, Pydantic v2 models at every trust boundary (HTTP, queues, LLM outputs, config) as your Jackson plus Bean Validation, FastAPI's Depends as your container, and ASGI middleware as your filter chain.
Where Python and Go fit
Go has static types without runtime validation frameworks (you use struct tags plus a validator library) and favours explicit wiring in main() over containers. Python sits between: dynamic at runtime, statically checkable, with powerful runtime introspection that FastAPI and Pydantic exploit.
In production
FastAPI services run on Uvicorn (often under Gunicorn or as multiple Uvicorn workers), behind an ingress, with Pydantic settings from environment variables and secrets, typed end to end and gated by a strict type check in CI.
Use it when / avoid it when
Use FastAPI for JSON/HTTP APIs, model-serving endpoints and LLM gateways where Python's ecosystem is the reason you are in Python. Prefer Django when you need an admin, ORM migrations and server-rendered pages in one batteries-included package; prefer Spring Boot or Go when the service has no Python-specific dependency.

3. Fundamentals

3.1 Gradual typing and what a checker actually proves

Python's type system is gradual: unannotated code is typed as Any, which is compatible with everything in both directions. A codebase can be 5% or 100% typed, and a checker only proves properties about the typed parts. That is fundamentally different from Java, where everything has a static type. Strict mode (mypy --strict, pyright "typeCheckingMode": "strict") closes the gaps: it rejects untyped definitions, implicit Any from missing stubs, and unchecked generics.

Checkers use nominal subtyping for classes (like Java) and structural subtyping for Protocols (like Go interfaces). They perform flow-sensitive narrowing: after if x is not None:, x is narrowed from str | None to str, giving you null-safety that Java only approximates with Optional and annotations like @Nullable.

3.2 Generics: TypeVar, PEP 695 syntax, variance

# Python 3.12+ syntax (PEP 695)
from collections.abc import Callable, Iterable, Sequence

class Page[T]:                                 # like class Page<T>
    def __init__(self, items: Sequence[T], total: int) -> None:
        self.items, self.total = items, total
    def map[U](self, fn: Callable[[T], U]) -> "Page[U]":   # generic method, like <U> Page<U> map(...)
        return Page([fn(i) for i in self.items], self.total)

def first[T](xs: Iterable[T], default: T) -> T:
    return next(iter(xs), default)

type JsonValue = str | int | float | bool | None | list[JsonValue] | dict[str, JsonValue]   # recursive alias

Unlike Java, Python generics are not erased in a way you can observe: Page[int] is a real runtime object (typing._GenericAlias), which is how Pydantic validates list[Order] element by element. But instances do not remember their type argument (Page[int]([1], 1) yields a plain Page), so it is erasure at the instance level and reification at the annotation level.

Variance is inferred for PEP 695 type parameters. Sequence[T] is covariant (read-only, like List<? extends T>), list[T] is invariant (mutable), and Callable[[T], R] is contravariant in T. A classic bug the checker catches: passing list[Dog] where list[Animal] is expected. Java rejects the same thing for List.

3.3 Protocol: structural typing

from typing import Protocol, runtime_checkable

@runtime_checkable
class EmbeddingModel(Protocol):
    dim: int
    def embed(self, texts: list[str]) -> list[list[float]]: ...

class OpenAIEmbedder:                      # does NOT inherit from EmbeddingModel
    dim = 1536
    def embed(self, texts: list[str]) -> list[list[float]]:
        return [[0.0] * self.dim for _ in texts]

def index(docs: list[str], model: EmbeddingModel) -> None: ...
index(["a"], OpenAIEmbedder())             # OK: structurally compatible, checked statically

This is Go's implicit interface satisfaction brought to Python. It is ideal for ports-and-adapters architectures: the domain defines a Protocol, adapters satisfy it without importing it. In Java you would declare implements EmbeddingModel; in Python you do not have to, and the checker still verifies compatibility. @runtime_checkable lets isinstance check method presence (not signatures) at runtime.

3.4 TypedDict, Literal, NewType, Annotated

  • TypedDict types a dict with known keys: useful for JSON you pass around without converting to objects (e.g. LLM message dicts). Required/NotRequired and ReadOnly (3.13) refine it. Zero runtime cost: it is a plain dict.
  • Literal["asc", "desc"] is a type with fixed values: Python's lightweight enum, and FastAPI/Pydantic validate it.
  • NewType("UserId", int) creates a distinct static type with no runtime wrapper: prevents passing an OrderId where a UserId is expected, like a Java value class but free.
  • Annotated[int, Field(gt=0)] attaches metadata to a type. Checkers see int; Pydantic and FastAPI read the metadata. This is the mechanism behind constraints and Depends, the Python equivalent of annotating a parameter in Java.

3.5 ParamSpec, Concatenate and typed decorators

import functools, time
from collections.abc import Awaitable, Callable

def timed[**P, R](fn: Callable[P, Awaitable[R]]) -> Callable[P, Awaitable[R]]:
    @functools.wraps(fn)
    async def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        t0 = time.perf_counter()
        try:
            return await fn(*args, **kwargs)
        finally:
            print(f"{fn.__name__} took {time.perf_counter() - t0:.3f}s")
    return wrapper

@timed
async def get_user(user_id: int, *, include_orders: bool = False) -> dict[str, object]: ...
# get_user("x") is now a type error: the decorator preserves the exact signature.

Without ParamSpec, decorators erase signatures to Callable[..., Any]. This is the Python equivalent of what Spring AOP proxies do transparently; in Python, decorators are explicit and the type system must be told how to preserve signatures.

3.6 Pydantic v2 in one page

A Pydantic BaseModel subclass is analysed once at class creation: annotations plus Field(...) metadata and validators are compiled into a core schema, which pydantic-core (Rust) turns into a tree of validator and serializer objects. Validation then runs in Rust with no Python bytecode per field in the common case. Key concepts:

  • Lax vs strict mode. By default, "42" is coerced to 42 for an int field (lax, like Jackson's coercion). model_config = ConfigDict(strict=True) or Field(strict=True) rejects it.
  • Validators. @field_validator (before/after/wrap/plain modes) and @model_validator for cross-field rules; equivalent to ConstraintValidator and class-level constraints.
  • Serialisation. model_dump() (to Python objects), model_dump_json() (direct to JSON bytes in Rust), with by_alias, exclude_none, @field_serializer and @computed_field.
  • TypeAdapter validates any type (e.g. list[Order] or a TypedDict) without a model class.
  • Discriminated unions. Field(discriminator="type") selects the right model by a tag in O(1), like Jackson's @JsonTypeInfo/@JsonSubTypes.
  • JSON Schema. model_json_schema(), used for OpenAPI and for LLM tool/structured-output definitions.

3.7 ASGI

ASGI (Asynchronous Server Gateway Interface) is the contract between a server (Uvicorn, Hypercorn, Granian) and an application. An ASGI app is just an async callable:

async def app(scope: dict, receive, send) -> None:
    # scope: {"type": "http", "method": "GET", "path": "/x", "headers": [...], ...}
    if scope["type"] == "http":
        await send({"type": "http.response.start", "status": 200,
                    "headers": [(b"content-type", b"text/plain")]})
        await send({"type": "http.response.body", "body": b"hello"})

It is analogous to the Servlet API but event-driven: receive() yields request body chunks and disconnect events; send() emits response start and body chunks, which makes streaming (Server-Sent Events for LLM tokens) and WebSockets first-class. A lifespan scope delivers startup/shutdown events, the equivalent of Spring's ApplicationReadyEvent and @PreDestroy. Middleware in ASGI is simply an app that wraps another app: the same onion as servlet filters.

3.8 Starlette and FastAPI layering

Starlette provides routing, the Request/Response classes, middleware, background tasks, WebSockets and a test client. FastAPI subclasses Starlette's application and router and adds: parameter declaration from type hints, Pydantic validation, the dependency injection system, response models and OpenAPI generation. Most "FastAPI" runtime behaviour (middleware order, exception handling, streaming) is actually Starlette's.

3.9 Dependency injection with Depends

A FastAPI dependency is any callable (function, class, async function, generator) whose parameters are themselves declared like endpoint parameters. FastAPI builds a dependency graph per route at startup, and at request time resolves it depth-first, caching each dependency's result per request (so two consumers of get_db share one session, like a request-scoped bean). Generator dependencies (yield) provide setup and teardown, giving you request-scoped resources with deterministic cleanup. app.dependency_overrides[get_db] = fake_db replaces a node in the graph for tests, the equivalent of @MockitoBean.

Critically, there is no container holding singletons. Application-lifetime objects (connection pools, HTTP clients, model weights) are created in the lifespan handler and stored on app.state, or held in module-level objects, and dependencies hand them out. That explicitness is closer to Go's "wire it in main" than to Spring's component scanning.

3.10 Async vs sync endpoints

If you declare an endpoint (or dependency) with async def, FastAPI awaits it directly on the event loop. If you declare it with plain def, FastAPI runs it in a worker thread via AnyIO's to_thread.run_sync, using a capacity limiter of 40 threads by default. So a def endpoint that calls a sync DB driver is safe (it blocks a worker thread, not the loop), while an async def endpoint that calls the same driver blocks everything. This single rule is the most important operational fact about FastAPI.

4. Internal Working: Class Creation, Validation and a Request's Journey

4.1 What happens when you define a Pydantic model

  1. class OrderIn(BaseModel): ... invokes Pydantic's metaclass (ModelMetaclass.__new__).
  2. It collects annotations (resolving forward references; on 3.14 via the deferred-annotations machinery), Field() defaults and metadata, and decorated validators/serialisers, and merges with parent classes.
  3. For each field type, the GenerateSchema machinery produces a core schema: a nested dict like {"type": "model-fields", "fields": {"qty": {"schema": {"type": "int", "gt": 0}}}}. Custom types can participate via __get_pydantic_core_schema__.
  4. pydantic-core compiles the core schema into a tree of Rust SchemaValidator and SchemaSerializer nodes, stored as __pydantic_validator__ and __pydantic_serializer__ on the class.
  5. A JSON Schema can be generated lazily from the same core schema.

This is a one-time compilation step, like Jackson building and caching a BeanDeserializer per type, or Hibernate Validator building constraint metadata. It is why defining thousands of models dynamically in a hot path is slow and why you should create TypeAdapters once at module level, not per request.

4.2 How validation executes

OrderIn.model_validate_json(raw_bytes) parses JSON in Rust (the jiter parser) and validates in a single pass, never building an intermediate Python dict for the whole document. model_validate(dict_obj) walks existing Python objects. For each field: lookup by name or alias, run "before" validators (Python callbacks), the core type validator (Rust), constraint checks, then "after" validators. Errors are accumulated, not thrown at the first failure, producing a ValidationError with a list of {loc, msg, type, input} entries; FastAPI turns that into a 422 response. Python-level validators are the slow part: each call crosses from Rust into the interpreter, so prefer declarative constraints (Field(gt=0, max_length=200), Annotated types, pattern) over custom validators in hot models.

Performance tip

Prefer model_validate_json(body_bytes) over model_validate(json.loads(body)): it avoids building throwaway Python dicts and strings. FastAPI does this for request bodies that are a single model in recent versions; for your own Kafka consumers and HTTP clients, do it yourself.

4.3 FastAPI startup: building the route graph

When you decorate @app.post("/orders"), FastAPI creates an APIRoute. Its constructor inspects the endpoint signature with inspect.signature and the resolved type hints and builds a Dependant tree: path params, query params, headers, cookies, body fields, and sub-dependants for each Depends, recursively. It also builds a response field from response_model or the return annotation. All of this happens once at import, analogous to Spring's RequestMappingHandlerMapping scanning @RequestMapping methods and building HandlerMethodArgumentResolver chains.

4.4 A request's journey

  1. Uvicorn accepts the TCP connection on its event loop (uvloop if installed), parses HTTP/1.1 with httptools or h11, builds the ASGI scope and calls the app.
  2. Middleware stack (outermost first): Starlette's ServerErrorMiddleware (turns unhandled exceptions into 500), your user middleware in reverse order of addition (CORS, GZip, tracing, auth...), then ExceptionMiddleware (maps HTTPException and registered handlers), then the router.
  3. Routing: the router iterates routes and matches path regexes compiled at startup; first full match wins (unlike Spring's "most specific pattern wins", order matters).
  4. Request parsing: for routes with a body, FastAPI reads the body (awaiting receive()), parses JSON or form data.
  5. Dependency resolution (solve_dependencies): depth-first through the Dependant tree; each sub-dependency's parameters are extracted and validated; results are cached per request by (callable, security scopes); async def dependencies are awaited, def ones run in the thread pool; generator dependencies are entered into an AsyncExitStack.
  6. Validation errors from all parameters are collected; if any, a RequestValidationError is raised, producing a 422 with all errors at once.
  7. Endpoint call: awaited if async; run via run_in_threadpool if sync.
  8. Response serialisation: if a response model is declared, the return value is validated/serialised through it (filtering fields, which is a security feature: you cannot accidentally leak password_hash), then rendered as JSON.
  9. Teardown: the exit code of yield dependencies runs. With the default scope="request" it runs after the response has been sent; with Depends(..., scope="function") (FastAPI 0.121+) it runs right after the endpoint returns, before sending Version-sensitive · checked Nov 2026. Background tasks run after the response is sent, in the same worker.

4.5 The thread pool behind sync code

Sync endpoints and sync dependencies are executed with anyio.to_thread.run_sync, which uses a process-global capacity limiter (default 40 tokens). If 40 sync requests are in flight, the 41st waits for a token even though the event loop is idle. This is equivalent to Tomcat's server.tomcat.threads.max: a hidden concurrency cap. You can raise it at startup:

from contextlib import asynccontextmanager
import anyio.to_thread
from fastapi import FastAPI

@asynccontextmanager
async def lifespan(app: FastAPI):
    limiter = anyio.to_thread.current_default_thread_limiter()
    limiter.total_tokens = 100        # size to your DB pool, not "as high as possible"
    yield

app = FastAPI(lifespan=lifespan)

Remember Chapter 4.1: those threads share the GIL. A sync endpoint doing CPU work still blocks other sync endpoints from executing Python in parallel; it just does not freeze the event loop's scheduling entirely (the loop thread still competes for the GIL every 5 ms).

4.6 How the static checker sees the same code

mypy and pyright never run your code. They parse it, build symbol tables, and infer types using annotations, typeshed stubs for the stdlib, inline types or stub packages (types-requests) for third-party libraries, and plugins (Pydantic ships a mypy plugin; pyright understands Pydantic via dataclass_transform, PEP 681). PEP 681 is the reason static checkers know that OrderIn(qty=1, sku="A") has a synthesised __init__ with typed keyword arguments: the library declares "I behave like a dataclass".

FastAPI's Annotated[Session, Depends(get_db)] is understood statically as Session; the checker ignores Depends. Thus the type of an injected parameter is checked in your endpoint body, but whether get_db actually returns a Session is checked only in get_db's own annotation. Keep dependency functions fully annotated.

5. Architecture

Reading the diagram: everything left of Router is Starlette (and could be shared with any ASGI framework); everything right of it is FastAPI-specific. The branch at Endpoint async def? is the async-vs-sync decision from §3.10. Compare with Spring MVC: Uvicorn plays Tomcat's connector, middleware plays the servlet filter chain, the router plus dependency solver plays DispatcherServlet plus argument resolvers, and response_model serialisation plays the HttpMessageConverter.

Reading the diagram: get_session is requested by both the auth dependency and the endpoint, but because of per-request caching it runs once; both receive the same session, exactly like a @RequestScope bean. The settings dependency is a process singleton via functools.lru_cache. Teardown runs after the response has gone out in the default scope, so a commit failure there cannot change the HTTP status: commit explicitly in the endpoint or service (or use scope="function") when the client must learn about commit errors.

Reading the diagram: the Python classes are thin; the heavy lifting lives in two compiled Rust objects per type. BaseSettings (from the separate pydantic-settings package) is a model whose input comes from environment variables, dotenv files and secret directories instead of a request body, which is precisely @ConfigurationProperties.

Reading the diagram: Spring discovers and wires objects for you; FastAPI asks you to create long-lived objects explicitly in the lifespan function and expose them through small provider functions. The FastAPI model has less magic and fewer startup surprises, but no lifecycle management for arbitrary objects, no AOP proxies, and no @Transactional; transaction boundaries are explicit code (often a dependency or a unit-of-work context manager).

6. The Math: Throughput, Thread-Pool Sizing and Validation Cost

6.1 Sizing the sync thread pool

For sync endpoints, Little's Law gives the number of threads needed: \( N_{threads} = \lambda \times W_{blocking} \). At 300 req/s and 80 ms of blocking DB time per request, you need \( 300 \times 0.08 = 24 \) busy threads on average; the default 40 leaves headroom. At 1,000 req/s you need 80, which exceeds the default limiter: requests queue invisibly and latency climbs while CPU is low. But also check the downstream: 80 concurrent queries need 80 DB connections per worker process, and with 8 workers per pod and 10 pods that is 6,400 connections, far beyond what PostgreSQL handles well. That is why high-throughput Python services go async with smaller pools, or put PgBouncer in front.

6.2 CPU budget for validation and serialisation

Intuition: validation cost is roughly linear in the number of leaf values. If Rust-core validation costs on the order of tens of nanoseconds per simple field and a Python-level validator costs on the order of a microsecond (interpreter entry and the function body), then a payload with 2,000 fields and 10 custom validators per item over 100 items costs roughly \( 2000 \times 50\,\text{ns} + 1000 \times 1\,\mu\text{s} \approx 1.1 \) ms Illustrative. At 1,000 req/s per process that is 110% of a core: impossible. The lesson is not the exact numbers but the shape: custom Python validators dominate, and big list payloads should be validated once, at the edge, never re-validated internally (use model_construct() for trusted internal data).

6.3 Process count

Workers per pod \( = \lceil \lambda_{pod} \cdot c_{cpu} / u_{target} \rceil \), where \( c_{cpu} \) is CPU-seconds per request and \( u_{target} \) the target utilisation (say 0.6). At 400 req/s per pod and 3 ms CPU per request: \( 400 \times 0.003 / 0.6 = 2 \) workers. Measure \( c_{cpu} \) with a profiler under realistic payloads; JSON serialisation of large responses is often the surprise.

7. Code: A Typed, Validated, Injected API in Three Languages

7.1 DTOs and validation: Bean Validation vs Pydantic vs Go struct tags

// Spring Boot 3.x, jakarta.validation
import jakarta.validation.Valid;
import jakarta.validation.constraints.*;
import java.math.BigDecimal;
import java.util.List;

public record OrderLine(@NotBlank @Pattern(regexp = "^[A-Z0-9-]{3,32}$") String sku,
                        @Min(1) @Max(1000) int qty,
                        @DecimalMin("0.01") BigDecimal unitPrice) {}

public record OrderIn(@NotNull @Size(min = 1, max = 100) List<@Valid OrderLine> lines,
                      @Email String notifyEmail,
                      @Pattern(regexp = "standard|express") String shipping) {
    @AssertTrue(message = "express orders limited to 20 lines")
    boolean isExpressSmall() { return !"express".equals(shipping) || lines.size() <= 20; }
}
# pip install "pydantic[email]>=2.7"
from decimal import Decimal
from typing import Annotated, Literal, Self
from pydantic import BaseModel, ConfigDict, EmailStr, Field, computed_field, model_validator

Sku = Annotated[str, Field(pattern=r"^[A-Z0-9-]{3,32}$")]

class OrderLine(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")   # immutable, reject unknown fields
    sku: Sku
    qty: Annotated[int, Field(ge=1, le=1000)]
    unit_price: Annotated[Decimal, Field(gt=0, decimal_places=2)]

class OrderIn(BaseModel):
    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)
    lines: Annotated[list[OrderLine], Field(min_length=1, max_length=100)]
    notify_email: EmailStr | None = None
    shipping: Literal["standard", "express"] = "standard"

    @model_validator(mode="after")
    def express_is_small(self) -> Self:
        if self.shipping == "express" and len(self.lines) > 20:
            raise ValueError("express orders limited to 20 lines")
        return self

    @computed_field                      # included in model_dump() and JSON schema
    @property
    def total(self) -> Decimal:
        return sum((l.unit_price * l.qty for l in self.lines), Decimal("0"))

raw = b'{"lines":[{"sku":"ABC-1","qty":"2","unit_price":"9.99"}],"shipping":"express"}'
order = OrderIn.model_validate_json(raw)          # "2" coerced to 2 in lax mode
print(order.total, order.model_dump_json())
// go get github.com/go-playground/validator/v10
package orders

import (
	"errors"

	"github.com/go-playground/validator/v10"
	"github.com/shopspring/decimal"
)

type OrderLine struct {
	SKU       string          `json:"sku" validate:"required,min=3,max=32"`
	Qty       int             `json:"qty" validate:"min=1,max=1000"`
	UnitPrice decimal.Decimal `json:"unit_price"`
}

type OrderIn struct {
	Lines       []OrderLine `json:"lines" validate:"required,min=1,max=100,dive"`
	NotifyEmail string      `json:"notify_email,omitempty" validate:"omitempty,email"`
	Shipping    string      `json:"shipping" validate:"omitempty,oneof=standard express"`
}

var validate = validator.New()

func (o *OrderIn) Validate() error {
	if err := validate.Struct(o); err != nil {
		return err
	}
	if o.Shipping == "express" && len(o.Lines) > 20 { // cross-field rule in plain code
		return errors.New("express orders limited to 20 lines")
	}
	return nil
}

Observations: Pydantic's constraints live in the type (Annotated), so you can reuse Sku anywhere, including as a query parameter. extra="forbid" is the equivalent of Jackson's FAIL_ON_UNKNOWN_PROPERTIES and is a good default for inbound APIs (mass-assignment protection). Go has no coercion: "2" for an int field is a decode error, which is the same as Pydantic strict mode.

7.2 Settings: @ConfigurationProperties vs BaseSettings

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_prefix="ORDERS_",            # ORDERS_DATABASE_URL, ORDERS_JWT_SECRET ...
        env_file=".env",                 # local dev only; env vars take precedence
        secrets_dir="/run/secrets",      # Kubernetes/Docker secrets mounted as files
        env_nested_delimiter="__",       # ORDERS_RATE__PER_MINUTE=100
    )
    database_url: PostgresDsn
    jwt_secret: SecretStr                # repr shows '**********'; .get_secret_value() to read
    jwt_audience: str = "orders-api"
    db_pool_size: int = Field(10, ge=1, le=100)
    debug: bool = False

@lru_cache                               # process-wide singleton, overridable in tests
def get_settings() -> Settings:
    return Settings()                    # fails fast at startup if config is invalid

Like Spring Boot's relaxed binding plus @Validated configuration classes, invalid configuration aborts startup with a precise error instead of failing at first use. SecretStr keeps secrets out of logs and tracebacks.

7.3 The full FastAPI service

This is a complete, runnable single-file service (split into files in a real project, see Chapter 4.3's project layout). It uses an in-memory repository behind a Protocol so you can run it without a database.

# pip install "fastapi>=0.121" "uvicorn[standard]" "pydantic-settings" "pyjwt>=2.8" "pydantic[email]"
# run: ORDERS_DATABASE_URL=postgresql://x@localhost/db ORDERS_JWT_SECRET=dev uvicorn app.main:app --reload

import time
import uuid
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager
from dataclasses import dataclass
from decimal import Decimal
from typing import Annotated, Protocol

import jwt
from fastapi import Depends, FastAPI, HTTPException, Query, Request, Response, status
from fastapi.responses import JSONResponse
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer
from pydantic import BaseModel, ConfigDict, Field

from app.settings import Settings, get_settings
from app.schemas import OrderIn          # the model from 7.1

# ---------- domain & ports ----------
class OrderOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)   # read from ORM objects/dataclasses
    id: uuid.UUID
    owner: str
    total: Decimal
    status: str

@dataclass
class Order:
    id: uuid.UUID
    owner: str
    total: Decimal
    status: str = "PENDING"

class OrderRepository(Protocol):
    async def add(self, order: Order) -> None: ...
    async def get(self, order_id: uuid.UUID) -> Order | None: ...
    async def list_for(self, owner: str, limit: int, offset: int) -> list[Order]: ...

class InMemoryOrderRepository:                # satisfies the Protocol structurally
    def __init__(self) -> None:
        self._rows: dict[uuid.UUID, Order] = {}
    async def add(self, order: Order) -> None:
        self._rows[order.id] = order
    async def get(self, order_id: uuid.UUID) -> Order | None:
        return self._rows.get(order_id)
    async def list_for(self, owner: str, limit: int, offset: int) -> list[Order]:
        mine = [o for o in self._rows.values() if o.owner == owner]
        return mine[offset : offset + limit]

class OrderService:
    def __init__(self, repo: OrderRepository) -> None:
        self.repo = repo
    async def place(self, owner: str, cmd: OrderIn) -> Order:
        order = Order(id=uuid.uuid4(), owner=owner, total=cmd.total)
        await self.repo.add(order)
        return order

# ---------- lifespan: the "ApplicationContext" ----------
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    settings = get_settings()                       # validate config at startup
    app.state.repo = InMemoryOrderRepository()      # real app: async engine / pools here
    yield
    # shutdown: close pools, flush telemetry

app = FastAPI(title="Orders API", version="1.0.0", lifespan=lifespan)

# ---------- dependencies ----------
SettingsDep = Annotated[Settings, Depends(get_settings)]

def get_repo(request: Request) -> OrderRepository:
    return request.app.state.repo

def get_order_service(repo: Annotated[OrderRepository, Depends(get_repo)]) -> OrderService:
    return OrderService(repo)                        # cheap per-request object, like a prototype bean

bearer = HTTPBearer(auto_error=False)

class Principal(BaseModel):
    sub: str
    scopes: frozenset[str] = frozenset()

async def get_principal(
    settings: SettingsDep,
    creds: Annotated[HTTPAuthorizationCredentials | None, Depends(bearer)],
) -> Principal:
    if creds is None:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "missing bearer token",
                            headers={"WWW-Authenticate": "Bearer"})
    try:
        claims = jwt.decode(creds.credentials, settings.jwt_secret.get_secret_value(),
                            algorithms=["HS256"],            # never accept the alg from the token
                            audience=settings.jwt_audience,
                            options={"require": ["exp", "sub", "aud"]})
    except jwt.PyJWTError as e:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "invalid token") from e
    return Principal(sub=claims["sub"], scopes=frozenset(claims.get("scope", "").split()))

def require_scope(scope: str):
    async def checker(p: Annotated[Principal, Depends(get_principal)]) -> Principal:
        if scope not in p.scopes:
            raise HTTPException(status.HTTP_403_FORBIDDEN, f"missing scope {scope}")
        return p
    return checker

# ---------- middleware: the filter chain ----------
@app.middleware("http")
async def request_id_and_timing(request: Request, call_next) -> Response:
    rid = request.headers.get("x-request-id") or str(uuid.uuid4())
    t0 = time.perf_counter()
    response = await call_next(request)
    response.headers["x-request-id"] = rid
    response.headers["server-timing"] = f"app;dur={(time.perf_counter() - t0) * 1000:.1f}"
    return response

# ---------- error mapping: @ControllerAdvice ----------
class DomainError(Exception):
    def __init__(self, code: str, detail: str) -> None:
        self.code, self.detail = code, detail

@app.exception_handler(DomainError)
async def domain_error_handler(_: Request, exc: DomainError) -> JSONResponse:
    return JSONResponse(status_code=409,
                        content={"type": f"https://errors.example.com/{exc.code}",
                                 "title": exc.detail, "status": 409},
                        media_type="application/problem+json")   # RFC 9457

# ---------- endpoints ----------
@app.post("/v1/orders", status_code=status.HTTP_201_CREATED, response_model=OrderOut)
async def create_order(
    body: OrderIn,
    principal: Annotated[Principal, Depends(require_scope("orders:write"))],
    svc: Annotated[OrderService, Depends(get_order_service)],
    response: Response,
) -> Order:
    order = await svc.place(principal.sub, body)
    response.headers["Location"] = f"/v1/orders/{order.id}"
    return order                                     # serialised through OrderOut

@app.get("/v1/orders", response_model=list[OrderOut])
async def list_orders(
    principal: Annotated[Principal, Depends(require_scope("orders:read"))],
    repo: Annotated[OrderRepository, Depends(get_repo)],
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> list[Order]:
    return await repo.list_for(principal.sub, limit, offset)

@app.get("/v1/orders/{order_id}", response_model=OrderOut)
async def get_order(
    order_id: uuid.UUID,                              # path param validated as UUID
    principal: Annotated[Principal, Depends(require_scope("orders:read"))],
    repo: Annotated[OrderRepository, Depends(get_repo)],
) -> Order:
    order = await repo.get(order_id)
    if order is None or order.owner != principal.sub:  # same 404 for "not yours": no enumeration
        raise HTTPException(status.HTTP_404_NOT_FOUND, "order not found")
    return order

@app.get("/healthz", include_in_schema=False)
async def healthz() -> dict[str, str]:
    return {"status": "ok"}

Equivalent Spring wiring for comparison:

@RestController
@RequestMapping("/v1/orders")
class OrderController {
    private final OrderService svc;                       // constructor injection, singleton
    OrderController(OrderService svc) { this.svc = svc; }

    @PostMapping
    @PreAuthorize("hasAuthority('SCOPE_orders:write')")   // Spring Security resource server
    ResponseEntity<OrderOut> create(@Valid @RequestBody OrderIn body, @AuthenticationPrincipal Jwt jwt) {
        Order o = svc.place(jwt.getSubject(), body);
        return ResponseEntity.created(URI.create("/v1/orders/" + o.id())).body(OrderOut.from(o));
    }
}

Note the differences: in Spring, the JWT filter runs in the security filter chain before the controller and populates the SecurityContext; in FastAPI, authentication is a dependency, so it runs only on routes that declare it and appears in the OpenAPI spec as a security requirement. You can still enforce it globally with APIRouter(dependencies=[Depends(get_principal)]).

7.5 Structured LLM output with Pydantic

from typing import Literal
from pydantic import BaseModel, Field, ValidationError

class Ticket(BaseModel):
    category: Literal["billing", "bug", "feature", "other"]
    severity: int = Field(ge=1, le=4, description="1 = critical")
    summary: str = Field(max_length=200)

schema = Ticket.model_json_schema()      # pass to the LLM provider as the response/tool schema

def parse_llm_reply(raw_json: str) -> Ticket | None:
    try:
        return Ticket.model_validate_json(raw_json)   # never trust the model: validate like user input
    except ValidationError as e:
        # feed e.errors() back to the model for one repair attempt, then give up
        print(e.errors(include_url=False))
        return None

print(parse_llm_reply('{"category":"billing","severity":2,"summary":"double charge"}'))
print(parse_llm_reply('{"category":"refund","severity":9,"summary":"x"}'))

Treat LLM output exactly like untrusted HTTP input. The same model gives you the JSON Schema for the request and the validator for the response.

7.6 Streaming responses (Server-Sent Events)

import asyncio
from collections.abc import AsyncIterator
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse

app = FastAPI()

async def token_stream(prompt: str) -> AsyncIterator[str]:
    for tok in ["Hello", " ", "from", " ", "the", " ", "model"]:
        await asyncio.sleep(0.05)                 # an upstream LLM stream in reality
        yield tok

@app.get("/v1/complete")
async def complete(prompt: str, request: Request) -> StreamingResponse:
    async def sse() -> AsyncIterator[bytes]:
        async for tok in token_stream(prompt):
            if await request.is_disconnected():   # stop spending tokens on a gone client
                break
            yield f"data: {tok}\n\n".encode()
        yield b"event: done\ndata: {}\n\n"
    return StreamingResponse(sse(), media_type="text/event-stream",
                             headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"})

Spring equivalent: SseEmitter in MVC or Flux<ServerSentEvent> in WebFlux. In Go you would write to an http.ResponseWriter and call http.Flusher.Flush().

package main

import (
	"encoding/json"
	"log/slog"
	"net/http"
	"os"

func (a *API) listOrders(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")

}

func main() {
	svc := &OrderService{repo: memRepo{}} // "DI container" = main()
	api := &API{svc: svc}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /v1/orders", api.listOrders) // Go 1.22+ method patterns

Go makes wiring explicit and compile-time checked; FastAPI makes it declarative per endpoint and resolved at runtime; Spring makes it container-managed and resolved at startup. Chapter 5.3 develops the Go side fully.

8. Applications: How Teams Use Typing, Pydantic and FastAPI

8.1 Model-serving and LLM gateway APIs

The most common production use of FastAPI in AI teams is a thin, typed HTTP layer in front of a model or an LLM provider: request models define prompts, parameters and limits; response models define the contract consumed by Java or TypeScript clients; OpenAPI is exported and used to generate clients (OpenAPI Generator for Spring's RestClient or WebClient). Teams often generate the Pydantic models from a shared schema (OpenAPI or JSON Schema with datamodel-code-generator) so Java and Python agree on one source of truth.

8.2 Contract layer for agents and tools

Agent frameworks describe tools as typed Python functions or Pydantic models and derive JSON Schema for the LLM. The official OpenAI and Anthropic Python SDKs use Pydantic-based models for their response types. Pydantic AI and instructor use Pydantic models as output types and re-prompt on validation errors. In each case the model is both the specification sent to the LLM and the validator applied to its reply.

8.3 Internal platforms and back-office tools

Platform teams use FastAPI for internal control planes (feature-flag services, experiment registries, incident tooling) because the automatic interactive docs (/docs) reduce the need for a UI in early versions. Netflix's open-source incident-management tool Dispatch is one public example of a FastAPI backend.

8.4 Typed data pipelines

Pydantic validates records entering pipelines (Kafka consumers, file ingestion), and TypedDict/dataclasses type intermediate stages cheaply. Pandera and Pydantic integrations validate DataFrames. The principle: validate at boundaries with Pydantic, keep internals as typed lightweight structures.

8.5 Configuration as code

BaseSettings classes replace ad-hoc os.environ.get calls, giving one typed, validated, documented configuration object per service, the role played by @ConfigurationProperties beans.

9. Case Studies

9.1 Dropbox: gradual typing of 4 million lines

Verified Dropbox's engineering blog (2019) describes adopting mypy incrementally across roughly 4 million lines of Python. Key lessons from that post that apply to any large migration: make the checker fast (they invested in mypy daemon mode and incremental checking), start with the most widely imported modules, and treat type coverage as a tracked metric. The post also explains why they invested in mypyc to compile typed Python to C extensions for speed.

9.2 Netflix Dispatch

Verified Netflix open-sourced Dispatch, its crisis/incident management platform, with a Python backend built on FastAPI and SQLAlchemy (see the repository linked in Further Reading). It is a useful reference for a medium-sized production FastAPI codebase: routers per domain, Pydantic schemas separated from ORM models, and dependency-provided database sessions.

9.3 Pydantic v2's Rust rewrite

Verified The Pydantic team rewrote the validation core in Rust (pydantic-core) for v2, released June 2023, and documented a migration guide covering renamed APIs (parse_obj to model_validate, dict() to model_dump(), validator to field_validator, Config class to model_config). The project reported validation speed-ups of roughly 5x to 50x depending on the workload project-reported. The migration was a major ecosystem event: FastAPI supported both v1 and v2 for a transition period. For Java engineers it is comparable to Jackson 1 to 2 or javax to jakarta: mechanical but broad.

9.4 What to learn from them

  • Type checking pays off at scale only when it is enforced in CI and fast enough to run locally.
  • Separate API schemas (Pydantic) from persistence models (ORM), as Spring teams separate DTOs from entities.
  • Validation libraries are infrastructure: pin versions, plan migrations.

12. Common Mistakes

  1. Sync I/O inside async def (the number-one FastAPI outage cause). Includes sync SQLAlchemy sessions, boto3, requests, and sync LLM SDK clients.
  2. Returning ORM entities without a response model, leaking internal fields; or lazy-loading relationships during serialisation outside the session (the Python twin of LazyInitializationException).
  3. Creating clients per request (httpx.AsyncClient() inside the endpoint): no connection reuse, TLS handshake per call, file descriptor churn. Create once in lifespan.
  4. Mutable default arguments and shared state in dependencies, e.g. a module-level list used as a cache without locks.
  5. Assuming annotations are enforced. def f(x: int) accepts a string at runtime; only Pydantic/FastAPI boundaries validate.
  6. Using Any or dict everywhere, defeating both the checker and OpenAPI.
  7. Accepting the JWT algorithm from the token header or not checking aud/exp: always pin algorithms and require claims.
  8. Committing in yield-dependency teardown and expecting failures to reach the client (default request scope runs teardown after the response).
  9. Route order bugs: /users/me declared after /users/{user_id} is shadowed (first match wins).
  10. Forgetting extra="forbid" on inbound models, allowing clients to send fields like is_admin that later code might trust via **model.model_dump().
  11. Huge validation in the request path (100k-item lists): put bulk ingestion behind streaming or a queue.

13. Production Concerns

13.1 Security

  • AuthN: verify JWTs against a JWKS endpoint (cache keys, respect kid), pin algorithms, validate iss, aud, exp, nbf. In a Spring estate, reuse the same identity provider and scopes so tokens work across both stacks.
  • AuthZ: object-level checks in the service layer (the "not yours = 404" pattern), not just scopes.
  • Input limits: limit request body size at the proxy (FastAPI has no built-in body-size limit), set max lengths in models, bound list sizes.
  • CORS: explicit origins; never allow_origins=["*"] with credentials.
  • Error hygiene: in production, do not echo raw validation input values for sensitive fields; customise the RequestValidationError handler.
  • Docs exposure: disable /docs and /openapi.json on public deployments or protect them.

13.2 Performance

  • Install uvicorn[standard] (uvloop + httptools).
  • Use response_model wisely: serialisation through a model costs CPU; for very large responses, return a pre-serialised Response built with TypeAdapter(...).dump_json() or orjson.
  • Avoid deep dependency trees per request on hot endpoints; each dependency is a function call and possibly a thread hop if sync.
  • Prefer async dependencies for trivial work: a sync dependency costs a thread-pool round trip.

13.3 Reliability and observability

  • Liveness (/healthz, process alive) vs readiness (/readyz, dependencies reachable) exactly as with Spring Actuator probes.
  • OpenTelemetry's FastAPI instrumentation creates server spans per route template; add httpx and SQLAlchemy instrumentation for client spans (Chapter 4.4).
  • Structured JSON logs with request ID from middleware; propagate via contextvars.
  • Graceful shutdown: Uvicorn handles SIGTERM, stops accepting, waits for in-flight requests (configure --timeout-graceful-shutdown), then runs lifespan shutdown.

13.4 Maintainability

  • CI gates: ruff check, ruff format --check, pyright or mypy --strict, tests. Treat type errors as build failures, as javac would.
  • Version your API (/v1), and diff the exported OpenAPI between releases to catch breaking changes (oasdiff or similar).
  • Pin FastAPI, Starlette and Pydantic together with a lockfile (Chapter 4.4).

Exercise 1 · Foundation

Write a typed generic Result[T, E] (success or error) using PEP 695 syntax and show that pyright rejects accessing .value without narrowing.

Solution
from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class Ok[T]:
    value: T

@dataclass(frozen=True, slots=True)
class Err[E]:
    error: E

type Result[T, E] = Ok[T] | Err[E]

def parse_port(s: str) -> Result[int, str]:
    return Ok(int(s)) if s.isdigit() and 0 < int(s) < 65536 else Err(f"bad port {s!r}")

r = parse_port("8080")
# r.value  -> error: "value" is not a known attribute of "Err[str]"
match r:
    case Ok(value=v):  print(v + 1)          # narrowed to Ok[int]
    case Err(error=e): print(e.upper())

Pattern matching narrows the union like a sealed interface plus switch pattern matching in Java 21.

Exercise 2 · Intermediate

Model a payment request with a discriminated union: card (PAN last four, expiry), sepa (IBAN), wallet (provider literal). Validate with model_validate_json and produce JSON Schema.

Solution
from typing import Annotated, Literal
from pydantic import BaseModel, Field, TypeAdapter

class Card(BaseModel):
    type: Literal["card"]
    last4: Annotated[str, Field(pattern=r"^\d{4}$")]
    exp: Annotated[str, Field(pattern=r"^(0[1-9]|1[0-2])/\d{2}$")]

class Sepa(BaseModel):
    type: Literal["sepa"]
    iban: Annotated[str, Field(min_length=15, max_length=34)]

class Wallet(BaseModel):
    type: Literal["wallet"]
    provider: Literal["apple", "google"]

Method = Annotated[Card | Sepa | Wallet, Field(discriminator="type")]

class Payment(BaseModel):
    amount_cents: Annotated[int, Field(gt=0)]
    method: Method

p = Payment.model_validate_json(b'{"amount_cents": 500, "method": {"type": "wallet", "provider": "apple"}}')
print(type(p.method).__name__)          # Wallet
print(TypeAdapter(Payment).json_schema()["properties"]["method"])   # oneOf + discriminator mapping

The discriminator makes validation O(1) in the number of variants and produces clearer errors (only the selected variant's errors are reported), like Jackson's @JsonTypeInfo(use = NAME, property = "type").

Exercise 3 · Advanced

Implement a tenant-aware dependency: read X-Tenant-ID, verify it matches a tenants claim in the JWT, store it in a ContextVar for logging, and guarantee it is reset after the request. Write a test using overrides.

Solution
from contextvars import ContextVar
from collections.abc import AsyncIterator
from typing import Annotated
from fastapi import Depends, Header, HTTPException

current_tenant: ContextVar[str | None] = ContextVar("current_tenant", default=None)

async def tenant_scope(
    x_tenant_id: Annotated[str, Header()],
    principal: Annotated["Principal", Depends(get_principal)],
) -> AsyncIterator[str]:
    if x_tenant_id not in principal.tenants:
        raise HTTPException(403, "tenant not allowed")
    token = current_tenant.set(x_tenant_id)
    try:
        yield x_tenant_id
    finally:
        current_tenant.reset(token)       # no leakage between requests/tasks

Test: override get_principal with a principal whose tenants contains "t1", call with header t1 (200) and t2 (403). Because each request runs in its own task with a copied context, ContextVar values do not leak even without the reset, but resetting is correct hygiene for sync paths and nested scopes.

Exercise 4 · Advanced

A def endpoint performs a 50 ms synchronous DB query. Load tests show throughput flat at about 800 req/s per worker regardless of DB capacity. Explain the ceiling and fix it.

Solution

The AnyIO limiter allows 40 concurrent sync calls; by Little's Law the ceiling is \( 40 / 0.05 = 800 \) req/s. Options: raise total_tokens (while sizing the DB pool to match and watching GIL contention), or switch to an async driver and async def, which bounds concurrency by the pool instead of threads. Also consider adding more worker processes if CPU allows.

Exercise 5 · Expert

Solution

Pick one source of truth. Option 1, code-first in FastAPI: export app.openapi() in CI to a versioned artifact, generate the Java client with OpenAPI Generator, and fail CI on breaking changes via an OpenAPI diff tool. Option 2, spec-first: hand-maintained OpenAPI/JSON Schema in a contracts repo, generate Pydantic models (datamodel-code-generator) and Java DTOs from it. Add consumer-driven contract tests (Pact) for critical interactions. Version with URL major versions and additive-only minor changes; deprecate with Sunset headers. For events (Kafka), use a schema registry with compatibility rules (Chapter 4.4).

15. Interview Questions

Conceptual Are Python type hints enforced at runtime?

No. The interpreter stores them (lazily since 3.14) but does not check them. Static checkers verify them before runtime; libraries like Pydantic and FastAPI read them to perform runtime validation at boundaries.

Conceptual Protocol vs ABC: when do you use which?

Protocol for structural typing: consumers declare what they need, implementations need not know about it (like Go interfaces), ideal for ports and third-party types. ABC for nominal hierarchies with shared implementation and runtime enforcement of abstract methods at instantiation (like Java abstract classes).

Conceptual Why is Pydantic v2 much faster than v1?

Validation and serialisation logic is compiled once per type into a tree of Rust validators/serializers (pydantic-core); JSON can be parsed and validated in one pass without intermediate Python objects. v1 executed Python code per field.

Architecture How does FastAPI's DI differ from Spring's, and what do you lose?

FastAPI resolves a per-endpoint graph of provider functions at request time with per-request caching and generator-based teardown; there is no global container, no component scanning, no AOP, no lifecycle for arbitrary singletons. You gain explicitness and easy overrides; you lose declarative transactions, interceptors on arbitrary beans and auto-configuration. Long-lived objects come from lifespan and app.state.

Architecture Where should authentication live in a FastAPI service?

Token verification as a dependency on routers (so it composes with scopes and appears in OpenAPI), coarse transport checks (mTLS, IP) in middleware or the gateway, and object-level authorisation in the service layer. Keep the identity provider and scope names shared with Spring services.

Coding Write a dependency that provides an async DB session per request and rolls back on error.
async def get_session(request: Request) -> AsyncIterator[AsyncSession]:
    async with request.app.state.sessionmaker() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise

Mention the teardown-timing caveat (default request scope runs after the response) and that many teams commit explicitly in the service instead.

Scenario After adding an async endpoint that calls an internal SDK, all endpoints' p99 jumps. Diagnose.

The SDK is synchronous and blocks the event loop. Confirm with loop-lag metrics, py-spy dump showing the loop thread inside a socket read, or asyncio debug slow-callback logs. Fix by declaring the endpoint def, wrapping the call in asyncio.to_thread, or using an async SDK.

Scenario Your OpenAPI-generated Java client broke after a Python release that "only renamed an internal field". What happened and how do you prevent it?

The field was part of a response model, so the schema changed. Prevent with response models separated from internal models, explicit aliases for wire names, OpenAPI diff checks in CI, and contract tests.

Behavioral How would you introduce strict typing into an untyped 200k-line Python service?

Baseline the checker with existing errors suppressed per module, enforce strictness on new and touched files, type the most-imported modules first, add stubs for key dependencies, measure coverage over time, and run the checker in CI and pre-commit. Communicate wins (bugs caught) to keep momentum, as Dropbox did.

16. Knowledge Check

  • Python typing is gradual and unchecked at runtime; strict mypy/pyright in CI is your compiler.
  • Protocols give Go-style structural interfaces; ParamSpec keeps decorators typed; Annotated carries metadata for frameworks.
  • Pydantic v2 compiles schemas into Rust validators; use declarative constraints and model_validate_json for speed.
  • FastAPI = Starlette (ASGI, routing, middleware) + Pydantic + per-endpoint DI + OpenAPI.
  • async def runs on the loop; def runs in a 40-thread pool by default.
  • Long-lived resources belong in lifespan; per-request resources in yield dependencies; overrides replace them in tests.

  4. In a new thread created per request
