Part 3 · Chapter 3

Two Pointers, Sliding Window, Sorting & Binary Search

Order is information. Once data is sorted, a linear scan with two pointers replaces nested loops, binary search replaces scans, and a whole class of "find the minimum feasible X" problems becomes a logarithmic search over the answer. This chapter builds the sorting algorithms that create order (and proves why Θ(n log n) is optimal for comparison sorts), dissects what Arrays.sort, list.sort() and Go's slices.Sort actually run, then turns to the three scanning patterns that exploit order: binary search, two pointers and sliding windows.

  • Prerequisites: Chapter 3.1 (complexity, recurrences, prefix sums).
  • You will be able to: implement and analyse insertion, merge, quick, heap, counting and radix sort; explain stability and the comparison lower bound; write bug-free binary searches with explicit invariants (including on answer spaces and rotated arrays); and apply two-pointer and sliding-window templates to substring and subarray problems.

1. Introduction: Exploiting Order

Many brute-force solutions examine all pairs or all subarrays: Θ(n²) or worse. The techniques in this chapter cut that down by exploiting monotonicity — a property that lets you discard many candidates with one comparison:

  • Sorting establishes order so later steps can be monotone. It is also the most common preprocessing step in interviews ("sort, then…").
  • Binary search exploits a monotone predicate: if the predicate is false at x it is false everywhere to the left. Each probe discards half the candidates — on array indices, or on an abstract answer range such as "minimum capacity", "smallest time", "largest minimum distance".
  • Two pointers exploit order between two positions: in a sorted array, if a[i] + a[j] is too big, no pair using j with any index ≥ i can work, so j moves inward.
  • Sliding windows exploit monotonicity of a window property under extension and shrinking (e.g. "a window with a repeated character still has one if extended"), so each element enters and leaves the window once.

The meta-skill an interviewer looks for: articulate the invariant ("everything left of lo fails the predicate", "the window never contains a duplicate") and argue why moving a pointer cannot skip an answer.

2. History

  • 1945 — Merge sort. John von Neumann wrote a merge-sort program for the EDVAC; it is among the first programs written for a stored-program computer.
  • 1946 — Binary search was described by John Mauchly in the Moore School Lectures. Correct implementations proved elusive: until D. H. Lehmer's 1960 version, published algorithms worked only for array lengths of the form 2k − 1, and in 2006 Joshua Bloch reported that the midpoint overflow bug affected Arrays.binarySearch in the JDK for nearly a decade.
  • 1887–1954 — Radix sort. Herman Hollerith's tabulating machines sorted punched cards digit by digit (1880s–1890s); Harold Seward formalised radix and counting sort for computers at MIT in 1954.
  • 1959–1961 — Quicksort. Tony Hoare invented quicksort in Moscow in 1959 and published it (with Quickselect, "Find") in 1961–1962.
  • 1964 — Heapsort. J. W. J. Williams introduced the binary heap and heapsort; Robert Floyd gave the linear-time bottom-up heap construction the same year.
  • 1973 — Linear-time selection. Blum, Floyd, Pratt, Rivest and Tarjan published the median-of-medians algorithm, deterministic Θ(n) selection.
  • 1997 — Introsort. David Musser's introspective sort switches from quicksort to heapsort when recursion gets too deep, guaranteeing O(n log n); it became the basis of C++ std::sort.
  • 2002 — Timsort. Tim Peters designed Timsort for Python 2.3: a stable, adaptive merge sort that detects runs. Java 7 (2011) adopted it for object sorts.
  • 2009–2011 — Dual-pivot quicksort. Vladimir Yaroslavskiy's dual-pivot quicksort replaced the classic single-pivot sort for Java primitives in JDK 7; it was substantially reworked again in JDK 14.
  • 2015 — Timsort bug. Stijn de Gouw and colleagues, attempting to formally verify Java's TimSort with the KeY prover, found that its merge-stack invariant could be violated, causing an ArrayIndexOutOfBoundsException for specially crafted large inputs.
  • 2018–2022 — Powersort and pdqsort. Ian Munro and Sebastian Wild published powersort's nearly optimal merge policy (ESA 2018), adopted by CPython 3.11. Orson Peters's pattern-defeating quicksort (2016–2021) became Rust's unstable sort and Go's sort.Sort in Go 1.19 (2022).

3. Fundamentals

3.1 Sorting vocabulary

  • Stable: equal keys keep their input order. Needed for multi-key sorts done as successive passes (sort by date, then stable-sort by customer → grouped by customer, dates in order) and for radix sort's correctness.
  • In-place: O(1) (or O(log n) stack) extra memory.
  • Adaptive: faster on partially sorted input (insertion sort, Timsort).
  • Comparison-based: only learns about keys through comparisons — subject to the Ω(n log n) lower bound. Distribution sorts (counting, radix, bucket) inspect key digits and can beat it.
  • Inversions: pairs i < j with a[i] > a[j]. A sorted array has 0; a reversed one has n(n−1)/2. Insertion sort's running time is Θ(n + inversions).

3.2 Insertion sort

Concept: grow a sorted prefix; insert each new element into place by shifting larger elements right — how you sort a hand of cards. Internals: each shift removes exactly one inversion. Complexity: best Θ(n) (sorted), worst/average Θ(n²), Θ(1) extra space, stable, adaptive, online. Why it matters: for tiny arrays (n ≲ 16–48) its low overhead beats everything, so every production hybrid sort (TimSort, dual-pivot quicksort, pdqsort, introsort) finishes small partitions with insertion sort (TimSort uses binary insertion sort to cut comparisons).

[5 | 2 4 6 1 3]   sorted prefix | rest
[2 5 | 4 6 1 3]   2 shifts past 5
[2 4 5 | 6 1 3]
[2 4 5 6 | 1 3]   6 stays
[1 2 4 5 6 | 3]   1 shifts past four elements
[1 2 3 4 5 6 |]   3 shifts past three

3.3 Merge sort

Concept: divide in half, sort each half recursively, merge two sorted halves with two pointers. Internals: the merge takes the smaller head each step; taking from the left on ties makes it stable. Complexity: T(n) = 2T(n/2) + Θ(n) = Θ(n log n) in every case; Θ(n) auxiliary array; stable; not adaptive in its basic form (natural merge sort and Timsort are). Strengths: predictable, stable, parallelisable, and sequential-access friendly — so it is the algorithm for linked lists and for external sorting of data larger than memory (sort runs that fit in RAM, then k-way merge them with a heap).

             [38 27 43 3 9 82 10]
          [38 27 43]        [3 9 82 10]
        [38] [27 43]       [3 9]  [82 10]
             [27][43]     [3][9]  [82][10]
        merge: [27 43]     [3 9]   [10 82]
        [27 38 43]         [3 9 10 82]
             [3 9 10 27 38 43 82]

3.4 Quicksort

Concept: pick a pivot, partition so that smaller elements precede it and larger follow, recurse on both sides. The work happens before recursion (partitioning) whereas merge sort works after (merging).

Partition schemes: Lomuto keeps one boundary and swaps small elements behind it — simple, but degrades to Θ(n²) on many duplicates. Hoare scans inward from both ends swapping out-of-place pairs — about three times fewer swaps on average. Three-way (Dijkstra's Dutch national flag) splits into <, =, > regions, making arrays with many equal keys linear. Pivot choice: a fixed first/last element makes sorted input the worst case; random pivots give expected Θ(n log n) for every input; median-of-three (or "ninther") reduces the constant. Complexity: expected Θ(n log n), worst Θ(n²), Θ(log n) expected stack if you recurse on the smaller side first and loop on the larger (guaranteeing O(log n) stack even in the worst case). Not stable. Its practical speed comes from in-place sequential scans with excellent locality and few data moves.

Introsort / pdqsort fix the worst case: track recursion depth and switch to heapsort beyond ~2 log₂ n levels. pdqsort adds detection of already-sorted runs and of bad partitions, shuffling elements to break adversarial patterns.

3.5 Heapsort

Build a max-heap in Θ(n) (bottom-up sift-down), then repeatedly swap the root with the last element and sift down: Θ(n log n) worst case, Θ(1) extra space, not stable, poor cache behaviour (sift-down jumps between i and 2i+1). It is the safety net inside introsort and Java's JDK 14+ dual-pivot quicksort. Heap internals are covered in Chapter 4.

3.6 The comparison-sort lower bound

Any comparison sort can be modelled as a binary decision tree: internal nodes are comparisons, leaves are output permutations. To sort every input correctly the tree needs at least n! leaves, and a binary tree of height h has at most 2ʰ leaves, so h ≥ log₂(n!) = Θ(n log n). The height is the worst-case number of comparisons. The same argument applies to the average case (the average leaf depth of a tree with n! leaves is ≥ log₂ n!). Merge sort and heapsort are therefore asymptotically optimal; to beat n log n you must use more than comparisons.

3.7 Counting, radix and bucket sort

Counting sort: for integer keys in [0, k), count occurrences, prefix-sum the counts to get each key's starting position, then place elements (iterating input in order — backwards if filling from the ends — to stay stable). Θ(n + k) time and space. Great when k = O(n): ages, HTTP status codes, small enums, characters.

Radix sort (LSD): sort by the least significant digit with a stable counting sort, then the next digit, and so on. Stability preserves the order established by lower digits. With d digits in base b: Θ(d(n + b)). For 32-bit integers using base 2⁸, d = 4 passes over the data — linear time, which beats comparison sorts for large n of fixed-width keys. MSD radix sort recurses from the most significant digit and suits strings (it can stop early once prefixes differ). Negative numbers need an offset or a flipped sign bit.

Bucket sort: for keys roughly uniform in [0, 1), distribute into n buckets, sort each (insertion sort), concatenate: expected Θ(n). Used for floating-point data with known distribution and in "Maximum Gap" (pigeonhole argument).

3.8 Selection: k-th smallest

Quickselect partitions like quicksort but recurses into only the side containing the k-th position: expected T(n) = T(n/2) + Θ(n) = Θ(n), worst Θ(n²). Median-of-medians guarantees Θ(n) worst case but with a large constant; introselect falls back to it. Alternatives: a size-k heap, Θ(n log k), which also works on streams (Chapter 4). C++ nth_element is introselect; Java has no built-in selection — use a heap or sort.

3.9 Binary search on a sorted array

Think of binary search as finding the boundary of a monotone predicate over indices: P(i) is false…false, true…true, and we want the first true. With a half-open interval [lo, hi) and the invariant "the first true lies in [lo, hi]" (where hi = n means "none"):

lo = 0, hi = n
while lo < hi:
    mid = lo + (hi - lo) / 2        # never overflows; mid in [lo, hi)
    if P(mid): hi = mid             # answer is mid or to the left
    else:      lo = mid + 1         # answer is strictly right of mid
return lo                           # first index with P true, or n
  • lower_bound(x): P(i) = a[i] ≥ x — first position where x could be inserted keeping order (Python bisect_left).
  • upper_bound(x): P(i) = a[i] > x (bisect_right). The count of x equals upper − lower; the last occurrence is upper − 1.
  • Exact search: lower_bound, then check a[lo] == x.

The loop always terminates because the interval strictly shrinks (mid < hi, so hi = mid shrinks it; lo = mid + 1 shrinks it). Most binary-search bugs come from mixing closed and half-open conventions, e.g. while (lo <= hi) with hi = mid (infinite loop) — pick one convention and keep it.

3.10 Binary search on the answer space

When the question is "the minimum X such that feasible(X)" and feasibility is monotone (if X works, every larger X works), binary search X over its numeric range and test feasibility with a greedy or linear check. Complexity: Θ(log(range) × cost(feasible)). Classic instances: minimum eating speed to finish piles within h hours, minimum ship capacity to deliver in d days, minimise the largest sum when splitting an array into k parts, maximise the minimum distance between placed items ("aggressive cows"), smallest divisor under a threshold, k-th smallest in a sorted matrix or multiplication table (count elements ≤ X). Real-valued answers use a fixed number of iterations (e.g. 100) instead of a lo < hi test.

3.11 Rotated sorted arrays and other partial orders

A sorted array rotated at an unknown pivot is two sorted runs. At any mid, at least one of [lo, mid] or [mid, hi] is sorted; decide which by comparing with an endpoint, check whether the target lies within the sorted half's range, and discard the other half. Finding the minimum compares a[mid] with a[hi]: if a[mid] > a[hi] the minimum is right of mid. With duplicates, a[mid] == a[hi] gives no information — shrink hi by one, degrading to Θ(n) worst case. Related: peak finding in an array where neighbours differ (move toward the larger neighbour — a peak must exist on that side), searching a row- and column-sorted matrix (start at the top-right corner: Θ(m + n) staircase walk).

3.12 Two pointers

Three shapes:

  1. Opposite ends on sorted data: pair-sum problems (if the sum is too small, only increasing i can help), container with most water (move the shorter wall — the taller cannot produce a larger area with a narrower width), palindrome checks, 3Sum (fix one, two-pointer the rest: Θ(n²)).
  2. Same direction (read/write): a slow write pointer and a fast read pointer for in-place filtering — remove duplicates, move zeroes, compact arrays. This is how ArrayList.removeIf compacts in one pass.
  3. Two sequences: merge two sorted arrays, intersection of sorted lists (posting-list intersection in search engines), subsequence checks.

Partitioning (Dutch national flag) is a three-pointer generalisation: low/mid/high regions for <, =, >.

3.13 Sliding windows

A window is a contiguous range [l, r]. Fixed-size windows slide by adding a[r] and removing a[r−k] (moving average, max sum of k consecutive, anagram occurrences with a count array). Variable-size windows expand r every step and shrink l while the window is invalid (for "longest valid" problems) or while it remains valid (for "shortest valid" problems). Both pointers only move right, so total work is Θ(n) plus the cost of maintaining window state (counts in an array or map, a monotonic deque for extrema).

Precondition — monotonicity: if a window is invalid, every larger window containing it is invalid too (or, for "shortest", if valid then every superset is valid). "Sum ≤ S with non-negative numbers", "at most k distinct characters" and "no repeated characters" satisfy it; "sum exactly k with negatives" does not (use prefix sums). "Exactly k" trick: exactly(k) = atMost(k) − atMost(k − 1), turning a non-monotone condition into two monotone ones.

4. Internal Working: What Your Standard Library Actually Runs

4.1 Java: Arrays.sort for primitives (dual-pivot quicksort)

For int[], long[], double[] etc., Arrays.sort runs java.util.DualPivotQuicksort. Two pivots P1 ≤ P2 split the array into three parts (< P1, between, > P2), which reduces the number of passes over memory compared with single-pivot quicksort. Since the JDK 14 rewrite, the implementation also: sorts tiny ranges with insertion sort (and "mixed insertion sort" for small-to-medium ranges), detects and merges pre-existing runs (so nearly sorted data is fast), falls back to heapsort when recursion becomes too deep (guaranteeing O(n log n)), and in Arrays.parallelSort uses parallel merging. float/double sorts handle −0.0 and NaN specially so that the result matches Double.compare ordering. Stability is meaningless for primitives (equal values are indistinguishable). Version-sensitive · checked Nov 2026

4.2 Java: Arrays.sort for objects and List.sort (TimSort)

For Object[] and therefore Collections.sort and List.sort (ArrayList.sort sorts its backing array directly), the JDK uses java.util.TimSort (or ComparableTimSort) — stable, as the specification of Arrays.sort(Object[]) requires:

  1. Compute minRun (between 16 and 32 for large arrays) so that n/minRun is close to a power of two.
  2. Scan for natural runs: maximal ascending or strictly descending sequences (descending ones are reversed in place — strictness keeps stability). Short runs are extended to minRun with binary insertion sort.
  3. Push runs on a stack and merge adjacent runs to maintain invariants on their lengths (roughly Fibonacci-like growth), which bounds the stack to O(log n) and keeps merges balanced. The 2015 verification work found the original invariant check incomplete; OpenJDK enlarged the stack bound rather than changing the merge rule.
  4. Merge with a temporary array the size of the smaller run, using galloping: when one run "wins" many times in a row, switch to exponential search to find how many elements to copy in bulk.

Consequences: Θ(n) on already-sorted or reverse-sorted input, Θ(n log n) worst case, up to n/2 extra references. A comparator that violates the contract (not transitive, inconsistent) can cause the famous IllegalArgumentException: Comparison method violates its general contract! — TimSort detects some inconsistencies during merging.

4.3 Python: Timsort with the powersort merge policy

CPython's list.sort is the original Timsort (run detection, binary insertion, galloping merges). In Python 3.11 Tim Peters replaced the ad-hoc stack-merging rules with Munro and Wild's powersort policy: each run boundary gets a "power" computed from the run's midpoint position, and runs are merged so that the merge tree is nearly optimal with respect to run lengths. The detailed design notes live in Objects/listsort.txt. sorted(key=...) computes each key once (decorate-sort-undecorate internally), so an expensive key function is called n times, not n log n. Version-sensitive · checked Nov 2026

4.4 Go: pattern-defeating quicksort

Since Go 1.19, sort.Sort, sort.Slice and later slices.Sort use pdqsort: an introsort descendant with insertion sort for small slices, ninther pivot selection, detection of already partitioned inputs, deliberate shuffling when partitions are unbalanced, and a heapsort fallback. Unstable — use sort.Stable or slices.SortStableFunc (insertion-sorted blocks merged with SymMerge, in place).

4.5 Library binary searches

  • Arrays.binarySearch(a, key) returns the index if found, otherwise −(insertionPoint) − 1. With duplicates it returns some matching index, not necessarily the first. Its midpoint is (low + high) >>> 1, the fix Bloch described.
  • Collections.binarySearch on a LinkedList uses an iterator-based search: O(log n) comparisons but O(n) traversal.
  • TreeMap.ceilingKey/floorKey give lower/upper-bound semantics on a dynamic sorted set (Chapter 4).
  • Python bisect_left/bisect_right are exactly lower/upper bound; insort inserts keeping order (O(n) due to shifting).
  • Go sort.Search(n, pred) returns the first index where the predicate is true — the predicate formulation of §3.9.

4.6 Quicksort partition, traced (Hoare-style with random pivot = 4)

a = [7 2 4 9 1 4 8 3]   pivot value 4
i scans right for a[i] >= 4, j scans left for a[j] <= 4, swap, continue

i=0 (7)  j=7 (3)  swap -> [3 2 4 9 1 4 8 7]
i=2 (4)  j=5 (4)  swap -> [3 2 4 9 1 4 8 7]   (equal keys swap: keeps splits balanced)
i=3 (9)  j=4 (1)  swap -> [3 2 4 1 9 4 8 7]
i=4 (9)  j=3 (1)  i > j stop: left = a[0..3] all <= 4, right = a[4..7] all >= 4
recurse on [3 2 4 1] and [9 4 8 7]

Stopping on equal keys (≥ / ≤ rather than > / <) looks wasteful but is what keeps Hoare partitioning balanced on arrays of identical values; Lomuto partitioning on such input puts everything on one side and goes quadratic.

5. Architecture: Seeing the Algorithms Move

What to try: run insertion sort on a nearly sorted array and then on a reversed one, and count the steps — that is the Θ(n + inversions) bound made visible. Run quicksort and watch partitions shrink around each pivot; notice how much of the work happens in long sequential sweeps (why it is cache-friendly). Run merge sort and observe that the amount of work per level is the same regardless of input order. Run heap sort and see the large "jumps" between parent and child positions, the reason it loses to quicksort in practice despite its better worst case.

Reading the diagram: the first branch is the only way to beat n log n — exploit key structure. The memory branch is where databases live: PostgreSQL switches from in-memory quicksort to an external merge sort when the data exceeds work_mem. Stability is the next decisive property; the JDK's split (TimSort for objects, quicksort for primitives) is exactly this decision.

Reading the diagram: everything problem-specific is inside P. For lower_bound, P(i) is a[i] ≥ x; for "minimum capacity", the indices are capacities and P is "can ship within d days". For a rotated array, P(i) is a[i] ≤ a[n−1] (first index of the second run = the minimum). Memorise this loop once and you avoid off-by-one debugging under interview pressure.

Reading the diagram: r advances every iteration; l advances only inside Shrink. Because neither moves left, the two states together execute at most 2n transitions. For "shortest valid window" problems the roles flip: shrink while valid, recording the best before each shrink.

6. The Math

6.1 Insertion sort and inversions

Each inner-loop shift swaps an adjacent inverted pair, removing exactly one inversion, so running time is Θ(n + I). For a uniformly random permutation each of the \(\binom{n}{2}\) pairs is inverted with probability ½, so \(E[I] = n(n-1)/4\) — average Θ(n²). The same fact shows that any algorithm that only swaps adjacent elements (bubble sort, insertion sort) is Ω(n²) on average.

6.2 Comparison lower bound, quantitatively

\[ \log_2 n! = \sum_{i=1}^{n} \log_2 i \ \ge\ \frac{n}{2}\log_2\frac{n}{2} = \Omega(n \log n), \qquad \log_2 n! = n\log_2 n - n\log_2 e + O(\log n) \]

So any comparison sort needs about n log₂ n − 1.44n comparisons in the worst case. Merge sort uses at most n⌈log₂ n⌉ − 2⌈log₂ n⌉ + 1, within a lower-order term of optimal. For n = 10⁶, log₂ n! ≈ 1.85 × 10⁷ comparisons.

6.3 Quicksort's expected cost

Intuition: elements i and j (in sorted order) are compared only if one of them is the first pivot chosen among the j − i + 1 elements between them; that happens with probability 2/(j − i + 1). Summing over pairs:

\[ E[C] = \sum_{i \lt j} \frac{2}{j-i+1} = 2(n+1)H_n - 4n \approx 2n\ln n \approx 1.39\, n\log_2 n \]

About 39% more comparisons than merge sort, yet faster in practice because of in-place sequential partitioning. Worst case: the pivot is always the extreme, T(n) = T(n−1) + Θ(n) = Θ(n²). The probability that randomized quicksort exceeds c·n log n comparisons decays rapidly in c, so the worst case is a theoretical rather than practical concern — unless an adversary knows your pivot rule (McIlroy's 1999 "A Killer Adversary for Quicksort" constructs such inputs on the fly).

6.4 Distribution sorts

Counting sort: Θ(n + k). Radix sort with d digits in base b: Θ(d(n + b)); for w-bit keys choose b = 2ʳ, d = ⌈w/r⌉, total Θ((w/r)(n + 2ʳ)); with r ≈ log₂ n this is Θ(wn / log n) — linear for fixed w. Illustrative For n = 10⁷ 32-bit integers with r = 8: 4 passes × (10⁷ + 256) operations ≈ 4 × 10⁷, versus ≈ 2.3 × 10⁸ comparisons for a comparison sort — though memory traffic, not operation count, usually decides the real winner.

6.5 Binary search

Each iteration at least halves the interval, so at most ⌈log₂(n + 1)⌉ iterations: 20 for a million elements, 30 for a billion, 64 for any long range. For search on an answer range [L, H] with feasibility cost F: Θ(F · log₂(H − L)). For a real-valued answer with tolerance ε: ⌈log₂((H − L)/ε)⌉ iterations — 100 iterations reduce any double-precision interval to its last bit.

Midpoint overflow: with 32-bit ints, lo + hi overflows once lo + hi > 2³¹ − 1, i.e. for arrays over about 1.07 billion elements (in Bloch's report, the sum became negative). Use lo + (hi − lo) / 2 or (lo + hi) >>> 1 (the unsigned shift treats the overflowed sum as an unsigned 32-bit number, which is correct for non-negative lo, hi).

6.6 Two pointers and windows: why linear

In opposite-ends two pointers, j − i decreases by one per step: at most n − 1 steps. In a sliding window, l and r are each non-decreasing and bounded by n: at most 2n pointer moves. With a hash map for window state, the total is Θ(n) expected; with an alphabet-sized array, Θ(n + σ).

6.7 3Sum lower bound intuition

3Sum is solvable in Θ(n²) by sort + two pointers. It was long conjectured that no Θ(n2−ε) algorithm exists; the conjecture in its strongest form was refuted in 2014 (Grønlund and Pettie showed slightly subquadratic algorithms), but a "3SUM-hardness" family of geometric problems is still used to argue that quadratic is essentially the best you can do. In an interview, Θ(n²) is the expected answer.

7. Code

7.1 Sorting algorithms

import java.util.Arrays;
import java.util.Random;
import java.util.concurrent.ThreadLocalRandom;

public final class Sorts {

    static void insertionSort(int[] a, int lo, int hi) {          // sorts a[lo..hi]
        for (int i = lo + 1; i <= hi; i++) {
            int x = a[i], j = i - 1;
            while (j >= lo && a[j] > x) { a[j + 1] = a[j]; j--; } // shift; strict > keeps it stable
            a[j + 1] = x;
        }
    }

    /** Top-down merge sort with one reusable buffer and an insertion-sort cutoff. Stable. */
    static void mergeSort(int[] a) {
        int[] buf = new int[a.length];
        mergeSort(a, buf, 0, a.length - 1);
    }
    private static void mergeSort(int[] a, int[] buf, int lo, int hi) {
        if (hi - lo < 16) { insertionSort(a, lo, hi); return; }
        int mid = (lo + hi) >>> 1;
        mergeSort(a, buf, lo, mid);
        mergeSort(a, buf, mid + 1, hi);
        if (a[mid] <= a[mid + 1]) return;                           // already in order: adaptive shortcut
        System.arraycopy(a, lo, buf, lo, hi - lo + 1);
        int i = lo, j = mid + 1;
        for (int k = lo; k <= hi; k++) {
            if (i > mid) a[k] = buf[j++];
            else if (j > hi) a[k] = buf[i++];
            else if (buf[j] < buf[i]) a[k] = buf[j++];              // take left on ties: stable
            else a[k] = buf[i++];
        }
    }

    /** Randomized 3-way quicksort (Dijkstra partition); recurse on smaller side to bound stack. */
    static void quickSort(int[] a) { quickSort(a, 0, a.length - 1); }
    private static void quickSort(int[] a, int lo, int hi) {
        while (hi - lo >= 16) {
            int p = a[ThreadLocalRandom.current().nextInt(lo, hi + 1)];
            int lt = lo, i = lo, gt = hi;                            // a[lo..lt-1] < p, a[lt..i-1] == p, a[gt+1..hi] > p
            while (i <= gt) {
                if (a[i] < p) swap(a, lt++, i++);
                else if (a[i] > p) swap(a, i, gt--);
                else i++;
            }
            if (lt - lo < hi - gt) { quickSort(a, lo, lt - 1); lo = gt + 1; }   // smaller side first
            else { quickSort(a, gt + 1, hi); hi = lt - 1; }
        }
        insertionSort(a, lo, hi);
    }

    /** In-place heapsort: bottom-up heapify Theta(n), then n sift-downs. */
    static void heapSort(int[] a) {
        int n = a.length;
        for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n);
        for (int end = n - 1; end > 0; end--) { swap(a, 0, end); siftDown(a, 0, end); }
    }
    private static void siftDown(int[] a, int i, int n) {
        while (true) {
            int l = 2 * i + 1, r = l + 1, big = i;
            if (l < n && a[l] > a[big]) big = l;
            if (r < n && a[r] > a[big]) big = r;
            if (big == i) return;
            swap(a, i, big); i = big;
        }
    }

    /** Stable counting sort for keys in [0, k). */
    static int[] countingSort(int[] a, int k) {
        int[] count = new int[k + 1];
        for (int x : a) count[x + 1]++;
        for (int i = 0; i < k; i++) count[i + 1] += count[i];        // count[v] = start index of v
        int[] out = new int[a.length];
        for (int x : a) out[count[x]++] = x;                         // left-to-right keeps stability
        return out;
    }

    /** LSD radix sort on 32-bit ints, 8 bits per pass; flips the sign bit so negatives sort first. */
    static void radixSort(int[] a) {
        int[] buf = new int[a.length];
        for (int shift = 0; shift < 32; shift += 8) {
            int[] count = new int[257];
            for (int x : a) count[(((x ^ Integer.MIN_VALUE) >>> shift) & 0xFF) + 1]++;
            for (int i = 0; i < 256; i++) count[i + 1] += count[i];
            for (int x : a) buf[count[((x ^ Integer.MIN_VALUE) >>> shift) & 0xFF]++] = x;
            System.arraycopy(buf, 0, a, 0, a.length);
        }
    }

    /** Quickselect: k-th smallest (0-based), expected Theta(n). */
    static int quickSelect(int[] a, int k) {
        int lo = 0, hi = a.length - 1;
        while (true) {
            int p = a[ThreadLocalRandom.current().nextInt(lo, hi + 1)];
            int lt = lo, i = lo, gt = hi;
            while (i <= gt) {
                if (a[i] < p) swap(a, lt++, i++);
                else if (a[i] > p) swap(a, i, gt--);
                else i++;
            }
            if (k < lt) hi = lt - 1;
            else if (k > gt) lo = gt + 1;
            else return p;                                           // k falls in the == block
        }
    }

    private static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }

    public static void main(String[] args) {
        var rnd = new Random(42);
        for (int trial = 0; trial < 200; trial++) {
            int n = rnd.nextInt(2000);
            int[] base = rnd.ints(n, -1000, 1000).toArray(), want = base.clone();
            Arrays.sort(want);
            int[] m = base.clone(); mergeSort(m);
            int[] q = base.clone(); quickSort(q);
            int[] h = base.clone(); heapSort(h);
            int[] r = base.clone(); radixSort(r);
            int[] c = Arrays.stream(base).map(x -> x + 1000).toArray();
            int[] cs = Arrays.stream(countingSort(c, 2000)).map(x -> x - 1000).toArray();
            for (int[] got : new int[][]{m, q, h, r, cs})
                if (!Arrays.equals(got, want)) throw new AssertionError("trial " + trial);
            if (n > 0 && quickSelect(base.clone(), n / 2) != want[n / 2]) throw new AssertionError("select");
        }
        System.out.println("all sorts agree with Arrays.sort");
    }
}
import random

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if right[j] < left[i]:
            out.append(right[j]); j += 1
        else:                       # ties take left: stable
            out.append(left[i]); i += 1
    out.extend(left[i:]); out.extend(right[j:])
    return out

def quick_sort(a, lo=0, hi=None):
    """In-place randomized 3-way quicksort."""
    hi = len(a) - 1 if hi is None else hi
    while lo < hi:
        p = a[random.randint(lo, hi)]
        lt, i, gt = lo, lo, hi
        while i <= gt:
            if a[i] < p:
                a[lt], a[i] = a[i], a[lt]; lt += 1; i += 1
            elif a[i] > p:
                a[i], a[gt] = a[gt], a[i]; gt -= 1
            else:
                i += 1
        if lt - lo < hi - gt:
            quick_sort(a, lo, lt - 1); lo = gt + 1
        else:
            quick_sort(a, gt + 1, hi); hi = lt - 1

def radix_sort_nonneg(a, base=256):
    shift, m = 0, max(a, default=0)
    while m >> shift:
        buckets = [[] for _ in range(base)]
        for x in a:
            buckets[(x >> shift) & (base - 1)].append(x)   # stable per pass
        a = [x for b in buckets for x in b]
        shift += 8
    return a

import java.util.function.LongPredicate;

public final class BinarySearchKit {

    /** First index i in [0, n) with a[i] >= x, or n. */
    static int lowerBound(int[] a, int x) {
        int lo = 0, hi = a.length;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (a[mid] >= x) hi = mid; else lo = mid + 1;
        }
        return lo;
    }

    /** First index with a[i] > x, or n. */
    static int upperBound(int[] a, int x) {
        int lo = 0, hi = a.length;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (a[mid] > x) hi = mid; else lo = mid + 1;
        }
        return lo;
    }

    /** Smallest v in [lo, hi] with p(v) true, assuming p is monotone false..true; returns hi + 1 if none. */
    static long firstTrue(long lo, long hi, LongPredicate p) {
        long l = lo, h = hi + 1;
        while (l < h) {
            long mid = l + (h - l) / 2;
            if (p.test(mid)) h = mid; else l = mid + 1;
        }
        return l;
    }

    /** Index of target in a rotated sorted array of distinct values, or -1. */
    static int searchRotated(int[] a, int target) {
        int lo = 0, hi = a.length - 1;
        while (lo <= hi) {                                   // closed interval variant
            int mid = (lo + hi) >>> 1;
            if (a[mid] == target) return mid;
            if (a[lo] <= a[mid]) {                           // left half sorted
                if (a[lo] <= target && target < a[mid]) hi = mid - 1; else lo = mid + 1;
            } else {                                         // right half sorted
                if (a[mid] < target && target <= a[hi]) lo = mid + 1; else hi = mid - 1;
            }
        }
        return -1;
    }

    /** Minimum of a rotated sorted array (distinct values). */
    static int rotatedMin(int[] a) {
        int lo = 0, hi = a.length - 1;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (a[mid] > a[hi]) lo = mid + 1; else hi = mid;  // min is right of mid, or at/left of mid
        }
        return a[lo];
    }

    /** floor(sqrt(n)) for n >= 0 via "last true": largest r with r*r <= n. */
    static long isqrt(long n) {
        // r * r > n would overflow near the top of the range; divide instead
        long first = firstTrue(0, 3_037_000_500L, r -> r > 0 && r > n / r);   // first r with r^2 > n
        return first - 1;
    }

    public static void main(String[] args) {
        int[] a = {1, 2, 2, 2, 5, 7};
        if (lowerBound(a, 2) != 1 || upperBound(a, 2) != 4 || lowerBound(a, 6) != 5 || lowerBound(a, 9) != 6)
            throw new AssertionError();
        int[] r = {4, 5, 6, 7, 0, 1, 2};
        if (searchRotated(r, 0) != 4 || searchRotated(r, 3) != -1 || rotatedMin(r) != 0) throw new AssertionError();
        if (isqrt(0) != 0 || isqrt(15) != 3 || isqrt(16) != 4 || isqrt(Long.MAX_VALUE) != 3_037_000_499L)
            throw new AssertionError(isqrt(Long.MAX_VALUE));
        System.out.println("binary search kit ok");
    }
}

    h = hi + 1
    while lo < h:
        mid = (lo + h) // 2                                  # Python ints don't overflow
        if pred(mid):
            h = mid
        else:
            lo = mid + 1
    return lo

7.3 Two pointers and sliding window templates

import java.util.*;

public final class Windows {

    /** Pair with sum = target in a sorted array (indices), or null. Opposite-end pointers. */
    static int[] pairSum(int[] a, int target) {
        int i = 0, j = a.length - 1;
        while (i < j) {
            long s = (long) a[i] + a[j];
            if (s == target) return new int[]{i, j};
            if (s < target) i++; else j--;
        }
        return null;
    }

    /** In-place dedupe of a sorted array; returns the new length. Read/write pointers. */
    static int dedupe(int[] a) {
        int w = 0;
        for (int r = 0; r < a.length; r++) if (r == 0 || a[r] != a[r - 1]) a[w++] = a[r];
        return w;
    }

    /** Fixed window: maximum sum of any k consecutive elements. */
    static long maxSumK(int[] a, int k) {
        long sum = 0, best;
        for (int i = 0; i < k; i++) sum += a[i];
        best = sum;
        for (int r = k; r < a.length; r++) { sum += a[r] - a[r - k]; best = Math.max(best, sum); }
        return best;
    }

    /** Variable window, longest valid: longest substring with at most k distinct chars. */
    static int longestAtMostKDistinct(String s, int k) {
        Map<Character, Integer> count = new HashMap<>();
        int best = 0;
        for (int l = 0, r = 0; r < s.length(); r++) {
            count.merge(s.charAt(r), 1, Integer::sum);
            while (count.size() > k) {                               // shrink while invalid
                char c = s.charAt(l++);
                if (count.merge(c, -1, Integer::sum) == 0) count.remove(c);
            }
            best = Math.max(best, r - l + 1);
        }
        return best;
    }

    /** Variable window, shortest valid: min length with sum >= target (non-negative values). */
    static int minLenSumAtLeast(int[] a, int target) {
        int best = Integer.MAX_VALUE;
        long sum = 0;
        for (int l = 0, r = 0; r < a.length; r++) {
            sum += a[r];
            while (sum >= target) {                                  // shrink while valid
                best = Math.min(best, r - l + 1);
                sum -= a[l++];
            }
        }
        return best == Integer.MAX_VALUE ? 0 : best;
    }

    /** Exactly-k via atMost(k) - atMost(k-1): count subarrays with exactly k distinct values. */
    static long exactlyKDistinct(int[] a, int k) { return atMost(a, k) - atMost(a, k - 1); }
    private static long atMost(int[] a, int k) {
        Map<Integer, Integer> count = new HashMap<>();
        long total = 0;
        for (int l = 0, r = 0; r < a.length; r++) {
            count.merge(a[r], 1, Integer::sum);
            while (count.size() > k) {
                if (count.merge(a[l], -1, Integer::sum) == 0) count.remove(a[l]);
                l++;
            }
            total += r - l + 1;                                      // subarrays ending at r
        }
        return total;
    }

    public static void main(String[] args) {
        if (!Arrays.equals(pairSum(new int[]{1, 3, 4, 6, 9}, 10), new int[]{0, 4})) throw new AssertionError();
        int[] d = {1, 1, 2, 3, 3, 3, 4};
        if (dedupe(d) != 4 || d[3] != 4) throw new AssertionError();
        if (maxSumK(new int[]{1, 12, -5, -6, 50, 3}, 4) != 51) throw new AssertionError();
        if (longestAtMostKDistinct("eceba", 2) != 3) throw new AssertionError();
        if (minLenSumAtLeast(new int[]{2, 3, 1, 2, 4, 3}, 7) != 2) throw new AssertionError();
        if (exactlyKDistinct(new int[]{1, 2, 1, 2, 3}, 2) != 7) throw new AssertionError();
        System.out.println("two pointers and windows ok");
    }
}
from collections import Counter

def longest_no_repeat(s: str) -> int:
    last, l, best = {}, 0, 0
    for r, ch in enumerate(s):
        if last.get(ch, -1) >= l:
            l = last[ch] + 1                  # jump l past the previous occurrence
        last[ch] = r
        best = max(best, r - l + 1)
    return best

def anagram_starts(s: str, p: str) -> list[int]:
    """Fixed window of len(p) with a running Counter difference."""
    need, win, out = Counter(p), Counter(), []
    for r, ch in enumerate(s):
        win[ch] += 1
        if r >= len(p):
            left = s[r - len(p)]
            win[left] -= 1
            if win[left] == 0:
                del win[left]
        if win == need:
            out.append(r - len(p) + 1)
    return out
