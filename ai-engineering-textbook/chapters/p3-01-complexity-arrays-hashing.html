1. Introduction: Why Cost Models Still Decide Interviews and Incidents

A senior interview rarely asks you to recite a definition of Big O. It asks you to look at your own solution, say "this is Θ(n log n) time and Θ(n) extra space because…", and then defend whether that is good enough for the stated constraints. In production the same skill shows up when a nightly job that "worked fine in staging" takes nine hours against real data because someone called list.contains(x) inside a loop over another list. Complexity analysis is the discipline of predicting that before it happens.

This chapter covers four tightly coupled topics:

  • Complexity analysis — asymptotic notation (O, Ω, Θ, o), worst/average/expected cases, space accounting, amortized analysis and recurrences. This is the measuring instrument for every algorithm in the rest of Part 3.
  • Arrays and dynamic arrays — contiguous memory, why cache lines make arrays beat "theoretically equal" linked structures, and how ArrayList and Python's list grow.
  • Strings — immutability, encodings (UTF-16 code units vs code points), builders, and linear-time pattern matching with Knuth–Morris–Pratt and Rabin–Karp rolling hashes.
  • Hashing — hash functions, collisions, chaining vs open addressing, load factor and resizing, with JDK HashMap/ConcurrentHashMap and CPython dict internals — and its frequent companion, the prefix sum.

Why group these? Because the single most common interview optimisation — "replace the inner loop with a hash lookup" — sits at their intersection: you need complexity analysis to see the inner loop is the bottleneck, arrays and strings are what you are iterating, and a hash map (often keyed by a prefix sum) is what removes the loop.

2. History: From Number Theory Notation to Swiss Tables

  • 1894–1909 — O and o notation. Paul Bachmann introduced the big-O symbol in analytic number theory (1894); Edmund Landau popularised it and added little-o (1909). They described the growth of number-theoretic functions, not programs.
  • 1953 — Hashing. Hans Peter Luhn at IBM wrote an internal memo describing hashing with chaining; around the same time Gene Amdahl, Elaine McGraw and Arthur Samuel used linear probing (open addressing) in an IBM 701 assembler. Arnold Dumey published the idea of hashing in the open literature in 1956.
  • 1965 — Computational complexity as a field. Juris Hartmanis and Richard Stearns published "On the Computational Complexity of Algorithms", measuring algorithms by time as a function of input size; they later received the 1993 Turing Award for it.
  • 1968–1976 — Knuth's analysis and Θ/Ω. Donald Knuth's The Art of Computer Programming (vol. 1 1968, vol. 3 1973) gave exact average-case analyses, including the famous linear probing analysis. In 1976 his SIGACT News note "Big Omicron and Big Omega and Big Theta" fixed the modern meanings of Ω and Θ.
  • 1977 — Knuth–Morris–Pratt. The linear-time string matching algorithm was published in SIAM Journal on Computing (Morris and Pratt had a 1970 technical report; Knuth found it independently from automata theory).
  • 1985 — Amortized analysis formalised. Robert Tarjan's paper "Amortized Computational Complexity" (SIAM J. Algebraic Discrete Methods) introduced the potential-function method in its general form.
  • 1987 — Rabin–Karp. Richard Karp and Michael Rabin published randomized fingerprinting for pattern matching (IBM Journal of Research and Development).
  • 1998 — Java 2 Collections. JDK 1.2 shipped HashMap, ArrayList and the Collections Framework designed by Joshua Bloch.
  • 2011 — Hash flooding. At 28C3, Alexander Klink and Julian Wälde showed that predictable string hashing let attackers send POST bodies whose parameter names all collide, degrading web frameworks (Java, PHP, Python, Ruby…) to quadratic time (oCERT-2011-003).
  • 2014 — Java 8. HashMap bins that grow past 8 entries become red-black trees (JEP 180), capping adversarial lookups at O(log n). ConcurrentHashMap was rewritten without segments.
  • 2014 — Python 3.4 switched str/bytes hashing to SipHash (PEP 456) as a HashDoS defence.
  • 2016–2017 — Compact layouts. Python 3.6 made dict compact and insertion ordered (guaranteed by the language from 3.7). Java 9 introduced Compact Strings (JEP 254), storing Latin-1 strings in one byte per character. Google presented SwissTable at CppCon 2017 and open-sourced it in Abseil.
  • 2021–2022 — Python 3.11 replaced Timsort's ad-hoc merge policy with Munro and Wild's powersort policy (relevant again in Chapter 3).
  • 2025 — Go 1.24 reimplemented the built-in map as a Swiss table.

The through-line: notation came from mathematics, hashing came from practical engineering, and the last decade's changes were driven by two forces you will meet repeatedly — adversarial input (HashDoS) and memory hierarchy (cache-friendly layouts).

3. Fundamentals

3.1 What we count: the cost model

Complexity is always relative to a cost model. The standard one is the word-RAM: memory is an array of words of w bits (w ≥ log n so an index fits in a word), and arithmetic, comparison, reading or writing one word each cost one unit. Under this model, adding two longs is O(1), but comparing two strings of length m is O(m), and hashing a string is O(m) the first time. A frequent interview slip is to call "sort n strings" O(n log n) — it is O(m · n log n) comparisons-cost in the worst case, where m is string length.

Input size n must be named explicitly. For a graph it is usually V and E; for a matrix, rows × cols; for a number-theoretic routine (is this integer prime?), it is the number of bits, which is why trial division up to √N is exponential in the input size even though it "looks" polynomial in N.

3.2 Asymptotic notation: O, Ω, Θ, o, ω

Intuition first: we want to compare how functions grow while ignoring constant factors (which depend on hardware and compilers) and small inputs (where everything is fast).

  • f = O(g) — f grows no faster than g, up to a constant: an upper bound.
  • f = Ω(g) — f grows at least as fast as g: a lower bound.
  • f = Θ(g) — both: a tight bound. When an interviewer says "what is the Big O?" they nearly always mean Θ of the worst case.
  • f = o(g) — f grows strictly slower (f/g → 0). ω is the strict lower analogue.

Important distinction: notation bounds a function; "worst case", "best case" and "average case" choose which function. "Quicksort is O(n²)" (worst-case function) and "quicksort is Θ(n log n) expected" (expected-time function) are both true. Saying "the best case of insertion sort is Ω(n)" mixes nothing up — the best-case function is Θ(n), so it is trivially Ω(n).

The common growth ladder, slowest to fastest: 1 ≪ α(n) (inverse Ackermann) ≪ log* n ≪ log n ≪ √n ≪ n ≪ n log n ≪ n² ≪ n³ ≪ 2ⁿ ≪ n! ≪ nⁿ. Two useful facts: any polylogarithm is o(nε) for every ε > 0, and any polynomial is o(cⁿ) for every c > 1.

3.4 Space complexity

Count auxiliary space (beyond the input) unless told otherwise, and remember the hidden consumers: the recursion stack (a recursive DFS on a path graph of 10⁶ nodes uses Θ(n) stack and will throw StackOverflowError with default thread stacks), copies made by substring/slicing (Python s[i:] is O(n) time and space), and boxing (a List<Integer> of n elements is roughly 4–5× the memory of an int[] on a 64-bit JVM with compressed oops: a 4-byte reference plus a 16-byte Integer object per element versus 4 bytes).

3.5 Amortized analysis — three methods

Amortization answers: "Some operations are expensive, but they are rare; what is the cost per operation averaged over a worst-case sequence?" Three equivalent techniques:

  1. Aggregate method: bound the total cost T(m) of any m operations, then divide. For a doubling array starting at capacity 1, m appends copy at most 1 + 2 + 4 + … + 2⌊log m⌋ < 2m elements, plus m writes, so T(m) < 3m and each append is amortized O(1).
  2. Accounting (banker's) method: charge each cheap operation a little extra "credit" stored on the data structure, and pay for expensive operations from saved credit. Charge each append 3 units: 1 to write itself, 1 to pay for its own future copy, 1 to pay for copying an element that was already in the older half. When capacity doubles, every element in the new half has a credit to pay for moving an element.
  3. Potential method: define a potential Φ(state) ≥ 0, Φ(initial)=0; amortized cost = actual cost + ΔΦ. If Φ never goes negative, the sum of amortized costs bounds the sum of actual costs. We do the dynamic-array proof formally in §6.

Amortization appears everywhere in Part 3: dynamic arrays, hash table resizing, the two-stack queue (Chapter 2), monotonic stacks (each element pushed and popped once), union-find with path compression (Chapter 5), and splay trees.

3.6 Recurrences and the master theorem (intuition)

Divide-and-conquer algorithms produce recurrences of the form T(n) = a·T(n/b) + f(n): a subproblems, each of size n/b, plus f(n) work to split and combine. Draw the recursion tree: level i has aⁱ nodes each of size n/bⁱ, so the work at level i is aⁱ·f(n/bⁱ). There are logb n levels and nlogb a leaves. The master theorem simply asks which end of the tree dominates:

  • Leaves dominate (f grows polynomially slower than nlogb a): T(n) = Θ(nlogb a). Example: Karatsuba, T = 3T(n/2) + n → Θ(n1.585).
  • Every level equal (f = Θ(nlogb a)): multiply by the number of levels, Θ(nlogb a log n). Example: merge sort, T = 2T(n/2) + n → Θ(n log n); binary search, T = T(n/2) + 1 → Θ(log n).
  • Root dominates (f grows polynomially faster and satisfies a regularity condition): T(n) = Θ(f(n)). Example: T = 2T(n/2) + n² → Θ(n²).

Recurrences that do not fit — T(n) = T(n−1) + n (selection sort, Θ(n²)), T(n) = 2T(n−1) + 1 (Towers of Hanoi, Θ(2ⁿ)), T(n) = T(n/3) + T(2n/3) + n (unbalanced split, still Θ(n log n)) — are solved by unrolling or by the recursion tree directly. The Akra–Bazzi method generalises the master theorem to unequal splits.

3.7 Arrays: the machine's native structure

An array is a contiguous block of equally sized slots. The address of element i is base + i × size, so random access is O(1) — a single multiply-add, no pointer chasing. That arithmetic is the whole reason arrays dominate: CPUs fetch memory in 64-byte cache lines and hardware prefetchers detect sequential strides, so scanning an int[] touches one new cache line every 16 elements. A linked list of the same length incurs a potential cache miss on every node (~100 ns to DRAM vs ~1 ns to L1). That is why "both are O(n) to traverse" hides a 10–50× real-world gap.

Costs on a static array of length n: read/write by index Θ(1); search unsorted Θ(n); search sorted Θ(log n) via binary search; insert/delete in the middle Θ(n) (shift); and no growth at all.

In Java, an int[] is a real contiguous block of primitives; an Integer[] or Object[] is a contiguous block of references to objects scattered across the heap. Project Valhalla's value classes aim to close this gap, but as of JDK 21 they are not available in a release. Python's list is likewise an array of pointers to PyObjects; for dense numerics use array.array or NumPy.

3.8 Dynamic arrays

A dynamic array (Java ArrayList, Python list, Go slices with append, C++ std::vector) wraps a static array with a size and a capacity. Appending when size < capacity is a single write; appending when full allocates a larger array (multiplicative growth), copies everything, then writes. The growth factor must be multiplicative: growing by a constant k gives Θ(n²/k) total copying for n appends — amortized Θ(n) per append. Any factor r > 1 gives amortized O(1); the trade-off is wasted space (up to (r−1)/r of capacity unused right after growth) versus copy frequency. Java uses 1.5×, CPython roughly 1.125× plus a constant, Go 2× for small slices tapering towards 1.25× for large ones.

Shrinking needs hysteresis: if you halve when the array becomes half full, alternating push/pop at the boundary causes Θ(n) per operation (thrashing). Shrink only at one-quarter full. ArrayList never shrinks automatically; you call trimToSize().

3.9 Strings

A string is a sequence of characters — but "character" is ambiguous. Unicode defines code points (U+0000 to U+10FFFF). Encodings map code points to code units: UTF-8 (1–4 bytes, used by Go strings and most wire formats), UTF-16 (one or two 16-bit units; Java char is a UTF-16 code unit, so an emoji is two chars, a surrogate pair). A user-perceived character (grapheme cluster, like a flag or an accented letter built from combining marks) can be several code points. Consequences: s.length() in Java counts UTF-16 units, reversing a string char-by-char corrupts surrogate pairs, and "index i" in Go is a byte offset.

Immutability. Java, Python and Go strings are immutable. Benefits: safe sharing across threads, caching the hash code (Java caches hash in the object), safe use as map keys, and string interning. Cost: every "modification" creates a new string, so building a string of length n by repeated += in a loop is Θ(n²) total copying. Use StringBuilder (Java), "".join(parts) (Python) or strings.Builder (Go), each amortized O(1) per appended character — they are dynamic arrays of characters.

Comparison and hashing are O(length). Two equal 1 MB strings take a megabyte of comparisons to confirm equality (identity checks shortcut only when the references are the same).

3.10 String matching

Problem: find occurrences of pattern P (length m) in text T (length n). The naive algorithm tries each alignment and compares up to m characters: Θ(nm) worst case (T = "aaaa…a", P = "aa…ab"), but typically fast on natural text because mismatches come early. KMP achieves Θ(n + m) worst case by never moving backwards in the text: when a mismatch happens after matching q characters, the longest proper prefix of P[0..q) that is also a suffix tells us how much of the match we can keep. That information is precomputed in the prefix function (failure function) π. Rabin–Karp compares hashes of windows: a polynomial rolling hash can be updated in O(1) as the window slides, so all n−m+1 window hashes cost Θ(n); only hash matches are verified character by character. Expected Θ(n + m), worst Θ(nm) if many spurious collisions — but its real power is multi-pattern matching and substring-equality queries (used with binary search in "longest duplicate substring"). Boyer–Moore (and the Horspool simplification) scan the pattern right-to-left and can skip large chunks; they are sublinear on average for large alphabets and are what grep descendants favour. The Z-algorithm computes, for each position, the longest substring starting there that matches a prefix — an alternative to π with the same Θ(n+m) bound.

3.11 Hash functions

A hash table stores key k in slot h(k) mod m. A good hash function for tables is fast, deterministic within a process, and spreads typical key sets uniformly. Cryptographic strength is not required, but unpredictability to attackers is desirable when keys come from untrusted input (hence SipHash in Python, Rust and Ruby). Java's String.hashCode is the polynomial s[0]·31n−1 + … + s[n−1], computed with Horner's rule in 32-bit wrapping arithmetic. It is deterministic across JVMs — convenient, but it means collisions are trivially constructible: "Aa" and "BB" share a hash code, and so do all 2k concatenations of k such blocks.

Universal hashing chooses h at random from a family H such that for any distinct x, y, Pr[h(x)=h(y)] ≤ 1/m. Then for any fixed key set, the expected chain length is O(1 + α) where α = n/m is the load factor — an expected bound adversaries cannot defeat unless they learn h.

3.12 Collision resolution: chaining vs open addressing

Separate chaining: each slot holds a list (or tree) of entries. Simple, tolerant of load factors above 1, deletion is easy, entries never move (so references to them stay valid). Downsides: one pointer chase per entry, per-entry allocation overhead. Java HashMap, ConcurrentHashMap and Go's pre-1.24 map use variants.

Open addressing: all entries live in the table itself; on collision, follow a deterministic probe sequence. Linear probing (i, i+1, i+2…) is the most cache-friendly but suffers primary clustering — runs of occupied slots grow and merge. Quadratic probing and double hashing break clusters at some cache cost. Deletion needs tombstones (a "deleted" marker so probes do not stop early) or backward-shift deletion. Load factor must stay well below 1. Python dict/set, Java's IdentityHashMap and ThreadLocalMap, Abseil SwissTable and Go 1.24 maps use open addressing. Robin Hood hashing (Celis, 1986) steals slots from entries that are closer to home, reducing probe-length variance.

3.13 Load factor and resizing

The load factor α = n/m trades memory for speed. With chaining, an unsuccessful lookup inspects about α entries; with linear probing, about ½(1 + 1/(1−α)²) probes — 2.5 at α = 0.5, 8.5 at α = 0.75, 50.5 at α = 0.9. That curve is why open-addressing tables cap α near 0.5–0.875 and chaining tables tolerate 0.75–1.0. When α exceeds the threshold, the table resizes (typically doubles) and rehashes every key — Θ(n) once, amortized O(1) per insertion by the same argument as dynamic arrays.

3.14 Hash sets and the "seen" pattern

A hash set is a hash map with no values (Java's HashSet literally wraps a HashMap with a dummy value). Its interview superpower is converting "have I seen something compatible with x before?" from an O(n) scan to O(1) expected. The compatible thing might be x itself (duplicates), target − x (Two Sum), a canonical form of x (sorted letters for anagrams), or a running prefix sum minus k (subarray sums).

3.15 Prefix sums and difference arrays

Given array a[0..n), the prefix sum array P has P[0] = 0 and P[i+1] = P[i] + a[i]. Then the sum of any range a[l..r] equals P[r+1] − P[l] — O(1) per query after Θ(n) preprocessing. In 2-D, P[i][j] stores the sum of the rectangle above-left of (i, j), and any sub-rectangle sum is obtained by inclusion–exclusion of four corners. The inverse idea is the difference array: to add v to every element in a[l..r] for many updates, record D[l] += v and D[r+1] −= v, then take a prefix sum once at the end — Θ(n + q) instead of Θ(nq). Prefix sums generalise to any associative, invertible operation: XOR prefixes, counts of a character, products (careful with zeros). Combined with a hash map from prefix value to earliest index or count, they solve "subarray with sum k" problems in linear time even with negative numbers — where sliding windows fail.

4. Internal Working: What the JDK and CPython Actually Do

4.1 ArrayList growth

In OpenJDK 21, ArrayList holds an Object[] elementData and an int size. A default-constructed list shares an empty array sentinel and allocates capacity 10 on the first add. When full, grow(minCapacity) computes the new length via ArraysSupport.newLength(oldCapacity, minCapacity − oldCapacity, oldCapacity >> 1) — i.e. old + old/2, a 1.5× factor (or exactly what is needed, if more) — and calls Arrays.copyOf, which bottoms out in an intrinsic memory copy. 4.2 CPython list over-allocation

CPython's list_resize (Objects/listobject.c) computes a new allocation of roughly newsize + (newsize >> 3) + 6, rounded down to a multiple of 4 — about 12.5% headroom plus a small constant. The growth pattern from empty is 0, 4, 8, 16, 24, 32, 40, 52, 64, 76, … Because headroom is proportional to size, the amortized cost of append is still O(1); the small factor favours memory over copy count, which suits a language where lists of pointers are ubiquitous. list.pop() from the end is O(1); pop(0) and insert(0, x) are O(n) — use collections.deque. 4.3 Java strings: compact strings, cached hash, indy concatenation

Since JDK 9 (JEP 254) a String holds a byte[] value and a byte coder: LATIN1 (one byte per char) when every character fits, otherwise UTF16 (two bytes per char). The field int hash caches the hash code after first computation (with a hashIsZero flag so strings that genuinely hash to 0 are not recomputed every time). substring copies (since 7u6 it no longer shares the parent array, which fixed a memory-leak pattern at the cost of O(k) copies). String concatenation with + compiles to an invokedynamic call to StringConcatFactory (JEP 280, JDK 9) — efficient for a single expression, but s += x inside a loop still allocates a new string each iteration: Θ(n²).

Python 3 strings (PEP 393) choose 1, 2 or 4 bytes per code point per string, based on the widest character, so indexing s[i] is O(1) by code point — unlike UTF-8 Go strings, where s[i] is a byte and ranging with for _, r := range s decodes runes.

4.4 Java HashMap, step by step

A HashMap<K,V> (OpenJDK 8 through 21) is an array Node<K,V>[] table whose length is always a power of two (default 16, lazily allocated). Each node stores hash, key, value, next.

  1. Spread the hash. hash(key) = (h = key.hashCode()) ^ (h >>> 16). Because the index uses only the low bits, XOR-ing the high half down lets high-bit variation influence small tables.
  2. Index. i = (n − 1) & hash — a bit mask instead of a modulo, valid because n is a power of two. Also avoids negative indices from negative hash codes.
  3. Empty bin → place a new node. Occupied → walk the chain comparing hash first (cheap int compare) and then == or equals; replace the value on match, else append at the tail (Java 8+ appends at tail; Java 7 prepended at head, which combined with unsynchronised concurrent resize could create a cycle and an infinite loop — a classic production incident).
  4. Treeify. If a chain reaches TREEIFY_THRESHOLD = 8 nodes and the table has at least MIN_TREEIFY_CAPACITY = 64 slots, the bin becomes a red-black tree of TreeNodes ordered by hash, then by compareTo if keys are Comparable, then by a tie-breaker (class name and identity hash). If the table is smaller than 64 it resizes instead. Trees shrink back to lists at UNTREEIFY_THRESHOLD = 6 (the gap of 2 prevents flapping).
  5. Resize. After insert, if ++size > threshold (capacity × loadFactor, default 0.75), the table doubles. Because capacity is a power of two, each node either stays at index i or moves to i + oldCap, decided by a single bit: (hash & oldCap) == 0. The JDK splits each chain into "lo" and "hi" lists, preserving relative order, with no rehash computation.
capacity 16 (mask 0b1111) -> 32 (mask 0b11111); the new bit is 0b10000 = oldCap

Why the Poisson argument for 8? The source comments note that with a well-distributed hash and load factor 0.75, bin sizes follow roughly a Poisson distribution with mean 0.5, so the probability of a bin reaching 8 is about 6 × 10⁻⁸. Treeification therefore almost never happens by accident; it exists for bad or adversarial hash codes.

4.5 ConcurrentHashMap (JDK 8+)

The Java 8 rewrite dropped the 16-segment lock striping. Now:

  • Reads (get) are lock-free: the table array and node val/next fields are read with volatile semantics.
  • Inserting into an empty bin uses a single CAS. Inserting into a non-empty bin synchronized-locks the first node of that bin only — contention is per bin.
  • The size is maintained like a LongAdder: a base counter plus CounterCell[] to spread contention; size() sums them and is only a moment-in-time estimate under concurrent updates.
  • Resizing is cooperative: the table is split into strides; threads that encounter a ForwardingNode (hash MOVED) help transfer bins rather than block.
  • Null keys and values are forbidden, because get returning null must unambiguously mean "absent" in a concurrent setting.
  • computeIfAbsent holds the bin lock while the mapping function runs — keep the function short and never let it update the same map (recursive updates throw IllegalStateException("Recursive update") in JDK 9+).

4.6 CPython dict: indices + compact entries

Since Python 3.6, a dict has two arrays: a sparse indices table (1, 2, 4 or 8 bytes per slot depending on size) and a dense entries array of (hash, key, value) in insertion order. Lookup hashes the key, probes indices using an open-addressing recurrence that mixes in the higher hash bits through a perturb variable (roughly i = (5*i + 1 + perturb) mod size; perturb >>= 5), and follows the stored index into entries. The table is kept at most two-thirds full (usable = 2/3 of slots). Benefits: iteration order is insertion order, iteration is a dense scan, and memory drops 20–25% versus the older layout because the sparse part holds small integers rather than 24-byte entries. Deletion leaves a DKIX_DUMMY tombstone in indices. Small integers hash to themselves, which is why the perturbation is essential to avoid clustering for keys like 0, 8, 16…

Why linear? k increases by at most 1 per character and every fallback decreases it by at least 1, and k ≥ 0; so total fallbacks ≤ total increments ≤ m. The same argument bounds the search phase by 2n. This is an amortized argument with potential Φ = k.

4.8 Rabin–Karp rolling hash, traced

Treat a window of length m as a number in base B modulo a prime M: H(s[i..i+m)) = Σ s[i+j]·Bm−1−j mod M. Sliding the window right by one: remove the leading character's contribution (multiply by Bm−1, precomputed), shift by multiplying by B, add the new character:

B=10, M=13, text digits "31415", m=3
 H("314") = 314 mod 13 = 2

                 = ((2 - 300) * 10 + 1) mod 13 = (-2979) mod 13 = 11   (141 mod 13 = 11 ok)
 slide: H("415") = ((11 - 1*100) * 10 + 5) mod 13 = (-885) mod 13 = 12 (415 mod 13 = 12 ok)
 Each slide O(1); compare hashes, verify characters only when equal.

In Java, take care with negative intermediate values: use Math.floorMod or add M before reducing. Use 64-bit arithmetic with M near 10⁹ so products fit in a long, or use two independent moduli ("double hashing") to make collisions astronomically unlikely.

6. The Math: Definitions, Proofs and Back-of-Envelope Numbers

6.1 Formal definitions

Intuition: "eventually, up to a constant factor". Formally:

\[ f(n) = O(g(n)) \iff \exists\, c \gt 0,\ n_0 : \forall n \ge n_0,\ 0 \le f(n) \le c \cdot g(n) \] \[ f(n) = \Omega(g(n)) \iff \exists\, c \gt 0,\ n_0 : \forall n \ge n_0,\ f(n) \ge c \cdot g(n) \ge 0 \] \[ f(n) = \Theta(g(n)) \iff f = O(g) \text{ and } f = \Omega(g), \qquad f = o(g) \iff \lim_{n\to\infty} \frac{f(n)}{g(n)} = 0 \]

Worked example: \(3n^2 + 10n + 7 = \Theta(n^2)\). Upper: for \(n \ge 1\), \(3n^2 + 10n + 7 \le 3n^2 + 10n^2 + 7n^2 = 20n^2\), so c = 20, n₀ = 1. Lower: \(3n^2 + 10n + 7 \ge 3n^2\), so c = 3. Logarithm bases do not matter inside O because \(\log_a n = \log_b n / \log_b a\) differs by a constant factor; but they do matter in exponents: \(2^{\log_2 n} = n\) while \(4^{\log_2 n} = n^2\).

6.2 Useful sums

\[ \sum_{i=1}^{n} i = \frac{n(n+1)}{2} = \Theta(n^2), \qquad \sum_{i=0}^{k} r^i = \frac{r^{k+1}-1}{r-1} = \Theta(r^k)\ (r \gt 1), \qquad \sum_{i=1}^{n} \frac{1}{i} = H_n = \ln n + O(1) \]

The first explains nested loops where the inner loop runs i times. The second (a geometric series is dominated by its largest term) explains dynamic arrays, heaps built bottom-up, and the master theorem's extreme cases. The harmonic series explains, for example, the expected Θ(n log n) comparisons of randomized quicksort and the coupon-collector bound.

6.3 Dynamic array: potential-method proof

Let the array double when full. Define \(\Phi = 2 \cdot \text{size} - \text{capacity}\) (non-negative after the first growth, since the array is always at least half full). For an append without growth: actual cost 1, \(\Delta\Phi = 2\), amortized 3. For an append that triggers growth from capacity k (size = k before): actual cost \(k + 1\) (copy k, write 1); before, \(\Phi = 2k - k = k\); after, size = k+1, capacity = 2k, \(\Phi = 2(k+1) - 2k = 2\); so \(\Delta\Phi = 2 - k\) and amortized cost \(= k + 1 + 2 - k = 3\). Every append is amortized 3 = O(1). For a growth factor r, the same argument gives amortized cost \(1 + \frac{r}{r-1}\): 3 for r = 2, 4 for r = 1.5, 10 for r = 1.125.

6.5 Hashing probabilities

Chaining, simple uniform hashing: expected chain length α = n/m; unsuccessful search Θ(1 + α); successful search Θ(1 + α/2). Linear probing (Knuth's analysis, uniform hashing): expected probes ≈ \(\tfrac12\left(1 + \tfrac{1}{1-\alpha}\right)\) for a hit and \(\tfrac12\left(1 + \tfrac{1}{(1-\alpha)^2}\right)\) for a miss. Birthday bound: with n keys hashed into N values, the probability of at least one collision is about \(1 - e^{-n^2/(2N)}\); for 32-bit hash codes (N ≈ 4.3 × 10⁹) a collision becomes likely (≈50%) around n ≈ 77,000. That is why equals must always be checked after a hash match, and why 64-bit fingerprints are the minimum for deduplicating millions of items by hash alone.

Rabin–Karp false positives: for two distinct strings of length m, the probability that their polynomial hashes collide under a random base B mod prime M is at most \((m-1)/M\) (a nonzero polynomial of degree ≤ m−1 has at most m−1 roots). With M ≈ 10⁹ and m = 10⁵, that is ≤ 10⁻⁴ per comparison — small but not negligible over 10⁶ comparisons; use two moduli to square it.

6.6 Back-of-envelope memory for maps

Illustrative On a 64-bit HotSpot JVM with compressed oops, a HashMap.Node is about 32 bytes (12-byte header + int hash + 3 references, padded), plus 4 bytes per table slot (at load 0.75, ~5.3 bytes per entry), plus key and value objects: a HashMap<Long, Long> costs roughly 32 + 5 + 16 + 16 ≈ 70 bytes per entry versus 16 bytes for the raw data — about 4×. Ten million entries ≈ 700 MB of heap. Primitive maps (fastutil Long2LongOpenHashMap, Eclipse Collections) store keys and values in parallel long[] arrays with open addressing, typically ~20–35 bytes per entry. Measure with JOL (Java Object Layout) rather than trusting these numbers.

7.1 Dynamic array with amortized growth and hysteretic shrink

import java.util.Arrays;
import java.util.Iterator;
import java.util.NoSuchElementException;

/** Growable array: amortized O(1) append/pop, O(1) get/set, O(n) insert/remove in the middle. */
public final class DynamicArray<T> implements Iterable<T> {
    private Object[] data = new Object[4];
    private int size;
    private int copies; // instrumentation: total elements copied during resizes

    public int size() { return size; }

    @SuppressWarnings("unchecked")
    public T get(int i) { Objects_checkIndex(i); return (T) data[i]; }

    public void set(int i, T v) { Objects_checkIndex(i); data[i] = v; }

    public void add(T v) {
        if (size == data.length) resize(data.length * 2);      // multiplicative growth
        data[size++] = v;
    }

    public void insert(int i, T v) {
        if (i < 0 || i > size) throw new IndexOutOfBoundsException(i);
        if (size == data.length) resize(data.length * 2);
        System.arraycopy(data, i, data, i + 1, size - i);       // shift tail right: O(n - i)
        data[i] = v;
        size++;
    }

    @SuppressWarnings("unchecked")
    public T removeLast() {
        if (size == 0) throw new NoSuchElementException();
        T v = (T) data[--size];
        data[size] = null;                                       // let GC reclaim it
        if (size > 0 && size == data.length / 4) resize(data.length / 2); // shrink at 1/4, not 1/2
        return v;
    }

    private void resize(int newCap) {
        copies += size;
        data = Arrays.copyOf(data, Math.max(newCap, 4));
    }

    private void Objects_checkIndex(int i) {
        if (i < 0 || i >= size) throw new IndexOutOfBoundsException(i);
    }

    int capacity() { return data.length; }
    int copies() { return copies; }

    @Override public Iterator<T> iterator() {
        return new Iterator<>() {
            int i = 0;
            public boolean hasNext() { return i < size; }
            public T next() { if (!hasNext()) throw new NoSuchElementException(); return get(i++); }
        };
    }

    public static void main(String[] args) {
        var a = new DynamicArray<Integer>();
        int n = 1_000_000;
        for (int i = 0; i < n; i++) a.add(i);
        // aggregate method: total copies < 2n for doubling
        if (a.copies() >= 2 * n) throw new AssertionError("copies " + a.copies());
        a.insert(0, -1);
        if (a.get(0) != -1 || a.get(1) != 0 || a.size() != n + 1) throw new AssertionError();
        while (a.size() > 1) a.removeLast();
        if (a.capacity() > 8) throw new AssertionError("did not shrink: " + a.capacity());
        System.out.println("appends=" + n + " copies=" + a.copies() + " (amortized O(1))");
    }
}
class DynamicArray:
    """Growable array with doubling growth and shrink at 1/4 full."""
    def __init__(self):
        self._data = [None] * 4
        self._size = 0
        self.copies = 0

    def __len__(self):
        return self._size

    def __getitem__(self, i):
        if not 0 <= i < self._size:
            raise IndexError(i)
        return self._data[i]

    def append(self, v):
        if self._size == len(self._data):
            self._resize(2 * len(self._data))
        self._data[self._size] = v
        self._size += 1

    def pop(self):
        if self._size == 0:
            raise IndexError("pop from empty")
        self._size -= 1
        v, self._data[self._size] = self._data[self._size], None
        if 0 < self._size == len(self._data) // 4:
            self._resize(len(self._data) // 2)
        return v

    def _resize(self, cap):
        self.copies += self._size
        new = [None] * max(cap, 4)
        new[: self._size] = self._data[: self._size]
        self._data = new

7.2 Open-addressing hash map with linear probing and tombstones

This is the structure behind Python's dict and every "implement a hash map" interview question. Note the separate handling of empty (stop probing) and tombstone (keep probing, but a reusable slot for inserts).

import java.util.Objects;

/** Open addressing, linear probing, power-of-two capacity, max load 0.5 (incl. tombstones). */
public final class LinearProbingMap<K, V> {
    private static final Object TOMBSTONE = new Object();
    private Object[] keys;
    private Object[] vals;
    private int size;       // live entries
    private int used;       // live + tombstones (they lengthen probes too)

    public LinearProbingMap() { this(16); }
    public LinearProbingMap(int cap) {
        int c = Integer.highestOneBit(Math.max(4, cap) * 2 - 1); // round up to power of two
        keys = new Object[c];
        vals = new Object[c];
    }

    private static int spread(Object k) {
        int h = k.hashCode();
        h ^= (h >>> 16);
        return h * 0x9E3779B1;      // multiplicative (Fibonacci) mixing so low bits vary
    }

    private int slotFor(Object k) {
        int mask = keys.length - 1;
        int i = spread(k) & mask;
        while (keys[i] != null) {                     // stop only at a truly empty slot
            if (keys[i] != TOMBSTONE && keys[i].equals(k)) return i;
            i = (i + 1) & mask;
        }
        return -1;
    }

    @SuppressWarnings("unchecked")
    public V get(K k) {
        Objects.requireNonNull(k);
        int i = slotFor(k);
        return i < 0 ? null : (V) vals[i];
    }

    @SuppressWarnings("unchecked")
    public V put(K k, V v) {
        Objects.requireNonNull(k);
        if ((used + 1) * 2 > keys.length) rehash(size * 2 + 2 > keys.length ? keys.length * 2 : keys.length);
        int mask = keys.length - 1;
        int i = spread(k) & mask, firstTomb = -1;
        while (keys[i] != null) {
            if (keys[i] == TOMBSTONE) { if (firstTomb < 0) firstTomb = i; }
            else if (keys[i].equals(k)) { V old = (V) vals[i]; vals[i] = v; return old; }
            i = (i + 1) & mask;
        }
        if (firstTomb >= 0) i = firstTomb; else used++;  // reuse a tombstone if we passed one
        keys[i] = k; vals[i] = v; size++;
        return null;
    }

    @SuppressWarnings("unchecked")
    public V remove(K k) {
        int i = slotFor(k);
        if (i < 0) return null;
        V old = (V) vals[i];
        keys[i] = TOMBSTONE; vals[i] = null; size--;
        return old;
    }

    private void rehash(int newCap) {       // also purges tombstones
        Object[] ok = keys, ov = vals;
        keys = new Object[newCap]; vals = new Object[newCap];
        size = 0; used = 0;
        for (int j = 0; j < ok.length; j++)
            if (ok[j] != null && ok[j] != TOMBSTONE) {
                @SuppressWarnings("unchecked") K kk = (K) ok[j];
                @SuppressWarnings("unchecked") V vv = (V) ov[j];
                put(kk, vv);
            }
    }

    public int size() { return size; }

    public static void main(String[] args) {
        var m = new LinearProbingMap<String, Integer>();
        for (int i = 0; i < 100_000; i++) m.put("k" + i, i);
        for (int i = 0; i < 100_000; i += 2) m.remove("k" + i);
        for (int i = 0; i < 100_000; i++) {
            Integer v = m.get("k" + i);
            if (i % 2 == 0 ? v != null : v != i) throw new AssertionError(i);
        }
        // "Aa" and "BB" collide in String.hashCode -- still correct
        m.put("Aa", 1); m.put("BB", 2);
        if (m.get("Aa") != 1 || m.get("BB") != 2 || m.size() != 50_002) throw new AssertionError();
        System.out.println("ok size=" + m.size());
    }
}
_EMPTY, _TOMB = object(), object()

class LinearProbingMap:
    def __init__(self, cap=16):
        self._keys = [_EMPTY] * cap
        self._vals = [None] * cap
        self._size = self._used = 0

    def _probe(self, key):
        mask = len(self._keys) - 1
        i = hash(key) & mask
        while True:
            yield i
            i = (i + 1) & mask

    def get(self, key, default=None):
        for i in self._probe(key):
            k = self._keys[i]
            if k is _EMPTY:
                return default
            if k is not _TOMB and k == key:
                return self._vals[i]

    def put(self, key, val):
        if (self._used + 1) * 2 > len(self._keys):
            self._rehash(len(self._keys) * 2)
        tomb = None
        for i in self._probe(key):
            k = self._keys[i]
            if k is _EMPTY:
                break
            if k is _TOMB:
                tomb = i if tomb is None else tomb
            elif k == key:
                self._vals[i] = val
                return
        if tomb is not None:
            i = tomb
        else:
            self._used += 1
        self._keys[i], self._vals[i] = key, val
        self._size += 1

    def remove(self, key):
        for i in self._probe(key):
            k = self._keys[i]
            if k is _EMPTY:
                raise KeyError(key)
            if k is not _TOMB and k == key:
                self._keys[i], self._vals[i] = _TOMB, None
                self._size -= 1
                return

    def _rehash(self, cap):
        old = [(k, v) for k, v in zip(self._keys, self._vals) if k is not _EMPTY and k is not _TOMB]
        self.__init__(cap)
        for k, v in old:
            self.put(k, v)

Why the multiplicative mix in Java? With a power-of-two mask we use only the low bits; Integer.hashCode is the identity, so keys 0, 16, 32… would all land in slot 0 of a 16-slot table. The golden-ratio multiplier (0x9E3779B1 ≈ 2³²/φ) propagates entropy into the low bits. Java's HashMap instead relies on the h ^ (h >>> 16) spread plus chaining/treeification as a fallback.

7.3 String matching: KMP, Rabin–Karp and Z

import java.util.ArrayList;
import java.util.List;

public final class StringMatching {

    /** pi[i] = length of longest proper prefix of p[0..i] that is also its suffix. O(m). */
    static int[] prefixFunction(String p) {
        int m = p.length();
        int[] pi = new int[m];
        for (int i = 1, k = 0; i < m; i++) {
            while (k > 0 && p.charAt(i) != p.charAt(k)) k = pi[k - 1]; // fall back
            if (p.charAt(i) == p.charAt(k)) k++;
            pi[i] = k;
        }
        return pi;
    }

    /** All start indices of p in t. Theta(n + m) worst case. */
    static List<Integer> kmp(String t, String p) {
        List<Integer> out = new ArrayList<>();
        if (p.isEmpty()) return out;
        int[] pi = prefixFunction(p);
        for (int i = 0, q = 0; i < t.length(); i++) {
            while (q > 0 && t.charAt(i) != p.charAt(q)) q = pi[q - 1];
            if (t.charAt(i) == p.charAt(q)) q++;
            if (q == p.length()) {           // full match ending at i
                out.add(i - q + 1);
                q = pi[q - 1];               // allow overlapping matches
            }
        }
        return out;
    }

    /** Rabin-Karp with two moduli; expected Theta(n + m). */
    static List<Integer> rabinKarp(String t, String p) {
        final long B = 131, M1 = 1_000_000_007L, M2 = 998_244_353L;
        int n = t.length(), m = p.length();
        List<Integer> out = new ArrayList<>();
        if (m == 0 || m > n) return out;
        long hp1 = 0, hp2 = 0, ht1 = 0, ht2 = 0, pow1 = 1, pow2 = 1;
        for (int i = 0; i < m; i++) {
            hp1 = (hp1 * B + p.charAt(i)) % M1;  hp2 = (hp2 * B + p.charAt(i)) % M2;
            ht1 = (ht1 * B + t.charAt(i)) % M1;  ht2 = (ht2 * B + t.charAt(i)) % M2;
            if (i > 0) { pow1 = pow1 * B % M1; pow2 = pow2 * B % M2; } // B^(m-1)
        }
        for (int i = 0; ; i++) {
            if (ht1 == hp1 && ht2 == hp2 && t.regionMatches(i, p, 0, m)) out.add(i); // verify
            if (i + m >= n) break;
            ht1 = Math.floorMod(ht1 - t.charAt(i) * pow1 % M1, M1);     // drop leading char
            ht2 = Math.floorMod(ht2 - t.charAt(i) * pow2 % M2, M2);
            ht1 = (ht1 * B + t.charAt(i + m)) % M1;                      // shift and add new char
            ht2 = (ht2 * B + t.charAt(i + m)) % M2;
        }
        return out;
    }

    /** z[i] = length of longest substring starting at i that matches a prefix of s. O(n). */
    static int[] zFunction(String s) {
        int n = s.length();
        int[] z = new int[n];
        for (int i = 1, l = 0, r = 0; i < n; i++) {
            if (i < r) z[i] = Math.min(r - i, z[i - l]);   // reuse the [l, r) box
            while (i + z[i] < n && s.charAt(z[i]) == s.charAt(i + z[i])) z[i]++;
            if (i + z[i] > r) { l = i; r = i + z[i]; }
        }
        return z;
    }

    public static void main(String[] args) {
        String t = "abababacaababacab", p = "ababaca";
        var a = kmp(t, p);
        var b = rabinKarp(t, p);
        var expected = List.of(2, 9);
        if (!a.equals(expected) || !b.equals(expected)) throw new AssertionError(a + " " + b);
        if (!kmp("aaaaa", "aa").equals(List.of(0, 1, 2, 3))) throw new AssertionError();

        int[] z = zFunction("aabxaab");
        if (z[4] != 3) throw new AssertionError();
        System.out.println("kmp=" + a + " rk=" + b + " ok");
    }
}

        hp = (hp * base + ord(p[i])) % mod
        ht = (ht * base + ord(t[i])) % mod
    top = pow(base, m - 1, mod)        # Python ints never overflow
    out = []
    for i in range(n - m + 1):
        if ht == hp and t[i:i + m] == p:
            out.append(i)
        if i + m < n:
            ht = ((ht - ord(t[i]) * top) * base + ord(t[i + m])) % mod
    return out

7.4 Prefix sums: 1-D, 2-D and difference arrays

import java.util.Arrays;
import java.util.HashMap;

public final class PrefixSums {

    /** P[i] = a[0] + ... + a[i-1]; range sum [l, r] = P[r+1] - P[l]. Uses long to avoid overflow. */
    static long[] prefix(int[] a) {
        long[] p = new long[a.length + 1];
        for (int i = 0; i < a.length; i++) p[i + 1] = p[i] + a[i];
        return p;
    }

    /** 2-D: S[i][j] = sum of the rectangle rows [0,i) x cols [0,j). */
    record Matrix2D(long[][] s) {
        static Matrix2D of(int[][] g) {
            int r = g.length, c = g[0].length;
            long[][] s = new long[r + 1][c + 1];
            for (int i = 0; i < r; i++)
                for (int j = 0; j < c; j++)
                    s[i + 1][j + 1] = g[i][j] + s[i][j + 1] + s[i + 1][j] - s[i][j];
            return new Matrix2D(s);
        }
        /** inclusive corners (r1,c1)..(r2,c2), O(1) by inclusion-exclusion */
        long sum(int r1, int c1, int r2, int c2) {
            return s[r2 + 1][c2 + 1] - s[r1][c2 + 1] - s[r2 + 1][c1] + s[r1][c1];
        }
    }

    /** Apply q range-add updates in O(n + q) using a difference array. */
    static long[] applyRangeAdds(int n, int[][] updates) { // each {l, r, v}
        long[] d = new long[n + 1];
        for (int[] u : updates) { d[u[0]] += u[2]; d[u[1] + 1] -= u[2]; }
        long[] out = new long[n];
        long run = 0;
        for (int i = 0; i < n; i++) out[i] = run += d[i];
        return out;
    }

    /** Count subarrays summing to k (negatives allowed): prefix sum + hash map, O(n). */
    static int subarraySum(int[] a, int k) {
        var seen = new HashMap<Long, Integer>();
        seen.put(0L, 1);                         // the empty prefix
        long run = 0; int count = 0;
        for (int x : a) {
            run += x;
            count += seen.getOrDefault(run - k, 0);
            seen.merge(run, 1, Integer::sum);
        }
        return count;
    }

    public static void main(String[] args) {
        long[] p = prefix(new int[]{3, 1, 4, 1, 5});
        if (p[4] - p[1] != 6) throw new AssertionError();
        var m = Matrix2D.of(new int[][]{{1, 2, 3}, {4, 5, 6}, {7, 8, 9}});
        if (m.sum(1, 1, 2, 2) != 28) throw new AssertionError();
        long[] r = applyRangeAdds(5, new int[][]{{0, 2, 1}, {1, 4, 10}});
        if (!Arrays.equals(r, new long[]{1, 11, 11, 10, 10})) throw new AssertionError(Arrays.toString(r));
        if (subarraySum(new int[]{1, -1, 1, 1, -1}, 1) != 7) throw new AssertionError(subarraySum(new int[]{1, -1, 1, 1, -1}, 1));
        System.out.println("prefix sums ok");
    }
}

8. Applications in Backend Engineering

8.1 Hash maps and sets

  • Idempotency and deduplication. A payment API stores idempotency keys in a hash-based store (Redis, a unique index, or an in-memory ConcurrentHashMap with TTL for a single node) so retried requests return the original result. The core operation is "have I seen this key?" — the hash set pattern.
  • Request-scoped joins. Instead of the N+1 query pattern, load child rows with one WHERE parent_id IN (…) query and group them in a Map<Long, List<Child>>: Θ(n + m) instead of n round trips. This is literally the hash join that your database runs internally.
  • Caches. Every in-process cache (Caffeine, Guava, Spring's ConcurrentMapCache) is a hash table plus an eviction policy (Chapter 2 builds LRU).
  • Counting and top-k. Counting events per tenant or per error code in a sliding interval: a hash map of counters, followed by a heap for top-k (Chapter 4).
  • Sharding and routing. Hashing a key to choose a partition (Kafka's default partitioner hashes the record key with murmur2; consistent hashing in Part 2).

8.2 Arrays and dynamic arrays

  • Ring buffers (the LMAX Disruptor, Netty's recycler, log appenders) are fixed arrays indexed modulo a power-of-two capacity — the cache-friendly alternative to linked queues.
  • Columnar formats (Parquet, Arrow) store each column as a contiguous array so scans are sequential and SIMD-friendly.
  • Batching. Accumulating records into a presized ArrayList before a JDBC batch insert or a Kafka send avoids repeated growth.

8.3 Strings and string matching

  • Log scanning and alerting: matching many patterns at once is the Aho–Corasick automaton (a trie plus KMP-style failure links); single patterns use Boyer–Moore variants.
  • Content-defined chunking and delta sync: rsync's rolling checksum finds blocks the receiver already has at any byte offset; backup and dedup systems choose chunk boundaries where a rolling hash hits a pattern, so an insertion shifts only nearby chunks.
  • Plagiarism and near-duplicate detection: shingling with rolling hashes, then MinHash for similarity.
  • Building responses: StringBuilder/StringJoiner and streaming writers instead of concatenation in loops; Jackson writes directly to output streams.

8.4 Prefix sums

  • Analytics endpoints: cumulative counters per day let you answer "events between day l and r" in O(1); Prometheus counters are monotonic precisely so that rate() can be computed as a difference of two samples.
  • Rate limiting and quotas: sliding-window counters keep per-bucket counts and sum a window (a small prefix-sum problem).
  • Image processing / geospatial: 2-D summed-area tables (integral images) give O(1) box sums; the Viola–Jones face detector made them famous.
  • Calendar/booking systems: difference arrays (or sweep lines) count overlapping reservations per time slot.

9. Case Studies

9.1 Hash flooding and Java 8's treeified bins Verified

In December 2011, Klink and Wälde demonstrated at the 28th Chaos Communication Congress that many web platforms parsed POST parameters into hash tables keyed by attacker-controlled strings with predictable hash functions. Since Java's String.hashCode is a public polynomial, an attacker can precompute thousands of colliding names; each insertion then walks a long chain, making parsing Θ(n²) — a few hundred kilobytes could pin a CPU for minutes. The coordinated advisory (oCERT-2011-003) led Tomcat and others to cap the number of parameters. The structural fix in the JDK came with Java 8's JEP 180, which converts long bins into balanced trees so worst-case lookups degrade to O(log n) instead of O(n). Python, Ruby and Perl took the other route — randomised, keyed hash functions (Python's SipHash, PEP 456). Lesson: average-case guarantees are only as good as your assumptions about who chooses the input.

9.2 Python's compact dict Verified

Raymond Hettinger proposed splitting dict storage into a sparse index table and a dense entries array on python-dev in 2012; PyPy shipped the idea first, and CPython 3.6 adopted it (What's New in Python 3.6 reports 20–25% less memory use). The side effect — insertion ordering — became a language guarantee in 3.7. The design shows a recurring theme: you can keep the O(1) expected bounds while dramatically improving constant factors and memory by thinking about layout.

9.3 Swiss tables in Abseil and Go 1.24 Verified

Google's SwissTable stores one control byte per slot (7 bits of the hash, or empty/deleted markers) in a separate array, grouped 16 at a time so that one SIMD instruction compares a probe group against the query's 7-bit tag. Most lookups touch one control group and one slot. Go 1.24 (February 2025) replaced the bucket-chained runtime map with a Swiss-table design; the Go blog post explains how they adapted it to Go's requirements such as incremental growth (splitting the map into many small tables so no single insert has to rehash everything — a latency-oriented answer to the amortization spike).

9.4 rsync's rolling checksum Verified

Andrew Tridgell and Paul Mackerras's 1996 technical report describes rsync: the receiver sends weak (rolling, Adler-32–like) and strong (MD4 at the time) checksums of fixed blocks; the sender slides a window byte by byte over its file, updating the weak checksum in O(1) per byte, and only computes the strong checksum on weak matches. It is Rabin–Karp's "cheap filter, expensive verify" design applied to network synchronisation.

9.5 Compact Strings in JDK 9 Verified

JEP 254 observed from heap dumps that strings are a major share of live heap data and most contain only Latin-1 characters. Switching String's storage from char[] to byte[] plus a coder flag halved the footprint of such strings, with no API change. For you, the takeaway is that String memory is roughly 1 byte per ASCII character plus ~40 bytes of overhead (object + array headers), not 2 bytes per character.

12. Common Mistakes and Misconceptions

  • "O(1) means fast." A hash lookup of a 10 KB string key is O(key length) to hash and compare; an O(1) operation with a cache miss is slower than an O(log n) binary search in L1 for small n.
  • Hidden linear costs inside loops. list.contains, list.remove(Object), list.indexOf, String.substring, Python x in list, s[i:] and list.pop(0) are all Θ(n). Two of them inside a loop over n make the loop Θ(n²).
  • Mutable keys. Mutating a field used in hashCode after insertion strands the entry in the wrong bucket: get returns null and remove fails while size still counts it. Use records or immutable value objects as keys.
  • Broken equals/hashCode contract. Overriding equals without hashCode (or JPA entities whose hash changes when the ID is assigned on persist) puts "equal" objects in different buckets.
  • Negative modulo. hashCode() % n can be negative in Java; Math.abs(Integer.MIN_VALUE) is still negative. Use Math.floorMod or a bit mask.
  • Integer overflow in prefix sums (10⁵ values of 10⁹ overflow int) and in binary-search midpoints ((lo + hi) / 2). Use long and lo + (hi − lo) / 2 or (lo + hi) >>> 1.
  • Comparing boxed integers with ==. Integer caches −128..127, so map.get(a) == map.get(b) "works" in tests and fails in production for larger counts.
  • String concatenation in loops — Θ(n²). Also stream().reduce("", String::concat).
  • Treating char as a character. Reversing, truncating or indexing by char splits surrogate pairs; use codePoints() or a BreakIterator for user-visible text.
  • Modifying a collection while iterating → ConcurrentModificationException (fail-fast iterators check modCount). Use Iterator.remove or removeIf.
  • Arrays.asList is fixed-size and write-through to the array; List.of is immutable and rejects nulls.
  • Assuming HashMap iteration order, then a JDK upgrade or a capacity change reorders output and snapshot tests fail.
  • Forgetting the empty prefix (seen.put(0, 1)) in subarray-sum problems, which misses subarrays starting at index 0.
  • Misusing amortized bounds for latency-critical paths — a single 100-million-element ArrayList resize copies 400 MB of references.
  • Calling Rabin–Karp "O(n) worst case" — it is expected linear; worst case with adversarial collisions is Θ(nm) unless you skip verification (then it is Monte Carlo, possibly wrong).

13. Production Concerns

13.1 Performance

  • Presize. Java 19 added HashMap.newHashMap(int numMappings), which computes the right capacity for the load factor; before that, new HashMap<>(n) is a capacity, not an expected size, and will resize at 0.75n. Likewise new ArrayList<>(n) and StringBuilder(n).
  • Avoid boxing on hot paths. int[] counts, IntStream, or primitive collections. Profiling with async-profiler's allocation mode will show Integer.valueOf as a hotspot.
  • Choose good hashCodes for composite keys: records generate a well-mixed hash from all components; hand-rolled a * 31 + b is fine; a + b or a ^ b collides massively (every (x, x) pair XORs to 0).

13.2 Security

  • Hash flooding: cap the number of request parameters, headers and JSON object fields (Jackson has StreamReadConstraints since 2.15 for nesting depth, number and string lengths); prefer keyed hashes for untrusted string keys in custom tables.
  • ReDoS: catastrophic backtracking in regexes like (a+)+$; validate with linear-time engines for untrusted patterns or inputs, and set input length limits.
  • Unicode normalization before comparing identifiers (NFC/NFKC), otherwise visually identical usernames are different keys.

13.3 Scalability and reliability

  • Unbounded in-memory maps are memory leaks waiting for traffic. Use bounded caches (Caffeine with maximumSize) and monitor heap after GC.
  • ConcurrentHashMap.size() under heavy contention is approximate; use mappingCount() for long counts and do not use it for correctness decisions.
  • Huge arrays need contiguous heap: G1 allocates objects larger than half a region as humongous objects, which can fragment the heap and trigger full GCs. Chunk very large arrays.

13.4 Monitoring and maintainability

  • Track collection sizes as gauges (Micrometer can bind cache and map sizes) and alert on growth trends.
  • Document complexity assumptions on public methods ("O(n) in the number of line items") and add a performance regression test with a realistic n.
  • Prefer clear, standard structures; a custom hash table needs a strong reason and thorough tests (deletion with tombstones is where bugs hide).

14. Exercises: Three Problem Ladders

Each ladder climbs from easy to hard. Attempt each problem for 15–25 minutes before opening the solution; say the brute force and its complexity out loud first, then optimise. Problem statements are paraphrased; common names are given so you can find them on practice sites.

14.1 Ladder A — Hashing ("have I seen something compatible?")

How to recognise the hashing pattern

  • The brute force has a nested loop where the inner loop searches for a partner or a duplicate.
  • You need membership, counting or grouping by an exact key, and order does not matter.
  • Items are "equivalent" under some canonical form (sorted letters, normalised slope, character counts).
  • Constraints say n up to 10⁵–10⁶, so Θ(n²) is too slow but Θ(n) extra memory is acceptable.
  • The phrase "pair/complement/target" or "exists two elements such that…".

A1 · Easy — "Contains Duplicate"

Given an integer array, report whether any value appears at least twice. Then state how your answer changes if memory must be O(1).

Solution

Approach: a hash set; Set.add returns false on a repeat, so we can exit early. Θ(n) expected time, Θ(n) space. With O(1) extra memory, sort in place (Θ(n log n)) and compare neighbours.

import java.util.*;

class A1ContainsDuplicate {
    static boolean containsDuplicate(int[] a) {
        var seen = HashSet.<Integer>newHashSet(a.length);   // JDK 19+: presized
        for (int x : a) if (!seen.add(x)) return true;
        return false;
    }
    static boolean containsDuplicateInPlace(int[] a) {
        Arrays.sort(a);                                      // dual-pivot quicksort, O(1)-ish extra
        for (int i = 1; i < a.length; i++) if (a[i] == a[i - 1]) return true;
        return false;
    }
    public static void main(String[] args) {
        if (!containsDuplicate(new int[]{1, 2, 3, 1}) || containsDuplicate(new int[]{1, 2, 3})) throw new AssertionError();
        if (!containsDuplicateInPlace(new int[]{4, 1, 4})) throw new AssertionError();
        System.out.println("ok");
    }
}

A2 · Easy — "Valid Anagram"

Decide whether two strings are rearrangements of each other. Follow-up: what if they contain arbitrary Unicode?

Solution

Approach: count characters. For lowercase ASCII an int[26] beats a map. Θ(n) time, Θ(1) space (alphabet-bounded). For Unicode, count code points in a HashMap<Integer,Integer> (and normalise first if visually equal forms should match).

import java.util.*;

class A2ValidAnagram {
    static boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;
        int[] c = new int[26];
        for (int i = 0; i < s.length(); i++) { c[s.charAt(i) - 'a']++; c[t.charAt(i) - 'a']--; }
        for (int x : c) if (x != 0) return false;
        return true;
    }
    static boolean isAnagramUnicode(String s, String t) {
        var m = new HashMap<Integer, Integer>();
        s.codePoints().forEach(cp -> m.merge(cp, 1, Integer::sum));
        t.codePoints().forEach(cp -> m.merge(cp, -1, Integer::sum));
        return m.values().stream().allMatch(v -> v == 0);
    }
    public static void main(String[] args) {
        if (!isAnagram("anagram", "nagaram") || isAnagram("rat", "car")) throw new AssertionError();
        if (!isAnagramUnicode("a😀b", "b😀a")) throw new AssertionError();
        System.out.println("ok");
    }
}

A3 · Easy — "Two Sum"

Given an array and a target, return indices of two distinct positions whose values add to the target (exactly one answer exists).

Solution

Approach: one pass; before inserting x, ask whether target − x was seen. Looking up before inserting prevents pairing an element with itself. Θ(n) expected time and space. If the array were sorted, two pointers give Θ(1) space (Chapter 3).

import java.util.*;

class A3TwoSum {
    static int[] twoSum(int[] a, int target) {
        var indexOf = new HashMap<Integer, Integer>();
        for (int i = 0; i < a.length; i++) {
            Integer j = indexOf.get(target - a[i]);
            if (j != null) return new int[]{j, i};
            indexOf.put(a[i], i);
        }
        throw new IllegalArgumentException("no pair");
    }
    public static void main(String[] args) {
        System.out.println(Arrays.toString(twoSum(new int[]{2, 7, 11, 15}, 9)));   // [0, 1]
        if (!Arrays.equals(twoSum(new int[]{3, 3}, 6), new int[]{0, 1})) throw new AssertionError();
    }
}

A4 · Medium — "Group Anagrams"

Partition a list of lowercase words into groups of anagrams.

Solution

Approach: map each word to a canonical key. Sorting letters costs Θ(k log k) per word; a 26-count signature costs Θ(k). Total Θ(n·k). Using a String built from counts as the key is safe; using int[] directly as a key is a bug (arrays use identity hashCode).

import java.util.*;

class A4GroupAnagrams {
    static List<List<String>> group(String[] words) {
        var groups = new HashMap<String, List<String>>();
        for (String w : words) {
            int[] c = new int[26];
            for (int i = 0; i < w.length(); i++) c[w.charAt(i) - 'a']++;
            String key = Arrays.toString(c);                 // canonical form, O(26)
            groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
        }
        return new ArrayList<>(groups.values());
    }
    public static void main(String[] args) {
        var g = group(new String[]{"eat", "tea", "tan", "ate", "nat", "bat"});
        if (g.size() != 3) throw new AssertionError(g);
        System.out.println(g);
    }
}

A5 · Medium — "Longest Consecutive Sequence"

Given an unsorted integer array, return the length of the longest run of consecutive integers (values, not positions) in Θ(n) time.

Solution

Approach: put all values in a set. Only start counting from x if x−1 is absent (x is a run start); then walk x+1, x+2… Each value is visited by at most one walk, so total work is Θ(n) despite the nested loop — an aggregate amortized argument. Sorting would be Θ(n log n).

import java.util.*;

class A5LongestConsecutive {
    static int longest(int[] a) {
        var s = new HashSet<Integer>();
        for (int x : a) s.add(x);
        int best = 0;
        for (int x : s) {
            if (s.contains(x - 1)) continue;        // not the start of a run
            int len = 1;
            while (s.contains(x + len)) len++;
            best = Math.max(best, len);
        }
        return best;
    }
    public static void main(String[] args) {
        if (longest(new int[]{100, 4, 200, 1, 3, 2}) != 4) throw new AssertionError();
        if (longest(new int[]{0, 3, 7, 2, 5, 8, 4, 6, 0, 1}) != 9) throw new AssertionError();
        System.out.println("ok");
    }
}

A6 · Medium — "4Sum II" (count tuples)

Given four arrays of length n, count tuples (i, j, k, l) with A[i]+B[j]+C[k]+D[l] = 0. n ≤ 200.

Solution

Approach: meet in the middle. Count all sums A[i]+B[j] in a map (n² entries), then for every C[k]+D[l] add the count of its negation. Θ(n²) instead of Θ(n⁴). The same split-in-half trick powers "subset sum" for n ≈ 40 (220 per half).

import java.util.*;

class A6FourSumCount {
    static int count(int[] a, int[] b, int[] c, int[] d) {
        var ab = new HashMap<Integer, Integer>();
        for (int x : a) for (int y : b) ab.merge(x + y, 1, Integer::sum);
        int total = 0;
        for (int x : c) for (int y : d) total += ab.getOrDefault(-(x + y), 0);
        return total;
    }
    public static void main(String[] args) {
        if (count(new int[]{1, 2}, new int[]{-2, -1}, new int[]{-1, 2}, new int[]{0, 2}) != 2) throw new AssertionError();
        System.out.println("ok");
    }
}

A7 · Hard — "Max Points on a Line"

Given up to 300 integer points, find the largest number that lie on one straight line.

Solution

Approach: fix an anchor point; every other point defines a direction. Points on the same line through the anchor share a normalised direction (dx, dy) divided by gcd, with a sign convention so (1,2) and (−1,−2) match. Count directions in a hash map. Θ(n²) time, Θ(n) space. Never use floating-point slopes as keys (precision, −0.0 vs 0.0, vertical lines). Duplicates of the anchor add to every line.

import java.util.*;

class A7MaxPoints {
    record Dir(int dx, int dy) {}
    static int gcd(int a, int b) { return b == 0 ? Math.abs(a) : gcd(b, a % b); }

    static int maxPoints(int[][] p) {
        int n = p.length, best = Math.min(n, 1);
        for (int i = 0; i < n; i++) {
            var count = new HashMap<Dir, Integer>();
            int dup = 0, local = 0;
            for (int j = i + 1; j < n; j++) {
                int dx = p[j][0] - p[i][0], dy = p[j][1] - p[i][1];
                if (dx == 0 && dy == 0) { dup++; continue; }
                int g = gcd(dx, dy);
                dx /= g; dy /= g;
                if (dx < 0 || (dx == 0 && dy < 0)) { dx = -dx; dy = -dy; }   // canonical sign
                local = Math.max(local, count.merge(new Dir(dx, dy), 1, Integer::sum));
            }
            best = Math.max(best, local + dup + 1);
        }
        return best;
    }
    public static void main(String[] args) {
        if (maxPoints(new int[][]{{1, 1}, {3, 2}, {5, 3}, {4, 1}, {2, 3}, {1, 4}}) != 4) throw new AssertionError();
        if (maxPoints(new int[][]{{0, 0}, {0, 0}, {1, 1}}) != 3) throw new AssertionError();
        System.out.println("ok");
    }
}

14.2 Ladder B — Prefix sums

How to recognise the prefix-sum pattern

  • Many queries for the sum (or XOR, or count) over a contiguous range of a fixed array.
  • "Number of subarrays whose sum equals / is divisible by k" — especially when values can be negative (sliding window fails).
  • "Balance" problems: equal numbers of 0s and 1s, of vowels and consonants — map one class to +1 and the other to −1.
  • Many range updates applied before reading the result → difference array.
  • 2-D rectangles: summed-area table; "count submatrices" → fix a pair of rows, collapse to 1-D.

B1 · Easy — "Range Sum Query – Immutable"

Design a class that answers many sum(l, r) queries on a fixed array.

Solution

Approach: precompute P with P[0] = 0. Θ(n) build, Θ(1) per query. If updates are added, switch to a Fenwick tree (Θ(log n) both).

class B1RangeSum {
    private final long[] p;
    B1RangeSum(int[] a) {
        p = new long[a.length + 1];
        for (int i = 0; i < a.length; i++) p[i + 1] = p[i] + a[i];
    }
    long sum(int l, int r) { return p[r + 1] - p[l]; }
    public static void main(String[] args) {
        var q = new B1RangeSum(new int[]{-2, 0, 3, -5, 2, -1});
        if (q.sum(0, 2) != 1 || q.sum(2, 5) != -1 || q.sum(0, 5) != -3) throw new AssertionError();
        System.out.println("ok");
    }
}

B2 · Easy — "Find Pivot Index"

Return the leftmost index where the sum of elements strictly left equals the sum strictly right, or −1.

Solution

Approach: right = total − left − a[i]. Keep a running left sum; no array needed. Θ(n) time, Θ(1) space.

import java.util.stream.IntStream;

class B2PivotIndex {
    static int pivot(int[] a) {
        long total = IntStream.of(a).asLongStream().sum(), left = 0;
        for (int i = 0; i < a.length; i++) {
            if (left == total - left - a[i]) return i;
            left += a[i];
        }
        return -1;
    }
    public static void main(String[] args) {
        if (pivot(new int[]{1, 7, 3, 6, 5, 6}) != 3 || pivot(new int[]{1, 2, 3}) != -1) throw new AssertionError();
        System.out.println("ok");
    }
}

B3 · Medium — "Product of Array Except Self"

Return an array where each position holds the product of all other elements, without division, in Θ(n) time.

Solution

Approach: prefix products from the left and suffix products from the right; out[i] = left[i] × right[i]. Store the left products in the output array and fold the right product in a single variable: Θ(1) extra space beyond the output. Division fails with zeros, which is why it is excluded.

import java.util.Arrays;

class B3ProductExceptSelf {
    static int[] product(int[] a) {
        int n = a.length;
        int[] out = new int[n];
        out[0] = 1;
        for (int i = 1; i < n; i++) out[i] = out[i - 1] * a[i - 1];     // product of a[0..i)
        int right = 1;
        for (int i = n - 1; i >= 0; i--) { out[i] *= right; right *= a[i]; }
        return out;
    }
    public static void main(String[] args) {
        if (!Arrays.equals(product(new int[]{1, 2, 3, 4}), new int[]{24, 12, 8, 6})) throw new AssertionError();
        if (!Arrays.equals(product(new int[]{-1, 1, 0, -3, 3}), new int[]{0, 0, 9, 0, 0})) throw new AssertionError();
        System.out.println("ok");
    }
}

B4 · Medium — "Subarray Sum Equals K"

Count contiguous subarrays summing to k; values may be negative. (Implemented as subarraySum in §7.4 — reproduce it without looking, then explain why a sliding window is wrong here.)

Solution

Approach: count of earlier prefixes equal to run − k, seeded with {0: 1}. A sliding window assumes that extending the window never decreases the sum, which negative values violate. Θ(n) expected time, Θ(n) space.

import java.util.*;

class B4SubarraySumK {
    static int count(int[] a, int k) {
        var freq = new HashMap<Long, Integer>(Map.of(0L, 1));
        long run = 0; int res = 0;
        for (int x : a) {
            run += x;
            res += freq.getOrDefault(run - k, 0);   // look up first
            freq.merge(run, 1, Integer::sum);       // then record
        }
        return res;
    }
    public static void main(String[] args) {
        if (count(new int[]{1, 1, 1}, 2) != 2 || count(new int[]{3, 4, 7, 2, -3, 1, 4, 2}, 7) != 4) throw new AssertionError();
        System.out.println("ok");
    }
}

B5 · Medium — "Contiguous Array"

In a binary array, find the longest contiguous subarray with equal numbers of 0s and 1s.

Solution

Approach: map 0 → −1; we need the longest subarray with sum 0, i.e. two equal prefix values as far apart as possible. Store the first index of each prefix value (seed {0: −1}). Θ(n) time; the prefix range is [−n, n] so an int[2n+1] can replace the map.

import java.util.Arrays;

class B5ContiguousArray {
    static int findMaxLength(int[] a) {
        int n = a.length;
        int[] first = new int[2 * n + 1];
        Arrays.fill(first, Integer.MIN_VALUE);
        first[n] = -1;                               // prefix 0 seen "before" index 0
        int run = 0, best = 0;
        for (int i = 0; i < n; i++) {
            run += a[i] == 1 ? 1 : -1;
            if (first[run + n] == Integer.MIN_VALUE) first[run + n] = i;
            else best = Math.max(best, i - first[run + n]);
        }
        return best;
    }
    public static void main(String[] args) {
        if (findMaxLength(new int[]{0, 1, 0}) != 2 || findMaxLength(new int[]{0, 0, 1, 0, 0, 0, 1, 1}) != 6) throw new AssertionError();
        System.out.println("ok");
    }
}

B6 · Medium — "Subarray Sums Divisible by K"

Count non-empty subarrays whose sum is divisible by k (values may be negative).

Solution

Approach: P[j] − P[i] ≡ 0 (mod k) ⇔ P[j] ≡ P[i] (mod k). Count prefix residues; each new residue r adds count[r]. Use Math.floorMod so negative sums map into [0, k). Θ(n + k).

class B6DivisibleByK {
    static int count(int[] a, int k) {
        int[] cnt = new int[k];
        cnt[0] = 1;
        int run = 0, res = 0;
        for (int x : a) {
            run = Math.floorMod(run + x, k);
            res += cnt[run]++;
        }
        return res;
    }
    public static void main(String[] args) {
        if (count(new int[]{4, 5, 0, -2, -3, 1}, 5) != 7 || count(new int[]{-1, 2, 9}, 2) != 2) throw new AssertionError();
        System.out.println("ok");
    }
}

B7 · Hard — "Number of Submatrices That Sum to Target"

Count all non-empty rectangular submatrices (r × c ≤ 100 × 100) whose sum equals a target.

Solution

Approach: fix a top row and a bottom row (Θ(r²) pairs); maintain column sums between them, which collapses the rectangle to a 1-D array of length c; then run B4 on it. Θ(r² · c) time, Θ(c) space. Always iterate the smaller dimension in the outer pair (transpose if needed).

import java.util.*;

class B7SubmatrixTarget {
    static int count(int[][] g, int target) {
        int r = g.length, c = g[0].length, res = 0;
        for (int top = 0; top < r; top++) {
            int[] col = new int[c];
            for (int bot = top; bot < r; bot++) {
                for (int j = 0; j < c; j++) col[j] += g[bot][j];   // column sums rows top..bot
                var freq = new HashMap<Integer, Integer>();
                freq.put(0, 1);
                int run = 0;
                for (int j = 0; j < c; j++) {
                    run += col[j];
                    res += freq.getOrDefault(run - target, 0);
                    freq.merge(run, 1, Integer::sum);
                }
            }
        }
        return res;
    }
    public static void main(String[] args) {
        if (count(new int[][]{{0, 1, 0}, {1, 1, 1}, {0, 1, 0}}, 0) != 4) throw new AssertionError();
        if (count(new int[][]{{1, -1}, {-1, 1}}, 0) != 5) throw new AssertionError();
        System.out.println("ok");
    }
}

14.3 Ladder C — Strings and string matching

How to recognise string-matching patterns

  • "Find a pattern in a text", "does the string consist of repeats", "longest prefix that is also a suffix" → KMP prefix function or Z-function.
  • "Compare many substrings for equality" or "longest repeated substring" → rolling hash, often with binary search on the length (monotone: if a length-L repeat exists, a length L−1 one does too).
  • Palindrome-at-the-start problems → KMP on s + separator + reverse(s).
  • Character-frequency constraints → counting arrays (A2) or sliding windows (Chapter 3).

C1 · Easy — "Valid Palindrome"

Ignoring case and non-alphanumeric characters, decide whether a string reads the same both ways, in Θ(1) extra space.

Solution

Approach: two pointers converging, skipping non-alphanumerics. Avoid building a cleaned copy (Θ(n) space) — interviewers often ask for the in-place version.

class C1ValidPalindrome {
    static boolean isPalindrome(String s) {
        int i = 0, j = s.length() - 1;
        while (i < j) {
            if (!Character.isLetterOrDigit(s.charAt(i))) i++;
            else if (!Character.isLetterOrDigit(s.charAt(j))) j--;
            else if (Character.toLowerCase(s.charAt(i++)) != Character.toLowerCase(s.charAt(j--))) return false;
        }
        return true;
    }
    public static void main(String[] args) {
        if (!isPalindrome("A man, a plan, a canal: Panama") || isPalindrome("race a car")) throw new AssertionError();
        System.out.println("ok");
    }
}

C2 · Easy — "Longest Common Prefix"

Return the longest prefix shared by every string in an array.

Solution

Approach: vertical scan: compare column by column, stop at the first mismatch or end of the shortest string. Θ(S) where S is the total characters examined (at most n × min length). A trie also works but is overkill unless queries repeat.

class C2LongestCommonPrefix {
    static String lcp(String[] a) {
        if (a.length == 0) return "";
        for (int col = 0; col < a[0].length(); col++) {
            char ch = a[0].charAt(col);
            for (int r = 1; r < a.length; r++)
                if (col == a[r].length() || a[r].charAt(col) != ch) return a[0].substring(0, col);
        }
        return a[0];
    }
    public static void main(String[] args) {
        if (!lcp(new String[]{"flower", "flow", "flight"}).equals("fl") || !lcp(new String[]{"dog", "car"}).isEmpty()) throw new AssertionError();
        System.out.println("ok");
    }
}

C3 · Medium — "Find the Index of the First Occurrence" with a worst-case guarantee

Return the first index of a needle in a haystack, or −1, in Θ(n + m) worst case.

Solution

Approach: KMP, stopping at the first full match. Mention that haystack.indexOf(needle) is the production answer, then justify KMP by the worst-case requirement.

class C3StrStr {
    static int strStr(String t, String p) {
        if (p.isEmpty()) return 0;
        int m = p.length();
        int[] pi = new int[m];
        for (int i = 1, k = 0; i < m; i++) {
            while (k > 0 && p.charAt(i) != p.charAt(k)) k = pi[k - 1];
            if (p.charAt(i) == p.charAt(k)) k++;
            pi[i] = k;
        }
        for (int i = 0, q = 0; i < t.length(); i++) {
            while (q > 0 && t.charAt(i) != p.charAt(q)) q = pi[q - 1];
            if (t.charAt(i) == p.charAt(q)) q++;
            if (q == m) return i - m + 1;
        }
        return -1;
    }
    public static void main(String[] args) {
        if (strStr("sadbutsad", "sad") != 0 || strStr("leetcode", "leeto") != -1 || strStr("aaaaab", "aab") != 3) throw new AssertionError();
        System.out.println("ok");
    }
}

C4 · Medium — "Repeated Substring Pattern"

Decide whether a string can be built by concatenating two or more copies of one of its substrings.

Solution

Approach: let b = π[n−1], the longest border. The smallest period is p = n − b. The string is a repetition iff b > 0 and n is divisible by p. Θ(n). (The famous one-liner (s + s).substring(1, 2n − 1).contains(s) is also correct — s is a rotation of itself at a non-trivial shift iff it is periodic — but its complexity depends on the search algorithm.)

class C4RepeatedSubstring {
    static boolean repeated(String s) {
        int n = s.length();
        int[] pi = new int[n];
        for (int i = 1, k = 0; i < n; i++) {
            while (k > 0 && s.charAt(i) != s.charAt(k)) k = pi[k - 1];
            if (s.charAt(i) == s.charAt(k)) k++;
            pi[i] = k;
        }
        int border = n == 0 ? 0 : pi[n - 1];
        return border > 0 && n % (n - border) == 0;
    }
    public static void main(String[] args) {
        if (!repeated("abab") || repeated("aba") || !repeated("abcabcabcabc") || repeated("abac")) throw new AssertionError();
        System.out.println("ok");
    }
}

C5 · Hard — "Shortest Palindrome"

Prepend the fewest characters to a string to make it a palindrome; return the result.

Solution

Approach: we need the longest palindromic prefix of s. Build t = s + "#" + reverse(s); the last value of π on t is the length of the longest prefix of s that equals a suffix of reverse(s), i.e. the longest palindromic prefix. The separator stops borders from crossing the middle. Prepend the reverse of the remaining suffix. Θ(n), versus Θ(n²) for checking every prefix.

class C5ShortestPalindrome {
    static String shortest(String s) {
        String rev = new StringBuilder(s).reverse().toString();
        String t = s + "#" + rev;
        int[] pi = new int[t.length()];
        for (int i = 1, k = 0; i < t.length(); i++) {
            while (k > 0 && t.charAt(i) != t.charAt(k)) k = pi[k - 1];
            if (t.charAt(i) == t.charAt(k)) k++;
            pi[i] = k;
        }
        int palPrefix = pi[t.length() - 1];
        return rev.substring(0, s.length() - palPrefix) + s;
    }
    public static void main(String[] args) {
        if (!shortest("aacecaaa").equals("aaacecaaa") || !shortest("abcd").equals("dcbabcd") || !shortest("").isEmpty()) throw new AssertionError();
        System.out.println("ok");
    }
}

C6 · Hard — "Longest Duplicate Substring"

Return any longest substring that occurs at least twice (possibly overlapping) in a string of length up to 3 × 10⁴.

Solution

Approach: the predicate "a duplicate of length L exists" is monotone in L, so binary search L. For a fixed L, compute all window hashes with a rolling hash and look for a repeat in a hash set — Θ(n) expected. Total Θ(n log n) expected. Use two moduli combined into one long key to make false positives negligible (or verify with regionMatches, kept here for safety). A suffix array/automaton gives a deterministic Θ(n log n)/Θ(n) alternative.

import java.util.*;

class C6LongestDupSubstring {
    static final long B = 131, M1 = 1_000_000_007L, M2 = 998_244_353L;

    /** start index of some duplicated substring of length len, or -1 */
    static int find(String s, int len) {
        if (len == 0) return 0;
        long h1 = 0, h2 = 0, p1 = 1, p2 = 1;
        for (int i = 0; i < len; i++) {
            h1 = (h1 * B + s.charAt(i)) % M1; h2 = (h2 * B + s.charAt(i)) % M2;
            if (i > 0) { p1 = p1 * B % M1; p2 = p2 * B % M2; }
        }
        var seen = new HashMap<Long, Integer>();
        seen.put(h1 << 32 | h2, 0);
        for (int i = 1; i + len <= s.length(); i++) {
            h1 = (Math.floorMod(h1 - s.charAt(i - 1) * p1 % M1, M1) * B + s.charAt(i + len - 1)) % M1;
            h2 = (Math.floorMod(h2 - s.charAt(i - 1) * p2 % M2, M2) * B + s.charAt(i + len - 1)) % M2;
            Integer prev = seen.putIfAbsent(h1 << 32 | h2, i);
            if (prev != null && s.regionMatches(prev, s, i, len)) return i;
        }
        return -1;
    }

    static String longestDup(String s) {
        int lo = 0, hi = s.length() - 1, bestStart = 0, bestLen = 0;
        while (lo <= hi) {
            int mid = (lo + hi) >>> 1;
            int at = find(s, mid);
            if (at >= 0) { bestStart = at; bestLen = mid; lo = mid + 1; } else hi = mid - 1;
        }
        return s.substring(bestStart, bestStart + bestLen);
    }

    public static void main(String[] args) {
        if (!longestDup("banana").equals("ana") || !longestDup("abcd").isEmpty()) throw new AssertionError(longestDup("banana"));
        System.out.println("ok");
    }
}

15. Interview Questions

Conceptual What is the difference between amortized O(1) and expected O(1)? Give a structure that has each.

Amortized is a deterministic guarantee about sequences: any m operations cost O(m) total, though one operation may cost Θ(n) (dynamic array append, hash table insertion including resize). Expected is a probabilistic guarantee about each operation, averaged over the algorithm's random choices (hash lookup under universal hashing, randomized quicksort's partition). Hash table insertion is both: expected over hashing, amortized over resizing. In a latency discussion, point out that neither bounds the worst single operation; Go 1.24 maps and incremental rehashing in Redis exist to bound that tail.

Conceptual Walk me through HashMap.put in Java 8+, including resize and treeification.

Spread hash (h ^ h>>>16), mask with (n−1) because capacity is a power of two, CAS-free insert into an empty bin or walk the chain comparing hash then equals; replace or append at tail. If the chain hits 8 and capacity ≥ 64, convert the bin to a red-black tree ordered by hash, then compareTo, then a tie-breaker; if capacity < 64 resize instead. After insertion, if size exceeds 0.75 × capacity, double the table and split each bin into lo/hi lists by the bit (hash & oldCap) — no rehashing needed. Trees untreeify at 6. Bonus points: Java 7 head insertion plus unsynchronised concurrent resize could form a cycle; never share a HashMap across threads without synchronisation.

Conceptual Why do Java's HashMap capacities use powers of two while many textbooks recommend prime table sizes?

Primes make h mod m depend on all bits of h, protecting against hash functions with patterns in low bits. Powers of two make indexing a single AND and make resize splitting trivial (one bit decides lo/hi), but they only use low bits — so the JDK compensates by XOR-ing high bits into low bits, and falls back on treeification for bad hashes. Open-addressing tables using powers of two usually add a multiplicative mix (Fibonacci hashing) for the same reason.

Conceptual Apply the master theorem to T(n) = 4T(n/2) + n², and to T(n) = 2T(n/2) + n log n.

First: log₂4 = 2 and f = n² = Θ(n²), so every level of the recursion tree does n² work across log n levels: Θ(n² log n). Second: log₂2 = 1 and f = n log n = Θ(n¹ log¹ n), the extended case 2 with k = 1: Θ(n log² n). Explain via the recursion tree: level i contributes n·log(n/2ⁱ), and summing log(n) − i over log n levels gives Θ(log² n) per n.

Coding Given a stream of transactions (id, amount), find whether any two distinct transactions sum to exactly a target, using O(n) time. Then: what if the stream is too large for memory?

In-memory: the Two Sum pattern — a hash set of seen amounts, check target − amount before inserting (see A3). Θ(n) expected time and space. Too large for memory: partition by amount into buckets on disk such that complements land in predictable buckets (e.g. range-partition by amount; bucket for x pairs with the bucket containing target − x), then solve each pair of buckets in memory — this is how a distributed hash join works. Alternatively, external sort and two pointers from both ends (Θ(n log n) I/O-efficient). A Bloom filter can prefilter candidates but needs a verification pass because of false positives.

Coding Count subarrays with sum k. Why doesn't a sliding window work, and what is your complexity?

Prefix sums with a hash map of prefix counts, seeded with {0:1}, look up run − k before inserting run: Θ(n) expected time, Θ(n) space. A sliding window requires monotonicity — extending the right end never decreases the sum, shrinking the left never increases it — which holds only for non-negative values. With negatives, you cannot decide which pointer to move. Follow-up "longest such subarray": store the first index of each prefix instead of a count.

Coding Implement strStr. The interviewer says "now make it worst-case linear". Explain why KMP is linear.

Build the prefix function, then scan with a match-length variable q (code in C3). Linear because q increases by at most one per text character and each fallback strictly decreases q, while q never drops below zero: the number of fallbacks is bounded by the number of increments, at most n. Same argument for building π (at most m). Total Θ(n + m), and the text pointer never moves backward — so KMP works on streams (e.g. scanning a socket for a delimiter).

Scenario A batch job that reconciles two lists of 2 million orders went from 5 minutes to 6 hours after a refactor. What do you look for?

A complexity regression, most likely a quadratic pattern: a List.contains/stream().filter(...).findFirst() inside a loop (2M × 2M = 4 × 10¹² comparisons), a remove(Object) in a loop, repeated string concatenation, or a JPA lazy load per item (N+1). Confirm with a profiler (async-profiler flame graph) rather than guessing; reproduce with n = 10⁴ and 2 × 10⁴ and check whether time quadruples. Fix by indexing one side in a presized HashMap keyed by order id (hash join) or sorting both and merging. Also check for a mutable key or poor hashCode (e.g. one that returns a constant or uses only a low-cardinality field), which makes a HashMap degrade toward O(log n) per op with treeification or O(n) for non-Comparable keys.

Scenario Your service's p99 latency spikes every few minutes; heap is large and you keep a 30-million-entry in-memory index in a HashMap that grows during the day. Hypotheses?

Resize pauses: each doubling allocates a new table (a 64M-slot reference array is 256 MB with compressed oops) and rehashes all entries on the inserting thread, blocking that request; the huge array may be a G1 humongous allocation causing GC pressure. Mitigations: presize with HashMap.newHashMap(expected), build the index off the request path and swap atomically (copy-on-write), shard into several smaller maps, or use a structure with incremental resizing. Also review whether a primitive map would cut memory by 2–3×, and monitor GC logs to confirm.

Architecture How would you defend a public API against hash-flooding attacks?

Defence in depth: limit request size, number of parameters/headers/JSON fields and nesting depth at the edge (Tomcat maxParameterCount, Jackson StreamReadConstraints); rely on JDK 8+ treeified bins (worst case O(log n) for Comparable keys like String); for custom hash tables keyed by untrusted strings use a keyed hash (SipHash with a per-process random key) so attackers cannot precompute collisions; rate-limit expensive endpoints; monitor CPU per request. Mention that the same class of issue exists for regexes (ReDoS) and XML entity expansion.

Conceptual Python dict vs Java HashMap: name three internal differences.

(1) Collision resolution: open addressing with a perturbation-based probe sequence vs separate chaining with treeified bins. (2) Layout and ordering: compact split layout (sparse indices + dense insertion-ordered entries), so iteration follows insertion order; HashMap order is unspecified (LinkedHashMap adds a doubly linked list for order). (3) Load factor: ≤ 2/3 vs 0.75; and string hashing: randomised SipHash per process (PYTHONHASHSEED) vs deterministic polynomial hash cached in the String. Both resize geometrically and both require key immutability in practice.

Behavioral Tell me about a time you found a performance problem by reasoning about complexity rather than profiling.

Structure with STAR, and make the reasoning explicit: the input-size growth you anticipated, the operation you identified as Θ(n) inside a loop, the back-of-envelope estimate (n = 10⁶, 10¹² operations ≈ hours), the fix (index with a map, presized), and how you verified (benchmark at two sizes, profiler confirmation, a regression test). Senior signal: you also added a guardrail — a code review checklist item or a performance test — so the pattern does not recur.

  • Name the cost model and the input size before stating a bound; strings and big integers are not O(1) to compare or hash.
  • O, Ω, Θ bound functions; worst, average, expected and amortized choose which function — they are different promises with different operational meanings.
  • Multiplicative growth gives amortized O(1) appends (cost 1 + r/(r−1)); additive growth gives Θ(n). Shrink at ¼, not ½.
  • Master theorem: compare f(n) with nlog_b a; leaves, all levels, or root dominate.
  • Java HashMap: power-of-two table, hash spreading, chaining, treeify at 8 (capacity ≥ 64), untreeify at 6, resize at 0.75 with lo/hi split. ConcurrentHashMap: CAS empty bins, lock first node, cooperative resize, no nulls.
  • CPython dict: open addressing with perturbation, compact insertion-ordered entries, ≤ 2/3 load.
  • KMP is Θ(n+m) worst case via the prefix function; Rabin–Karp is expected linear and shines for many patterns and substring-equality checks.
  • Prefix sums turn range sums into O(1) and, with a hash map of earlier prefixes, solve subarray-sum problems with negatives in Θ(n).

A dynamic array grows by a factor of 1.5 when full. What is the amortized cost of append and the total number of element copies for n appends (approximately)?

  1. O(log n) amortized; about n log n copies
  2. O(1) amortized; about n copies
  3. O(1) amortized; about 2n copies
  4. O(n) amortized; about n²/2 copies
Copies form a geometric series n(1 + 2/3 + 4/9 + …) ≈ n/(1.5 − 1) = 2n, so amortized O(1). Doubling gives about n copies; additive growth gives Θ(n²).

In OpenJDK's HashMap, a bin has accumulated 9 colliding entries but the table capacity is 32. What happens on the insertion that made it 9?

  1. The bin is converted to a red-black tree
  2. The table is resized instead of treeifying, because capacity is below MIN_TREEIFY_CAPACITY (64)
  3. The insertion throws an exception
  4. Nothing; HashMap never changes bin structure
treeifyBin checks the table length first; below 64 it calls resize(), on the theory that a small table, not a bad hash, is the cause.

T(n) = 3T(n/3) + n. What is T(n)?

  1. Θ(n)
  2. Θ(n²)
  3. Θ(n^1.58)
  4. Θ(n log n)
log₃3 = 1 and f(n) = n = Θ(n¹): every level of the recursion tree costs n and there are log₃ n levels.

Why does "count subarrays with sum k" require prefix sums + hashing instead of a sliding window when values may be negative?

  1. Window sums are no longer monotone in window size, so you cannot decide which end to move
  2. Sliding windows require sorted input
  3. Hash maps are always faster than two pointers
  4. Sliding windows are O(n²)
The window technique relies on "growing increases, shrinking decreases"; negatives break that invariant.

Which statement about Rabin–Karp is correct?

  1. It is Θ(n + m) in the worst case for any input
  2. It never needs to compare characters
  3. With verification it is always correct and expected Θ(n + m); adversarial collisions can make it Θ(nm)
  4. It requires the pattern's prefix function
Rolling hashes give O(1) window updates; equal hashes must be verified (Las Vegas) or accepted with a small error probability (Monte Carlo).

You use a Java record Point(int x, int y) as a HashMap key, but a teammate replaces it with a class whose hashCode returns x ^ y. Which keys now all collide?

  1. Points with equal x
  2. All points on the diagonal x = y (they all hash to 0), and more generally many symmetric pairs
  3. None; XOR is a perfect hash
  4. Only negative coordinates
x ^ x = 0, and (a, b) collides with (b, a). Records combine components with a 31-multiplier style hash that avoids this symmetry.

In Java, what does "😀".length() return, and why?

  1. 2, because length counts UTF-16 code units and the emoji is a surrogate pair
  2. 1, because it is one character
  3. 4, because it is four UTF-8 bytes
  4. It depends on Compact Strings being enabled
U+1F600 is outside the BMP; Java represents it with two chars. Use codePointCount for code points. Compact Strings changes storage, not semantics.
